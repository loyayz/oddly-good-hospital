# 饮水可用性中的短服务投影

依据：`docs/design/08-hospital-life.md` §17.2。环境饮水保留本人身体、其他真实身体与预约、固定建筑、完整设施报价及路线。目标当前使用者的短服务允许正常排队；该计算不授权实际占用、供水或恢复需求。

`facility_availability` 已在当前只读作用域内按主体与设施保存完整报价。短服务投影现在另按目标设施与实际当前使用者共享同一 WorldState；该投影只清除原用户的设施使用身份、身体及目标预约。来源准备和单一身体排除使用现有 `prepare_projection`、`begin_actor_exclusion_query`，每个请求者仍执行自己的完整报价。直接调用不会保留投影，异世界和新作用域不会命中旧投影。

WATER-PROJECTION 比较冻结原外层冷投影与当前实现的完整类型化返回值；两边共用当前 Space 完整报价，因此不把 Space 内部预约证明优化算成本项收益。覆盖患者、员工和陪同家属的使用者；本人查询、不同主体、重复读取、新批次、故障及恢复、事实替换、新 WorldState、无外层作用域、无关身体阻挡较大请求者，以及服务结束但身体和预约尚未退出。

患者和员工从明确的待使用计算边界开始，实际调用 `_claim_need` 和空间预约。家属从既有完整真实终态复制事实，保留真实已接纳的陪同身份；只声明本人已在既有水点待使用、原移动已结束、已先回过病房和新饮水任务四项前提，再实际调用 `_claim_need`。逐项记录前提、检查完整身体与其他实际身体、验证世界，并核对其他角色、移动、预约与家属事实不变。原文件保持只读。这些断言不证明移动、住院、返回病房或先前任务完成。

运行同一已导入的冻结工程：`water_availability_projection_runner.gd -- <新结果.json> WATER-PROJECTION --family-input=<真实qualified轮次的r1.json.final.bin>`。输入保留 Variant 的完整数值类型并核对内容指纹，不能用 JSON 类型转换代替。既有 STAFF-42 与 GROW-75 覆盖水报价作用域、动态身体、完整选座、水候选、当前水权限及采样串行等价。

局部投影构建、投影身体访问和排除集合只作工作计数，不是 elapsed、分配次数或线程 CPU。原160人初态和已保存最终态都没有 `using`，不能拿它们宣称本项使用中投影的收益；完整窗口收益需要后续同业务 plain 测量。
