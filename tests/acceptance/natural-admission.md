# 自然入院与诊疗等待专项

依据：随机来客规格§1.2及临床规格§6、自然入院交接。检查从真实到院前或实际会诊开始前启动，不用已经完成治疗的旧状态证明新交接。

```sh
godot --headless --path <隔离工程> --script res://tests/acceptance/natural_admission_runner.gd -- <结果JSON绝对路径>
```

可在结果路径后指定 `surgery-policy` 只运行NAT-11，或 `mixed-pool` 只运行NAT-12。省略时执行完整专项。

- NAT-01：治疗设备故障仍能真实到院、登记并完成一次初诊，缺项等待不丢证据。
- NAT-02：设备恢复后继续一次会诊、治疗、治愈离院，金额及治疗包只结算一次。
- NAT-03：会诊医生和实际治疗池医生可不同，会诊只使用当前人员，不预约未来医生。
- NAT-04（物资、人员、设备、拥堵四变体）：实际会诊期间条件变化，完成后保留原方案与治疗票；等待状态经当前版本完整内存快照恢复，条件恢复后实际治疗并治愈，不重复会诊或收费。
- NAT-05：无当班医生仍到院并等初诊；按真实候诊累计和固定输入随机流耐心离院，不强制设置完成。
- NAT-06：C档患者真实完成三次不同诊断工作与会诊；床区暂停后等待，恢复后重新取得真实床位与治疗资源。
- NAT-07：会诊途中失去必要住院研究时重评，不能把真正方案失效当作普通排队。
- NAT-08：低于75%预计效果的门诊组合在空间/路线查询前排除；能力和设备改善后重新查得方案，报价不改医院事实或随机流。
- NAT-09（自然、教学两变体）：缺医生和治疗设备时仍消费原到访机会并产生真实Visit；只对实际选中病例做一次入口检查，不枚举全部完整治疗路线。

- NAT-10：复杂病例仍要求R34与该病症手术定义，不重新引入完整治疗链门槛；教学和早期病例保持普通。

- NAT-11（医生、院长两变体）：已推荐尚未准备的手术失去研究资格，医生方案回会诊、院长方案待确认；同票号与等待累计保留，无预约、领包或Attempt。

- NAT-12：同治疗池第一位医生仅能会诊、下一位医生具备C档治疗资格；实际派工继续寻找合格人选，完成治疗并离院，不因首名候选不合格卡死。

资源变化是被测边界输入。拥堵变体在原合法治疗站位加入一个真实静止身体，验证当前路径阻塞及移除后的恢复；不将该身体此前行程算作已测试。床位变体验证重新合法开工，完整住院护理/转床另见CLIN专题。当前快照恢复是内存序列化边界检查，不代表真实磁盘保存。此专项也不代表Windows、GPU画面、长期平衡或全库验收。
