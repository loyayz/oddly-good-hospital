# 临床验收：接待、诊断、治疗、手术与住院

范围为实施路线阶段10—13。业务预期来自 `docs/design/01-simulation.md` §1、§3—4，`docs/design/07-clinical-team.md` §5—10、§14—17，`docs/design/04-technical.md` §4、§10、§14，以及 `docs/specs/26-10/2026-10-15-stage04-stage24.md` 的统一事实、阶段10—13合同和恢复与一致性。

本专题使用真实 `HospitalSimulation.step` 验证临床门面及原有空间、移动、排班、耗材、随机、访客和账目。夹具、复制样本及流式恢复实例不接入临床门面的可选科室路由依赖；科室路由、科室就绪与错入口交互由 `operations.md` 的 OPS 专项验收。本专题的临床链路结果与 OPS 结果共同构成对应系统证据，单独结果不作为完整应用集成验收。

数值来源为 `docs/data/balance.json` 的 `clinical`、`billing`、`diagnostic_flow`、`ward_care`，`docs/data/content-catalog.json` 的病例、方案与协议，以及 `docs/data/clinical-layouts.json` 的真实布局。D09/S13为A档零件装反，基价200；D14/S22为C档轮廓打结，基价600。基础诊断能力1、设备基础型、本院无治愈经验时，C档证据依次为42、77、102。诊断能力3和奇想型诊断台的C档证据依次为49.2、93，应省略共振。

夹具从正式医院工厂或合法内容定义建立。普通门诊至少通过一次真实接待、初诊、方案会诊、开工、结算与离院；手术至少通过一次真实准备、四段操作、15秒苏醒、护士陪同转床、护理、恢复与出院查房。控制随机种子只确定可重复输入；失败/成功预期来自已开始Attempt的承诺，恢复不得重新抽取。隔离样本可以从合法的既有业务边界继续，不以缩短生产工作量、传送患者或伪造完成凭据替代链路。

34 例均可独立选择。`clinical.gd` 的 `PREREQUISITES` 指定每例起点，`clinical_fixtures.gd` 按需生成并保存各段前置状态；单例不执行同专题的其他断言。完整专题包含上述贯通链路，局部回归只继续所需段。来源、有效性检查、强制重建和执行命令见 [测试入口说明](../README.md)。

CLIN-02 保留从真实到院到离院的门诊贯通场景。CLIN-15 从候手术开始实际建立准备束，CLIN-18 从候手术开始实际完成到齐、器械核对、四段操作及开术承诺恢复，CLIN-24 从主动护理且恢复临近结束的输入开始实际完成护理和查房；这些被测过程不由过程结束后的缓存状态代替。

普通手术前提复用已完成真实接待、初诊和会诊的 D09 候治疗状态，给输入医院配置合法手术资源，再通过正式选方案命令转入候手术。该节点不重复新病人到院时对所有方案的接诊评估。下游局部用例的输入工厂可以明确声明团队已到齐、既有器械核对进度或最后一个工作/恢复 tick；这些是经快照校验的输入，不是先前行走或完整工时的执行证据。最后一步、收费、资源交接和被测的后续实际移动仍调用正式服务，输出 `FIXTURE_INPUT` 区分。完整到齐及四段由 CLIN-18 实推，15秒苏醒由 CLIN-19 实推，真实陪同转床由 CLIN-20 实推。C 档手术报价复用候手术前提，舒缓链使用 D14 完成诊断的前提并补齐独立病区资源。

预设院已有实际摆放的 M09，赠机库存不是临床主体的替代证明。D14 的绑定 ID 为 `B_S22_D14_M14`，其权威流程 `TR14.equipment_id` 仍为 M09，不存在本专题另需摆放的 M14 实体。夹具建立时检查实际设施、病例与协议引用、解锁研究及手术适配；正式到院入口再次完成原临床就绪核验。前置失败立即输出具体夹具原因，依赖用例直接失败。

普通闭环沿医生已自主选择的常规方案自动继续，不在安全离位期间重复指定方案。共享 `outpatient_queue` 样本取自真实 dispatch 已建立门诊准备、已完成资源核验、尚未创建 Attempt 的边界，患者与医生仍按实际路线到位。该样本已有真实预留；缺货样本先用原同方案命令释放未开工准备，再建立无预留的零库存前提。手动选择及确认由对应边界用例单独验证。

手术夹具会诊候诊持续15模拟秒时只读记录一次各实际门诊医生的常规/舒缓报价、手术报价、会诊候选与人员位置、排班及安全离位原因。此日志不改变临床期限、队列、资源或验收结果。

每项用例只报告一个结果；同项内的状态、金额、数量和身份断言共同构成通过条件。所有费用断言读取实际账目，不将报价当作收入；所有耗材断言区分实存、预留和真正领用。执行只推进到本项必要业务边界。

定点与专题执行共用同一份断言和分段前置状态。CLIN-13 使用 D09 未开工准备及 D14 候手术边界，随后继续费用冻结验证；D14 候手术前提生成包含真实接待、初诊、光谱、共振和会诊，覆盖护士代检后必须实际回所属病房。CLIN-22、24、27、32 按需复用手术、苏醒、陪同转床和护理形成的住院状态。CLIN-29 复制 `c_diagnosed` 前提，选择舒缓后实际到场、工作、陪同转床、恢复1800个标准tick并完成查房；先前诊断和候诊选座路程属于输入，不重复执行。CLIN-32 另需真实入口陪诊及床边探视状态，前提不另报告30/31等其他用例；前提未成立时相应用例失败，全部模拟实例在入口结束时释放。

CLIN-29和SPACE-36使用专项临床驱动，按生产阶段顺序调用排班、安全交接、医护整理、休息与疲劳、设备故障维护、候诊、真实空间移动、工作、耗材和临床收费服务，保持0.1秒固定步。实际护理覆盖、工时、乘扶与离位均不跳过；不在每步重复招聘、研究、运营评分或日结，这些由对应专项验证。CLIN-02与CLIN-18保留完整模拟器推进；专项驱动不作为全院经营或全流程回放证据。

夹具快照同时保留下一条命令的序号，嵌套复制继续原输入身份序列，不复用已确认命令ID提交不同内容。CLIN-32 的纯探视者在拒绝后实际离院；原陪诊者的床边结束可先返回公共等候。退出途中每个仍在楼层的观测边界都须保留同一 Actor、VisitorStay 及该身体的真实空间阻挡，只有实际到达院外出口才结束本次纯探视的在院容量；到达出口的完成tick可以正常释放，不要求额外留存一tick。

CLIN-13 的两个金额报价分别读取门诊候治疗与C档手术候诊输入，查询前后完整世界事实相同。费用冻结分支独立声明D09舒缓的已选方案、2包未领用预留及患者和医生已到服务位的合法开工前输入，完整校验后执行一次真实固定步创建Attempt并领包。此前选择、预留及行走属于输入，不记为本例执行；改变设备等级后以结构性报价比较新计算工时，再推进实际工作，既有Attempt的费用及其他开工承诺保持。结构性报价不声称正在占用的设备可立即再次开工。

CLIN-15 从原位置上的可叫号输入只读核对7包仍缺8包协议、恰好8包不产生缺货请求，再以原60包库存执行一次正式固定步，检查完整资源束真正预留、80tick准备量及未领包/收费；不再先执行旧门诊目标的移动。CLIN-16 的取消从已预留输入开始；超时从同一准备在 `deadline_tick-1` 的合法输入开始，连续执行两个正式固定步。第一个调度入口tick为 `deadline_tick-1`，资源保留；第二个入口为 `deadline_tick`，资源释放。模拟tick在固定步结束时加一，因此两份完成快照分别为 `deadline_tick` 和 `deadline_tick+1`。此前等待为输入，实际到齐、器械核对和完整手术工作仍由 CLIN-18 贯通执行，门诊到院至离院仍由 CLIN-02 贯通执行。

CLIN-29 的 C 档舒缓从完成接待和全部诊断、尚未选方案的输入开始。医院配置独立护理护士和查房医生，病房入口与原诊室外墙之间保留实际通道；覆盖护士已经在所属病房的合法护士基地服务点就绪。选择前校验完整世界、真实护理归属和资格，必须仍无 Attempt。正式选择舒缓后，患者、治疗医生与护送人员按实际路线到场；恢复逐步累计1800个实际推进tick，每tick仅减少一个标准tick，完成护理和查房后才结算。

CLIN-13、15、16、17、18、29 的 `details.timing.stages_us` 及 `CASE_STAGE` 日志记录用例内部阶段用时。CLIN-17、18 通过测试侧子类记录临床、空间、通行缓存和各服务阶段计时；服务计时子类从当前方法签名生成并保存到隔离工程，`profile_sources` 保存源码摘要，`profile_errors` 必须为空。每个覆盖方法只调用一次原生产方法，接入计时前后世界事实必须相同，计时不改写生产脚本。`input_sha256` 为开始执行前完整世界二进制输入的SHA-256，用于确认固定负载测量输入一致，不把旧输出定义为正确答案。CLIN-18 分开记录实际到齐与整备、承诺保存恢复、最初三步工作及余下四段工作，并输出真实开术与苏醒tick。CLIN-29只记录已诊断输入、病区覆盖输入、选择并开工、门诊操作及实际转床恢复查房的独立阶段用时，不接入逐方法计时。CLIN-17、18的计时快照周期性写入隔离工程，超时中止仍可定位已执行阶段。`inclusive_calls` 记录调用数、累计和最大微秒耗时；调用可以嵌套，累计时间不能相加。计时子类安装和恢复重装包含在用例准备/恢复阶段内，与实际调度、工作分开。

CLIN-06 的工时预期独立使用模拟规格§4及 D09 的30标准秒：令 `E=设备等级×治疗能力发挥率`，`B=30÷(1+0.05×(治疗能力−1)+0.2E)×(1+0.003×劳累)`。本夹具没有沟通附加工时或科室专长倍率，常规预期为 `ceil(B×10)` tick，舒缓为 `ceil(B×1.8×10)` tick；两者分别在最后取整一次，不将已取整的常规工时再乘1.8。

CLIN-24 的10秒为标准查房工作量，实际工时应用《诊室互动、医生劳累与员工休闲》§4的开工劳累倍率。缺合格查房者的等待前提成立后，指定医生暂取诊断1输入，恢复查房班并完成真实基地整理；所有医生仍无查房资格时，再让指定医生沿真实 Move 到床边，护士原安全离位也须完成。到位且无 Move、尚无查房服务时记录劳累 F、治疗能力 L 和适用天赋工作率 R，随后恢复该医生既定诊断2输入并推进开工。独立预期为 `ceil(10×10×(1+0.003F)÷(1+0.05×(L−1))÷R)` tick，只在最后取整。本夹具查房医生为治疗1的人类 S49，其天赋只作用于课程，查房 R=1；不清零已有劳累，不以 Session 总工时反推输入。

CLIN-24 完成真实查房、唯一结算及安全离院后判定结果。失败时以正式世界流式编码保存该现场的完整 `world.freeze()`，结果包含绝对路径、字节数、SHA-256和模拟tick；前提失败同样保存已经实际建立的模拟世界，不从外部缓存补入已完成事实。
