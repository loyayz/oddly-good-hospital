# 前后队列临床交接专项

业务边界：从新的标准 `surgery_transfer` 前置状态开始，患者先真实离开手术台，护士走到队尾集合，按成员顺序沿队长尾迹转运。队长到床并结束队列后，护士仍须真实走到 `operator_cells[0]`，两人的移动均结束才交接为恢复；不把队长到场当作护士到场。

`clinical_convoy.gd` 是独立 `SceneTree` 测试，使用现有临床前置生成器。运行前按工程说明准备实际版本的 Godot 与完整原生平台库；不以替代返回值或旧运行报告充当验证。

```sh
godot --headless --path <isolated-project> --script res://tests/acceptance/clinical_convoy.gd -- <absolute-output.json>
```

选择理由及断言：

- CLIN-20 的转床交接实际执行，检查每步世界合法性和同层身体不重叠，床旁交接记录实际坐标。
- CLIN-28 的当前格式中途 JSON 流保存恢复，重建服务后继续，同一输入的完整最终事实与不中断执行一致。
- 原 Attempt、床位承诺和恢复余量不变，不提前计护理恢复工时。
- 转运前、实际队列中及患者到床后的报价只读，包含护士最后独立走到床旁的工时；行进中的原队列不重复计算护士集合。
- 当前队列恢复拒绝旧 `offsets`、缺失或错误成员/尾迹、错误领队、重复成员、错误楼层、断裂尾迹、间距不足、非有限数及多余中心；门包络形状也须合法。

前置声明：生成器允许手术及苏醒最后工作 tick 的合法命名输入，但本专项不声称重测完整手术和苏醒。被测的离台、集合、移动、床旁到位、恢复交接均实际运行，不瞬移、不改变步长。该专项不是完整临床、全部交通、Windows 构建、性能或画面验收。

## 保存队列占地边界

`convoy_restore.gd` 单独验证恢复时的一次性完整尾迹占地检查。其 20 个变体覆盖无真实成员重叠但队尾间隙被外人占用、另一队列交叉、静态障碍/设备/墙/净高、他人预约、本队成员预约豁免、不同楼层及真实登舱/乘梯/离舱阶段。登离舱仅检查 `ground_regions`，乘梯阶段不占地面。所有检查只读，不把坏存档继续当合法游戏运行，也不增加每步成员通行检查。

```sh
godot --headless --path <isolated-project> --script res://tests/acceptance/convoy_restore.gd -- <absolute-output.json>
```
