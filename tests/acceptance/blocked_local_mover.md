# 受阻的局部动作

依据 `docs/design/01-simulation.md` 的实际相撞、正在有效离开和原任务保留规则。局部意图本身不是通行承诺；对方的当前实际一步也被堵住时，仍按现场接触处理。

```powershell
godot --headless --path . --script res://tests/acceptance/run_blocked_local_mover.gd -- OUTPUT.json
```

`LOCAL-BLOCKED-MOVER` 在合法空地放置三张普通 2×1 桌：上边 `[38,69]`、下边 `[38,71]`、背面 `[37,70]`，形成前方开口的短通道。a 从 `[39.4,70]` 前往 `[43,70]`，b 从 `[40,70]` 前往 `[39,70]`。通过真实移动请求开始，不预置局部动作、伪造碰撞或修改移动预算。

a 先后退，b 沿原路线前进；当双方真正堵住彼此时，a 的局部意图不再代表它能有效离开。开阔一侧的 b 应按原左右优先规则自然绕开，a 沿原轴线继续。两人必须在 300 步内分别到达原目的地，原路径和请求序保持。

每个实际步检查速度预算、两人身体与已接受扫掠、三张桌的身体和扫掠安全，以及世界合法性。a 的 y 始终为 70，b 确实侧移，不能以两人都开始侧移作为通过。首次碰撞后用生产 HospitalJsonStream 写盘、摘要校验、解码并冷建完整世界，核对事实一致，再完整执行至双方到达。

修复前真实走 300 步仍未到达；修复后正常分支 44 步，首次实际步后的冷恢复再走 43 步到达。此例和 `LOCAL-ONE-AVOIDER` 共同约束：对方当前一步畅通时保留原回接意图等待；当前一步也受阻时不因已有意图而锁住另一人。没有固定优先权、让行承诺或整层动态搜索。
