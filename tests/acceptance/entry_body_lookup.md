# 入口真实身体局部查询

依据招聘规格 `docs/design/11-growth-arrivals-recruitment.md` §6.2、6.5 和员工生活规格 `docs/design/09-consultation-wellbeing.md` §4、5。业务规则不变：招聘按原顺序选择 1F 入口合法空格；返院只排除本人；两者都按当前同层 floor 身体的严格矩形相交判断占用，不加入预约、移动扫掠或队列走廊占用。

```sh
godot --headless --path . --script res://tests/acceptance/entry_body_lookup.gd
```

可用 `ENTRY_BODY_TEST_OUTPUT` 保存 JSON 结果。需要正式原生空间索引扩展和固定 Godot 4.7.2。测试使用独立用户资料目录；不会读玩家医院。

- 完整工厂建立合法边界。接触边缘不挡，极小交叠阻挡；忽略本人、不同楼层、outside 与预览 ID 的行为独立核验。
- 对全部物种、站立/坐姿/躺姿、四朝向以及症状身体绑定/清除，与直接枚举当前身体的参考结果对照。姿态组合是几何计算输入，不声称执行了每种临床姿态转换。
- 通过真实招聘录用九人，稳定填满入口；下一人失败不收费、不消费候选。首人真实走开后，立即可以在空出的首格再次录用。
- 两名员工真实离院并正式召回。同一 revision 连续返院时，后者不能穿过先进入的人；恢复当前完整事实后，真正腾空入口才继续返岗，过程验证世界且不重叠。
- 实际地面队列转弯、登梯、乘梯、离梯和到达解散逐步对照。走廊中间的空隙不是身体；忽略队长不能漏掉跟随者。transit 身份始终按原规则忽略，恢复 floor 后立即参与查询。
- 非方形患者真实走到导诊队尾后，入队转向立即发布身体；在下一次移动、revision 变化或重建前，441 个内部小矩形都命中。该源头遗漏先由专项复现，再以 `sync_actor` 修复，不用入口全院刷新掩盖。
- 合法设施预约与移动扫掠不被误加为真实身体。世界/facts 身份更换后不能保留旧身体索引。
- 固定 320 个远处角色，100 次热入口查询，分别计数局部实现与完整枚举的身体读取，并确认无热索引全员重建。耗时仅是该操作的辅助观察，不代表整步性能、帧率或发行验收。

复用现有 BodyIndex，合法地面队列由站立成员形成，尾迹包络覆盖成员身体；仅展开查询命中的队列，然后精确检查每个成员的当前身体。生产转床流程在队列移动结束、解散并恢复单体索引后才发布 lying；该交接由 CLIN-20 实际流程验证。正常发布沿现有 `sync_actor`、移动和交通接口；不为没有通知的任意裸 facts 修改建立另一套全院扫描。

选定既有回归：STAFF-36、37（录用身份/费用/失败原子性）；STAFF-76、77（真实离院、受阻返院与恢复）；CLIN-20（真实陪同转床、队列解散后入床躺下）；GUIDE-REAL-ARRIVAL、GUIDE-ARRIVAL-ORDER、GUIDE-DYNAMIC-ADMISSION-RETRY（导诊真实到场、次序和动态阻挡重试）。此专项不替代全量回归、Windows 实机画面或发布构建。
