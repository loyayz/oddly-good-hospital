# 个人床局部机会观察

依据个人床规格 §6.1–6.3。业务分配、稳定优先级、最大兼容匹配、原合法去返程与实际睡眠占用保持不变。本专项只检查未分配员工与无主床之间的机会变化如何触发原分配入口。

运行：

```sh
godot --headless --path . --script res://tests/acceptance/personal_bed_dependencies.gd
```

可用 `PERSONAL_BED_TEST_OUTPUT` 指定 JSON 结果文件。

- 由工厂建立合法未分床/床边占用边界，验证完整输入与员工生活状态。
- 不变状态、远处人物、远处普通行程和电梯排队计数不重做床匹配；热索引不重新遍历全员。
- 床边人物变化、原设施预约经过真实移动安全释放、当前 connector 下降方向变化仍触发。
- 发生合法床机会时使用当时的员工睡眠优先级；只改归属，不生成移动、使用预约或恢复。
- 暂不可用床不生成动态观察；恢复可用或取消改建后重建候选区域。
- 已固定几何不兼容的巨型员工真实在远处移动不重做匹配；通过建造入口移开阻挡设施后，原被排除者立即恢复候选并按当前优先级取得床。
- 多员工从完整工厂前提建立，关键输入和结果同时校验完整世界及员工生活状态，不只检查最终床主。
- 另以移动期 sweep 的计算边界检查临时扫掠消失。正式 movement 阶段本身会在员工生活调度前结束 sweep，此条不声称复现正式调度缺陷。

该专项使用当前 actor/reservation 所有者的发布入口维护已有空间索引。世界更换/恢复和冷索引沿原机制重建，不为任意未通知的裸事实编辑额外遍历全院。只缓存既有 fit 返回的几何区域及已证明几何兼容的员工身份，不保存路线、候选选择或另一套预约事实。

相关既有分床、最大匹配、库存生命周期与单向交通边界分别为 STAFF-53、54、55、73；个人床完整行程消费检查为 STAFF-41 的 facility_rules 子边界。此专项不替代这些用例，也不是整步性能或实机验收。
