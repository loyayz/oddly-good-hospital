# 环境观察批次与覆盖复用

依据 `docs/design/08-hospital-life.md` §4、§20：环境增益、脏乱、机器/施工噪声仍按原四邻传播、墙门及屏风阻隔计算；热图只是当前事实的只读观察。本改动不改变范围、数值、来源、噪声绕行或视图着色。

```sh
godot --headless --path . \
  --script res://tests/acceptance/environment_cache_scope_runner.gd -- \
  /absolute/output.json ENV-CACHE-LAYOUT ENV-CACHE-DOOR ENV-HEATMAP
```

- `ENV-CACHE-LAYOUT`：相同事实的20轮查询不再枚举覆盖来源；非几何提交复用，无关几何通知核对后仍保留原掩码。独立原始事实四邻遍历核对障碍、门、屏风移动/旋转、墙体、已购地变化及完整事实替换；这些是传播计算边界，不声称执行此前建造。另从合法世界真实执行建房、放屏风、旋转、移动、拆除和撤销，每次验证完整世界与覆盖结果。
- `ENV-CACHE-DOOR`：合法大体型角色真实穿过窄门。实际扩门及释放通过既有预约通知失效环境缓存，不依赖额外结构版本变化；门内JSON序列化恢复后继续实际移动，逐步核对原始事实的完整覆盖距离与顺序，最终到达并释放。
- `ENV-HEATMAP`：同一9×9输入对比逐格完整观察与批次输出，来源仅忽略无业务含义的解释顺序。冷批次各来源只准备一次；无变化重查不增加覆盖计算；嵌套查询保留父作用域；隐藏热图的空输入不准备来源；故障、附近人物变化及未启用地面保持原行为。

关联回归：`OPS-11`（环境计分及R15）、`OPS-18`（真实机器/施工声和屏风命令）、`OPS-42`（查询作用域与动态来源）、`GROW-75`（串行/并行体验观察及恢复交接）。按实际改动选择，不默认全量回归。

缓存沿用原8层、每层128个覆盖结果上限。已建立的只读批次按现有布局版本及预约通知复用；直接无批次查询仍核对原始来源。首次需要某层覆盖或有相关变化时仍构造该层完整覆盖边界，这不是把整层数据改成懒执行的寻路搜索，也不声称本阶段已经消除所有环境查询枚举。运行时缓存和预约变更序号均不进入存档。功能计数不等同整步性能、发行构建或图形实机验收。
