# 随机来客需求专项

依据：`docs/design/11-growth-arrivals-recruitment.md` §1.1–1.2。旧精确诊疗容量规则已被开放诊桌产生随机需求取代。

运行独立专项：

```sh
godot --headless --path <隔离工程> --script res://tests/acceptance/random_arrival_demand.gd
```

`random-arrival-demand-results.json` 记录逐项结果，任一失败退出1。无头专项不代表图形、Windows运行、完整经营或实际磁盘存档验收。

- 空地没有机会，也不抽人数或种子。
- 一张开放诊桌对应6基础兴趣，查询只读。
- 员工不可用、临时设备故障不改变需求。
- 同日查询、边界调用和完整内存快照恢复不重抽计划。
- 已放置新诊桌不重写当天计划；下一日计入需求，独立拥挤上限为16/桌。
- 暂停时保持规模命令立即应用，不推进tick或等待容量任务。
- 保持规模取当前与所存规模较小者。
- 关闭所属科室或房间时不计入明日需求。
- 界面明日区间反映当前有效规模与保持模式。
- 相同种子与输入生成相同计划及随机状态。

扩建场景从合法已放置房间/诊桌的日边界输入开始，只验证计划交接，不把设施工厂调用算作建造流程验收。患者实际入院、初诊、治疗、暂缺资源及耐心离院由自然入院与临床专项验证。

## 历史容量测试

`legacy_arrival_projection.gd`、`legacy_arrival_preparation.gd`、`legacy_capacity_solver.gd` 只为保留独立临床参考模型、原生数值检查和旧测试的可读依据，实际游戏不创建它们。旧 GROW 精确C/K容量、容量等待、封闭求解输入测试不再定义当前产品行为；不能把运行这些旧夹具称为随机来客验收。引用这些历史对象的独立临床/数值检查仍须明确其范围。
