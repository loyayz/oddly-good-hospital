# 环境真实墙边局部查询

依据 `docs/design/08-hospital-life.md` §4、§20：墙阻隔四邻环境传播，真实门洞放通；共墙各房间的墙段和门归属仍独立判断。当前扩门对环境观察生效，不把人物通行预约权限变成隔音权限。墙材只在真实墙边贡献数值，装修报价不得接受门洞。

业务规则、传播范围、材料分数和收款规则不变。交接点是环境服务向既有楼层静态几何借用墙/门位置，以及向预约所有者查询当前扩门区域与实际 span。楼层加载同时建墙段索引；布局变动沿既有几何版本更新。临时扩门使用已有预约索引，不建第二份环境布局缓存，不保存运行时索引。

```sh
godot --headless --path . \
  --script res://tests/acceptance/environment_wall_lookup_runner.gd -- \
  /absolute/output.json ENV-WALL-LAYOUT ENV-WALL-DOOR ENV-WALL-LOCAL
```

- `ENV-WALL-LAYOUT`：真实创建含4×4内接矩形的凹形房间，四次旋转、移动、拆除、撤销。每次验证完整世界，并逐方向对照1,056对局部墙边。包括完整事实替换、不同世界、不同楼层、同格和非法方向。
- `ENV-WALL-DOOR`：继承实际大体型角色穿门专项，真实扩门、持有、JSON序列化恢复、继续移动、释放和到达。每步不仅比完整传播距离与顺序，还对照门附近324对真实墙边。不修改模拟步长或瞬移。
- `ENV-WALL-LOCAL`：合法共墙两侧归属、原门及相邻实墙、墙材报价、门洞上材料失效和整数/分数位置的完整环境值对照。再实际建18间远处房间，固定200次局部查询仍仅返回200个墙段和200个门候选；记录原始全扫对照的访问数。计时只是该固定查询的诊断，不代表整步性能。

`environment_wall_reference.gd` 保留独立原始事实墙门判定。已有环境覆盖专项的原始四邻遍历也使用此判定，避免让被测索引同时提供期望值。

关联回归选择 `OPS-11`（环境计分、R15与原始四邻距离）、`OPS-18`（运行/施工声音与屏风）、`OPS-42`（环境观察边界）和 `SPACE-58`（共享静态楼层加载、失效、驱逐及恢复）；再选 `ENV-CACHE-LAYOUT`、`ENV-HEATMAP` 检查原覆盖缓存与批次。独立门专项已执行真实扩门，不重复该同一用例。未覆盖全量游戏、图形实机、发行构建或跨系统整步性能。
