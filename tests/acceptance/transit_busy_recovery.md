# Transit ground recovery after safe landing release

Requirements: navigation movement §4 (`docs/specs/26-10/2026-10-19-task-navigation-movement.md`), transport §4.1 (`docs/design/11-growth-arrivals-recruitment.md`), and adopted A41 (`transit_presence.md`). A local walk must not be held by unrelated remote occupancy; actual boarding/alighting entrances remain protected. Leaving drops the old ticket; actual return obtains a new one without changing original movement/job ownership or already-present ticket order.

Run `transit_busy_recovery.gd OUTPUT.json`. Four bounded cases execute: solo and convoy return after an incoming trip completes and a different ticket starts empty travel; solo and convoy source-boarding protection until actual departure. The first solo fixture declares an already-admitted assigned maintenance contractor as a valid initial boundary and creates its actual order through the normal command. The second pair declares a legal post-waypoint boundary. Every tested departure, return, ride and arrival is real production movement at0.1 seconds. These are minimal lawful fixtures, not reduced copies of the benchmark; the complete benchmark input remains unchanged. Fixture ticks use `space.advance`, not the full simulation pipeline.

The departed state is byte-serialized and restored into fresh services, then continued in parallel fact comparison within one test process. Body separation, floor sweeps, speed budgets, actual ticket presence, exact boarding order, original request/goal, maintenance job/work/payment facts and actual target arrival are checked. Source boarding is protected even when its destination is another floor; loaded incoming arrival remains protected through blocked alighting. Recovery does not itself grant movement or a ticket.

See `docs/reports/2026-11-12-transit-recovery-fix.md` for baseline failure, final selected checks, source identities and evidence. This is not a full-density throughput or starvation-free guarantee.
