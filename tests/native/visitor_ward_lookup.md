# 访客调度中的按需病房映射

`python3 -B tests/native/visitor_ward_lookup.py --output <新目录>` 提取原样生产 `_dispatch_waiting`、`_lookup` 及时间/阶段辅助函数，比较默认 `35d656dc` 基线与当前源码。公共等待、床边几何和移动动作使用显式输入适配器；这不证明真实到位、座位占用或完整探视流程。

规则与交接不变：只有有效探视窗口才读取病房归属；同次同步调度首次需要时构建一次，后续访客共享。没有跨调度缓存，也不复制业务所有权。该调度中的公共等待、座位提交和移动请求不创建/删除病房归属。多个病房记录映射到同一就诊时仍取原插入顺序第一项。

测试比较所有访客阶段、有效/过期窗口、同意与拒绝、离院、床边可用输入和动作记录；独立检查无需探视时不创建映射、多名探视者只创建一次，以及下一次调度重新读取变更的病房归属。完整环境应补 CLIN-31/32，不能用此隔离测试代替真实探视交接。

微基准使用8名访客及0/32/160条病房输入，每组12个A-B-B-A窗口，保留无探视需求与需要映射的控制场景。无需求且病房较多时省掉映射构造；需要映射时执行原构造并增加一个局部就绪判断，可能出现小幅成本或噪声。结果只描述明确适配器下的调度，不代表访客阶段全部耗时或医院整步收益。
