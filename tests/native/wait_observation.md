# 等待预约观察的隔离对照

运行：`python3 -B tests/native/wait_observation.py --output <新结果.json>`。默认基线为 `35d656dc`，可用 `--baseline` 指定已有提交。需要本机 Godot，工具不安装软件、不修改工程或玩家资料。

完整的基线及当前 `waiting_dependencies.gd` 与当前 `BodyIndex` 在独立 Godot 工程执行，仅添加脚本本地 preload。明确的空间输入适配器保守返回同楼层候选，再由真实 `BodyIndex` 精确筛选；这不是 Boost 原生集成。测试使用规则预期和基线双重核对 dirty 结果，包含字段变化、嵌套数组原地修改、旧/新范围、门跨层、删除、缺省值、取消订阅和 clear。当前实现的数组仅是运行期观察快照，不替代业务预约，不进入存档。

微基准固定 160 份预约、每窗口 2,000 次观察，交替运行四轮。每窗口先恢复相同输入并同步观察快照，再开始计时；分别测无变化与每次修改一份预约的模式。保留所有窗口，不以最佳窗口代替整体，也不由局部耗时推算整步或 FPS 收益。

输出记录命令、退出码、日志、源及驱动 SHA256、断言数和全部计时。完整 STAFF-69、真实空间服务、医院观察生命周期以及整步性能仍需另行验证。
