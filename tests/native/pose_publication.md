# 骨矩阵批次发布隔离验证

使用真实 `SkinnedPoseBatch`、`Skeleton3D`、`MultiMesh` 和着色器，合成合法的单三角面、多骨骼和多实例输入。复制当前源码及显式指定 Git 基线到新隔离工程；基线只改类名，不替换发布算法。无需加载医院平台 DLL。

```bash
python3 -B tests/native/pose_publication.py --godot godot --baseline 35d656dc --output /tmp/pose-publication-new
```

输出目录必须不存在。日志和结果记录引擎、命令、源码哈希、退出码和全部原始计时窗口；超时、脚本错误或比较失败均不能判为通过。

功能比较覆盖 1×1、3×21、64×40（实例×骨骼），姿态变化、批次/人物变换、交替矩阵页、末行非法缩放导致半页写入后的恢复、无有效边界暂停/恢复及重新绑定。比较实际矩阵页字节、独立矩阵基与零填充断言、原模型可见性、批次包围盒及资源计数。headless dummy RenderingServer 不保留实例数据，测试明确报告实例变换、颜色和行编号的服务器读回未验证，不把两侧默认值相等当作证据。它们的实际图形结果仍需有渲染器的测试。

计时固定为 64 实例×21 骨骼；每侧预热 30 次，再按 A-B-B-A 顺序执行三组、每窗 200 次完整 `publish`。所有窗口保留。这里测量 Linux headless 发布路径 CPU 成本，不代表实际 GPU 上传耗时、游戏整帧或完整 CORE-33/CORE-52 验收。未采用跳帧、降低骨骼或角色数、复用过期姿态。

本次生产优化仅将恒定颜色和行数据写入移至绑定时，将批次逆矩阵移出逐实例循环，并把永远不使用的像素填零移至页创建时。每次成功发布仍覆盖全部有效骨矩阵像素；失败后再次成功时也必须完整覆盖，保留原图像更新、页交换和动态校验。
