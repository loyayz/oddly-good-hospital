# V2 plain measurement review

## Disposition

Static measurement structure is suitable for the explicitly limited HospitalSimulation wall-time scope, but the frozen v2 series aggregator must be corrected before a qualified repeated series. Godot syntax/runtime smoke, actual protocol selection, clinical input qualification and real performance remain unverified here. No engine or benchmark was run, no production/source/control file changed.

## Required correction

`run_series_v2.py:26` breaks on a SCRIPT ERROR in the engine log without storing a rejection in the run record. Line28 computes all_repeats_complete using only complete and absence of qualification_error. If the error is in the final requested run (or the only run), and the harness emitted complete=true with non-reception work, the summary can claim all repetitions complete despite rejecting that run. The diagnostic error remains in raw.log but is absent from the aggregate predicate. Use an explicit per-run accepted/qualified Boolean and persistent rejection reasons; the aggregate must require that every requested record passed all process, report, log, sample-count and business checks. A failed series should return nonzero after preserving its summary.

The same final predicate accepts repeats=0 through vacuous truth. The frozen original protocol uses5, so this is not a claim that its current invocation is a no-op. Nevertheless validate positive integer repeats/steps, nonnegative prefix and finite positive timeout before launching. `aggregation-counterexamples.json` reproduces both Boolean cases without running the tool.

## Verified static boundaries

- `plain_v2.gd:65–67` measures the real `HospitalSimulation.step()` call with monotonic get_ticks_usec. `simulation.gd:264–273` completes the real step, including any internal waits; it is latency, not process CPU time. WorldState.TICK_SECONDS remains0.1. No teleport, population hold, disabled arrival or modified rule was found in these tools.
- The input is loaded from a disk envelope into a fresh WorldState/Simulation per process. WorldState uses the provided facts and freeze deep-copies complete facts, including RNG. The tool does not write back to the input file. Runtime caches are newly constructed, and the same Simulation instance continues across prefix/sample. Initial observations and constructor ensure calls may prepare some caches, so this is not a claim that every query or OS cache is cold.
- `plain_v2.gd:57–61` snapshots counters at the predetermined prefix boundary. Prefix plus sample uses consecutive original steps; there is no state reset between them. It records initial and sample-start actual population and final population without truncating or deleting natural arrivals.
- Step timers exclude the before-state copies, observation, JSON trace and flush. Window wall includes those costs. all_wall spans prefix plus sample, while initialization, final world validation/serialization, process launch and shutdown are outside this loop wall. `real_window_us_including_observation` and throughput labels are appropriately limited; none is whole-game/GameSession or GPU/FPS throughput. Boundary population observation is charged to prefix rather than sample.
- Per-step enter/complete logs and completed-count/tick checks expose incomplete steps. Sample step sum and nearest-rank p50/p95/p99 use only rows index>=prefix. These are within-run descriptive statistics; there is no invalid independent-sample confidence inference or speedup claim.
- Work counters count observed decrements in still-present sessions and explicitly miss transitions/removal ticks, so they are lower bounds, not total completed services. Excluding `reception` in the series gate avoids calling reception clinical work. Nonzero lower-bound work alone is not a proof of completed treatment or correctness; use actual events/facts and the independent business oracle.
- `run_engine.py` launches a new process session and enforces timeout with TERM then KILL to that group. Its own process exits0 even for a failed engine, but the series reads the saved returncode/timed_out fields before accepting a report. Keep that distinction. Wrapper wall_seconds uses time.time, so retain it as auxiliary process duration rather than the authoritative monotonic measurement.
- The series verifies original source hashes, input and selected Godot tool before launching. Native.so is among original source rows. It records current engine hash but does not independently enforce it against the accepted runtime manifest; coordinator must compare it. Protocol hash alone does not freeze the Python runner bytes, so archive/hash both Python runners with the protocol. Repeat-specific source/input identities should be checked or the selected files held immutable during the series.

## Scope still open

The original tick21→1021 window contained no non-reception work. A later continuation cannot qualify it retroactively. The replacement protocol must identify the exact initial input, fixed complete prefix and sample interval before measurement, preserve prefix cost, and bind qualification to that sample. Current v2 has no selected/frozen executable clinical protocol and was not engine-smoked in this review. The planned main-worker smoke is still required. Missing/invalid result JSON can raise before the series aggregate is saved; this is an incomplete failure, never a pass, and should receive a persisted failure classification in the corrected runner if handled.

GPU/rendering, native persistence, Windows/release acceptance, universal liveness and all deferred audit scopes remain outside this measurement review. Bash/PowerShell candidate integration remains on hold; no files from that candidate were read or integrated.
