# Root-only attribution static preflight

## Decision and scope

Current root-marker generation is a plausible bounded diagnostic candidate, not an admitted or executed profiler. No Godot process, test engine, baseline, source edit or production change was performed by this review. Four small source/plan files were read; only a pure text/Python mirror of marker insertion was evaluated. Current A measurements must finish without this observer running alongside them.

The static mirror finds60 insertion sites, including both floor-guidance dispatch and advance. Removing only generated marker lines exactly recovers the current original step_nonblocking method. All three explicit returns (simulation.gd283,294,381) receive close_root. The method hash and exact site map are in static-marker-check.json. This proves only text preservation for the current source, not that reload/new/attach executes correctly.

## Concrete admission risks

1. **Attach is not transactional.** step_profile.gd72 constructs a second HospitalSimulation on the original WorldState. Its constructor runs _ensure_services before the temporary services are disposed and the original runtime graph is copied. The equality check at79 detects changed facts after the fact, but returning null does not restore the world. An unsuccessful attach must abort that diagnostic instance/process, never fall back to a plain run on the possibly altered state. No actual mutation by this constructor was observed here. Capture complete facts including RNG before and after both successful and failed attach.
2. **Non-null is not the whole success gate.** _compile writes generated source to the default res://.cache/performance-loop-20261018/profile-sources. File-write failure adds errors but can still return a compiled script. Set source_directory to a new diagnostic output directory outside the locked A source tree. Require an empty error list, compile_error==OK, actual generated-source bytes/hash, exact current production/method hash, root_method_preserved=true and nested_enabled=false. Do not overwrite an earlier generated source or use recompilation success to ignore evidence-write failure.
3. **Runtime ownership transfers.** attach copies script variables by reference after disposing only the newly constructed temporary services. The original and returned objects then refer to the same original service graph and command/cache state. Do not dispose the old object after success: its dispose would tear down the transferred services. Drop the old reference without disposal, and dispose the returned simulation once at final completion. On an error after partial transfer, stop the isolated process rather than attempting an improvised recovery that might dispose shared services.
4. **Attach changes preparation, even if facts match.** The additional constructor/ensure can touch world-owned or shared runtime caches. Record attach wall cost separately and verify original space/clinic/service/queue identities transfer. A fresh-runtime profile attachment is not guaranteed identical cache preparation to a single plain constructor. Treat the paired800-step comparison as perturbation/semantic evidence, not a speedup experiment or exact continuation of A's warm cache.

## Attribution interpretation

Root rows are intervals between consecutive markers, not exclusive function timings. For example, clinic.dispatch's span includes the following busy_view work until dispatch.staff_idle; the wellbeing marker is inside the staff loop, so parts of the next iteration can fall in its preceding span. integrated worked_staff includes the subsequent merge work until the next marker. The source site map should accompany any claimed hotspot.

Sixty is a static site count, not an expected per-step count. Production guards, repeated staff-loop calls and nonblocking re-entry change dynamic root_marker_calls. step.setup increments nonblocking_invocations. Explicit null returns close the root before Simulation.step sleeps/re-enters, so pending sleeps belong to outer residual rather than the last business stage on that normal path.

The driver must start its monotonic full-step timer after begin_step, stop immediately after the real complete sim.step, then call end_step. Root span and handler totals exclude some dispatch/timer overhead. partition_check_us is zero by construction of residual and is not independent evidence of correct accounting. For root-only mode, require no nested calls/edges and an empty stack, finite nonnegative stage/handler/residual values, complete retained records for the chosen800 steps, and exactly800 completed world-tick boundaries. Unexpected negative residuals or an unclosed root after a successful full-step path are tool failures to explain, not a percentage to normalize away. Record per-step marker counts rather than forcing all to60.

A generated-script runtime error can leave an open timing span or make the outer ordinary step wait for a result that never arrives. The external process-group watchdog and raw ERROR/SCRIPT ERROR rejection remain essential. A timeout has no successful final facts or valid completed-step attribution. end_step(result!=null) alone is insufficient: check observer errors, original world validation, raw logs, final facts and requested sample count.

## Minimum runtime admission after A

- Use a separate diagnostic workspace/output and the frozen tick1021 input. Record all source, engine/native, driver and generated-script identities. No nested/all-instance mode or retired HOT_METHODS restoration.
- On a small tool admission case, verify actual reload/attach and complete facts/RNG preservation, plus the same original world/content/space/clinic/services and queued-command arrays/handlers after ownership transfer. A boundary-rejection case on a separate tool-owned instance should return null without mutation. This is tooling evidence, not a new clinical test.
- Run the planned bounded plain and root diagnostic from independent fresh copies of exactly the same complete facts, for the same fixed800 real0.1-second steps. Keep full semantic events, facts and RNG plus actual work/arrival evidence. Compare these before interpreting stage percentages; strict equality is useful additional evidence, and any allowed difference still needs a current-rule explanation.
- Keep initialization/attach costs, outer step wall, root spans, handler cost and residual distinct. Preserve all failures and incomplete windows. The new paired plain diagnoses this restored-cache window only, not the original continuous A cache history.
- Only after those gates may a concrete root-stage hotspot justify a minimal deeper probe. Any resulting production improvement returns to the original A protocol and affected functional checks; root profile timing is never its final benefit number.

No specific gameplay mutation or timing corruption has been observed because the candidate was not executed. The facts check, evidence-path behavior and ownership hazards above are grounded in current control flow and are prerequisites to claiming the observer is transparent.
