# 固定 160 人完整步快速诊断

本工具测量普通 `HospitalSimulation.step()`，用于定位高成本阶段和验证局部优化的整步收益。它不导出 Release，不测 GameSession 后台容量准备、真实渲染、GPU、持久化 IO 或两小时稳定性；所有结果固定 `diagnostic_only=true`、`formal_pass=false`。

## 输入与运行

输入为 `FileAccess.store_var` 保存的完整世界业务事实和内容身份。读取使用 `get_var`，不是对文件字节直接 `bytes_to_var`。每次运行从同一只读输入建立新世界及运行时服务；角色、历史、随机流、票序、预约、账目和工作余量完整保留，不恢复运行时缓存。

报告中的 160 人由 120 患者、32 原员工、8 真实亲友组成，64 房间、1,336 设施、4 层。所有计时步须完整返回、人数始终 160、角色身份集合不变、世界合法，且非接待临床工作实际推进。实际清洁/员工需求另有窗口进展检查。失败和超时不能算合格样本。

在已经准备并导入的独立工程中运行，输出必须为新路径：

```powershell
& 'C:/programs/godot/Godot_v4.7.2-stable_win64_console.exe' --headless --path '<工程绝对路径>' --script res://tools/performance/representative.gd -- --input=<输入绝对路径> --output=<新报告绝对路径.json> --steps=80 --profile=plain
```

模式为 `plain`（无插桩完整步）、`root`（互斥根阶段）、`nested`（根阶段及选定方法调用树）。不能把附着后关闭记录的包装器当作 plain 控制。输入读取、观察、事件展开、序列化、逐步证据写盘和完整世界冻结均在 `.step` 外部计时；计时样本包含完整步本身的所有同步工作及 pending 等待。

每个完整步保留原始微秒耗时。分位数为 nearest rank，不截尾，不删除冷首步或长尾；报告同时提供冷首步、后续均值、全窗均值、P50/P95/P99/max 和总耗时。默认不预热运行时缓存；每个窗口仅导入资源准备发生在计时前，业务缓存从新世界开始。多次前后交替运行应分别保留每窗指标，不能只挑最好结果。

`--setup=<JSON绝对路径> --store=<新输入.bin> --steps=0` 仅生成运营输入：普通付费装修命令、正式地污生成入口，以及原闲置员工的合法休息/睡眠阈值输入。没有创建完成任务、设置进度、改变区域、传送活动人物或补充额外员工/设备。零步输出仅证明准备与世界合法，不证明临床或清洁实际工作。

公共设施输入由 `prepare_public_input.gd --source=<完整原输入> --output=<新输入> --contention=false` 初始化新结构的亲友区域意图和员工个人床归属，保留原位置、工时、身份与随机流。它是未发行版本的测试前提构造，不提供旧存档迁移。分床初次计算另计入准备耗时；`personal_bed_probe.gd` 分别记录首次分配与已分配状态重复读取，不能用后者代替前者。

`--contention=true` 另构造命名的合法临界输入：保留全部160人，将原绝对时刻统一平移1800tick，16名原闲置患者处于四层生活区外的合法接近位置，首次需求刚到180秒，并提交原本可支付的清洁与待工装修。变更前提逐项写入 `.preparation.json`，全部身体、实际去返路线、原容量依据和世界事实通过校验。位置是该场景的初始条件，不是连续流程中的瞬移证明；后续300步以原0.1秒步长真实移动、排队、使用及退出。手动指定请求按预定步正常入队。观察器记录排队人数/人次tick、实际使用区域、8秒工时、完成、兜底和前人完整身体清空后的接续，且位于整步计时之外。

若需要定位后段长尾，`resume_representative.gd --source=<同源输入> --final=<已完成窗口.final.bin> --output=<新输入>` 只冻结那个实际完整边界，核对内容身份、全部人物身份、160人及世界合法性，不修改身体、工时、票序或完成事实。此类短探针单列为诊断，可能因当步没有实际临床工作而不满足代表场景资格；不能替代原完整窗口。报告单列 `initialization_elapsed_us`，不混入 `.step` 也不隐藏初始化成本。

## 阶段与调用证据

`step_profile.gd` 读取当前 `step_nonblocking` 的完整函数体，只插入根阶段标记；去除标记后逐字符验证源保持一致。服务子类包装选定方法并调用原实现，保留签名、默认参数和原有运行时图、命令队列与缓存所有权。服务转移后必须丢弃旧 simulation，不能对旧对象 dispose 已转移的资源。

根阶段互斥。嵌套行同时给调用次数、包含时间、减去已计时后代的独占时间；包含时间不能相加，也不能与根阶段相加。表中占比以外部完整步时间为分母。未包装的方法仍计入所属根阶段，不宣称这是逐方法全覆盖。

`observer_handler_us` 仅测记录函数体，不含全部包装派发/时钟读取开销；总扰动要与同输入 plain 比较。`residual_us` 是完整步扣根阶段与已测记录开销的余数，包含外层设置、等待及间隙。`partition_check_us=0` 是分解核对恒等式，不能独立证明归因正确。每步的阶段、占比、调用和完整标记保留在 JSON 及 `.steps.ndjson`。

最终 `.final.bin` 保存完整 `facts`（含 `facts.rng`）和有序语义事件。可比较完整二进制，或运行 `representative_compare.gd -- --before=<A.final.bin> --after=<B.final.bin> --output=<新差异.json>`。只有规则要求的结果必须严格确定；本次同输入局部只读筛选优化额外取得完整二进制相同证据。

### 慢步决策账本

对独立冻结工程运行 `instrument_all_instances.py <工程> --ledger`，再用 `representative_selected.gd --profile=ledger --selected=0,285,298` 执行完整300步。所有前缀步照常执行，只有选中的完整步记录账本。对应 plain 控制必须使用未插桩工程和相同输入。

`decision_profile.gd` 在原全实例观察器上记录每次已包装调用的编号、父调用、根阶段、业务人物、紧凑参数、返回结果及排他耗时。临床派单另外记录返回后的票据分配状态和等待原因；报价候选与实际预约可沿父链关联。完整调用行不使用旧参数分组数量上限。路线只保存数量与紧凑摘要，不复制全世界或将相同参数标签视为可共享计算的证明。

每步核对嵌套调用排他和与顶层调用包含和，逐根阶段列出未包装函数体耗时，再与观察器开销和完整步余数对应。计时采用同一继承观察器的权威计数，避免两套计时读数的误差。未包装函数仍归属于其根阶段，不能将这部分默认为零。账本用于归因，插桩耗时和采集开销不代替 plain 性能结果。

## 真实前提与失败边界

`representative_prepare.gd -- --source=<原正式输入.bin> --output-dir=<新目录>` 从全新合法初始世界建立实际诊疗前提。布局、人数、岗位和候选保留；首次模拟前声明的站位经过静态/身体检查。原冻结日计划只在三班完整 reference basis 精确相等时复用，不启动完整 742 病例求解。没有 source/day1 计划即拒绝。

`representative_continue.gd -- --input=<输入.bin> --output-dir=<目录> --run-id=<新ID>` 仅调用真实完整步，观察 GP、会诊、门诊准备及开工；每段至多 2,000 步或步间检查的 60 秒软期限，单个完整步可能越界。未达到目标保留合法续接点；固定负载失效只记录失败，不发布为合法固定输入。

本次 GP 窗口 tick823→903 共 80 步，包含真实 GP 剩余55工作 tick、完成及后续会诊。门诊输入 tick1151 已真实到场、领用1包并开始286 tick治疗；运营窗口计划40步至1191。原80步门诊探针在1201出现合法上门维修员使人数161，已保留失败。40步不是门诊完成、维修到场或持续稳定性的证据，不禁用其后维修，不缩短原治疗工时。

诊断应有外部进程树超时保护，并保留启动参数、源身份、原始日志和最后 enter/complete 标记。超时未完成的步没有有效耗时样本；不得将超时上限当作该步实际耗时。完整性能验收暂停期间不扩大为 Release/渲染/长稳测试。

`resume_representative.gd --source=<完整原输入> --final=<真实完成边界.final.bin> --output=<新输入>` 只接续已执行的完整事实，校验内容身份、原人物集合、160人和世界合法性，不提供位置、工时或完成量。已消费的手动命令不会重新入队。单步定位可能没有诊疗工时，此时即使步完整且世界合法，`qualified` 仍为 false、进程退出1；保留该结果为诊断，完整代表窗口另行验证。`nested` 的方法时间为包含/排除子调用的观测值，不能相加当作整步；速度收益使用同输入 `plain` 的完整窗口。
