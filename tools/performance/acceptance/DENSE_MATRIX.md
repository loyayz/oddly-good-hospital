# Formal joint capture matrix

This matrix assigns the existing design contract to actual Release capture groups and original operation interfaces. Each group requires its final exported probe, legal input and complete real evidence before acceptance. The original 0.1-second tick, original 1x/3x real-time session advancement, clinical work, actor departure and resource ownership remain active.

## Minimum workload groups

Seven independently reported groups cover the required workload dimensions without a Cartesian product. The 640-wide runs can jointly cover the maximum dense and wide-640 responsibilities only if their actual camera/scene keeps at least 576 real actors visibly qualified throughout each declared dense segment. Otherwise add a separate legal dense-640 group; do not lower its denominator, freeze departures or pool sparse segments. Each applicable frame/step percentile population still needs at least 1000 complete samples. A display-only extension may omit a new independent step-percentile verdict, but must retain all actual steps/speed/resource data.

New non-monotonic cost or a parameter interaction requires the corresponding additional group. If the primary hardware contract uses another actual main window, retain that primary group and label the 2560x1440 control separately.

## Dense sampling stop conditions

Each group records actual settings, hospital/session ownership and all operations. For D1/D3 and qualified W160 segments, independently count real displayed intervals and complete steps whose membership is certain in the dense segment. Continuous logical binding samples only provide frustum-admission evidence; corroborate actual visible IDs/raster before calling the density requirement complete. Do not join the end of one fragment to the beginning of another as an invented frame.

Stop only after the assigned operation blocks, the applicable complete sample minima and any declared real-duration requirement are satisfied. A due operation may finish late; it cannot be dropped at 7200s. Preserve the end boundary and continue actual capture to the next distinct displayed endpoint. Keep all ordinary cold/rebuild/autosave/shift/day frames in their original operating populations. Explicit user pause and original target loading remain labeled by their actual boundaries; waiting inside an already-started step stays with that step.

Input identities, receipts, generation/session ownership, ordinary failure outcomes and result assertions are mandatory alongside time. A parser failure, unsupported dispatcher, absent legal prerequisite, missing PresentMon display field, uncertain cross-clock membership or insufficient dense sample count is incomplete evidence. The seven-group count is a minimum only when every stated joint prerequisite actually holds.
