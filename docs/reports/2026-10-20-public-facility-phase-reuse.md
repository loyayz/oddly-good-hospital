# 公共设施阶段交接与等待复用

基线为dev `913cebef20696b324be4a70268508681d324339e`。公共设施按“选区→到区选位→等待→真实到位取用→安全离位”交接，手动目标、医疗预约、员工个人床、身体适配、队序和实际使用时长保持。对应规则见[公共设施规格](../specs/26-10/2026-10-18-public-facility-area-use.md)及[任务、寻路与移动规格](../specs/26-10/2026-10-19-task-navigation-movement.md)。

## 逐项处理

| 编号 | 源码偏差 | 处理结果与复用边界 |
| --- | --- | --- |
| 01 | 每次选区域入口重复枚举、适配同一批楼面点 | 按区域几何、完整身体及静态楼面版本复用入口候选和已检验点，惰性检查；保留全部合法候选、下界和稳定平局。 |
| 02 | 将别人计划前往的终点当成实际阻挡 | 安全等待区分移动意图、实际身体和真实预约；未来终点不产生使用权。到场仍执行当前碰撞和安全检查。 |
| 03 | 选区产生的入口在访客及整组交接时丢弃 | 同一决策将各成员已选入口传给出发交接，避免立即重新搜索；不保存为第二套世界事实。 |
| 04 | 固定公共设施候选统一附加返回选位前坐标的往返证明 | 公共候选只报价实际去程；真实返回义务仍归原生活、休息、娱乐任务。个人床原合法往返例外保持。 |
| 05 | 同一起点的多个目标分别进行精确搜索 | 接入现有原生距离场复用；保留12次摊销边界、结构/预约权限隔离及一次性A*回退。实际移动仍取得真实路线。 |
| 06 | 选座性格中的三格邻居对每个候选单独寻路 | 使用现有Boost有向BFS形成有界距离场，保留三格路径距离、真实边约束及预约豁免；不改为直线距离。 |
| 07 | 环境饮水条件嵌套重复适配、路线与临时世界 | 保留已有单批饮水查询复用，固定公共设施改为原世界去程；不再为公共候选构造通用去返程投影。 |
| 08 | 手动指定椅也计算自动偏好与评分 | 手动只验证指定目标，并将本命令预检目标交给首次派发；不枚举替代设备、不评分、不提前占用。 |
| 09 | 没有相关变化时每步重做完整局部选择 | 仅缓存等待负结果，按相关人物、身体、占用、队列、几何与连接结构重核。期限、资格、安全位置仍由任务及时处理，不延长轮询间隔。 |
| 10 | 已走到局部目标后丢弃目标、重新比较本区全部设施 | 患者、访客和员工先尝试对原目标执行当前原子取位；确实失效或竞争失败才局部重选。 |
| 11 | 每件候选遍历全部公共意图，生活设施还重复检查同一次队权 | 由原意图派生用途/区域/手动目标队列索引；只读候选批内不再重复队权查询，实际提交仍检查当前队权。 |
| 12 | 员工先选一个休息/娱乐候选，之后才判断队权，漏掉同区其他可用设施 | 将本候选队权纳入枚举，继续尝试原排序中的其他合资格物件。无新增容量、优先权或身体放宽。 |
| 13 | 实际取位反复计算不变的固定几何 | 缓存有静态版本依据的区域合法性；人物、当前预约、设施所有权、实际到场及真正病床扩展的退出证明仍实时核验。 |
| 14 | 用途、权限、具体目标失效或真实无路时未正确回交任务 | 区分区域行程和局部行程。区域失效才重新选区，局部目标失败优先保留本区；手动目标失效安全结束，不偷偷改派。 |
| 15 | 只要仍有移动记录就跳过任务期限及明确失败 | 移动返回带依据的结构无路结果。地面可取消，乘梯和上下床安全段先完成；原45秒时钟不刷新，到期从真实安全位置开始原8秒兜底。 |

上述15项均落实或保留已存在且满足规则的复用，没有把相同问题留作后续优化。额外修复如下：

- 实际退让可退到对方最终目标，然后等待对方走完，形成循环等待。历史退让点也避开对方剩余路线和目标，沿用原优先级与身体约束。
- 期限到达时当前位置可能是门口或交通登离点。`fallback_travel`阶段真实前往本地安全点；途中不计8秒、不发效果、不重置原期限，保存恢复保持该交接。
- 已购空楼层缺少公共区域索引，使没有设施时的随身用品兜底无法开始。索引纳入真实产权楼层，合法空上层按需派生，不按最高层号全量展开。
- 连接维修或停层/通行方向变化未使旧等待负结果重算，拓扑又可能继续读取旧停层。等待和拓扑共用导航结构依据；热缓存下移除、恢复停层仍更新实际可达结果，不把正常乘梯忙碌当成结构变化。
- 手动娱乐命令的预检结果未传给首次派发，造成同一指定设备立即重复报价。复用限于本次命令及相同完整组，不授予实际使用权。

## 保留检查与未采用的删减

| 提议或可能删减 | 结论及具体理由 |
| --- | --- |
| 删除取位时所有检查、直接采用出发前成功结果 | 不采用。人物实际到场前，设备可能故障、改建、被其他人使用，成员资格及队权也可能变化；必须在当前事实下原子提交。 |
| 个人床也改为公共设施去程报价 | 不采用。个人床分配明确要求原合法往返，且床存在真实承托、上下床及伸缩；已用单向故障连接边界验证该例外。 |
| 删除病床对其他实际人物出口的证明 | 不采用。真正伸缩的病床可能改变通行图，和固定椅子不同；其退出证明保留。 |
| 直接复用繁忙设备预览的“空闲”结论 | 不采用。预览可以证明前人离开后身体和目标有意义，不能证明现在已空闲，更不能创建使用权。 |
| 预先为每个新区域完整适配所有入口，或为一次报价立即铺满全层距离场 | 不采用。冷启动会付出大量可能未用到的计算；保留惰性入口检查和已有距离场摊销阈值，未新增自写通用寻路算法。 |
| 缩小合法候选、人数、身体、区域，或把排队当作失败 | 不采用。会改变合法负载和业务规则，且无法证明实际整步收益。 |

## 未完成与局限

Release正式矩阵、完整742病例容量/内存、最大房间预览、实际渲染比例/GPU资源证据和两小时稳定性继续暂停。快速测量不包含GameSession后台完整容量准备、渲染或持久化IO，不能据此声明正式性能达标或全量功能通过。

公共及GP仍有10～13秒级最大单步，GP P95未明显改善，运营未证明稳定收益；这些性能问题尚未解决。本批未重新采集完整步内部阶段剖面，现有次数只证明工作被省去或增加，不能给剩余长尾的每个阶段分摊时间。结构失败的缓存保守观察实际查询楼层，未实现逐格依赖失效；这是保留跨区/跨层合法绕行的安全边界，不以漏掉真实结构恢复换取命中率。
