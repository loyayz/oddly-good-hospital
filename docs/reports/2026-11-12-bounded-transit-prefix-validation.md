# Connector-owned bounded waypoint handoff: selected validation

## Rule and implementation
The confirmed cycle was incoming trip65→real exit blocker226→actual retreat blocker276→same connector wait.276 was not directly in the incoming exit. Transit now accepts a narrowly qualified actual-contact request for its own committed destination landing. Roles and floor IDs are not hardcoded; current next-connector identity, standing singleton ownership, no support/convoy/ticket/other local owner and actual exit dependency are checked. Eligibility uses the existing committed-landing predicate (including applicable boarding/riding), not only alighting.

Seven finite one/two-leg local candidates start at the real floating-point position. The stop is checked with last-leg orientation and existing legal/public/dynamic conditions. No full-floor candidate search, enlarged exit, future-space reservation or new priority. Explicit prefix is saved through the existing waypoint budget/order/continuation protocol. Dispatch rechecks actual origin, request/destination/suffix/root-trip binding and current static local geometry. It does not re-evaluate the historical retreat contact. Failure removes only that pending temporary instruction, preserving original path/cursor/body; no whole-floor fallback. Successful publication invalidates runtime route proofs/failure cache and uses ordinary floor motion/local collisions. Local intention may legitimately change under later real collision; original job/request/final target remain unchanged.

The prefix is bounded to two nonzero orthogonal legs, each at most clearance+0.00002 (public-floor binary32 addition tolerance). World validation checks its optional shape/owner fields and body-dependent extent; dispatch checks actual current legality. Old waypoint behavior is unchanged. V1/V2 persistent-owner designs and the earlier radius191 prototype are NOT implemented.
