# 合并后的回接与病房离位修复

初始复现与测量基线为 `e2b04eb6224bae862afa009f09d6b48aeb8ffa88`。LOST 的正常/冷恢复局部往复、CLIN-37 旧停车点被占后的不重选均已复现并修复。通过条件包含真实最终到达、原任务与目的地保持、实际身体/扫掠安全和当前生产流式保存后的冷恢复，不以没有重叠替代到达。

## 实际原因

**回接意图被误当成已完成进展。** `_local_try_return` 在侧移或后退后无法连接当前意图 C 时，仍从 C 的索引往后扫描。B 尚未实际到达、原路线游标也未推进，却被永久排除。对旧 `f8d8f80` 完整终态只读探测：30 个带局部等待标记的订单中，27 个能连接较早的未到达原路线点，但原恢复查询找不到；2 个原查询已有连接，1 个还缺目标附近家具的转角。这是全部移动订单的计数，之前 29 是其中导诊人物的计数，不能把等待标记直接解释为永久死锁。

合并版终态剩余 5 个同类等待，均能连接较早的未到达点。探测只对私有 Movement 副本选择意图，没有推进模拟，完整世界事实逐项保持。修复先保留能连接的当前意图；静态连接失效时，从实际游标重新枚举。真实碰撞仍依次尝试 B、C、D，实际到达才推进游标。当前代码对同一合并版终态的 5 次恢复查询均找到连接；实际到达另外用真实行走用例验证。

**LOST 的连续连接在真实接触后选回受阻方向。** 初始静态连接从约 `[43,70]` 退到 `[41,70]`，再向上走，被固定在 `[41,69]` 的身体挡住。新碰撞改变意图后，仅起点附近的几何不再包含后续设备，恢复查询又选择返回原走廊的连接，反复遇到 `[44,70]` 的固定人物。原目标、请求和身体安全可以一直保持，但 350 步仍不到达；保存恢复同样重复。

现在只通过已有局部索引取得实际位置和意图接点附近的设施边缘；当前没有移动订单的身体作为这两个邻域内的当前障碍几何，复用精确 BodySweep 检查。终点本身被占不提前否决 B/C 意图，未来移动者及未来扫掠不做整条连接预演。短连接继续保存至多两个剩余中间角点，真实后退腿到达首角才交给下一腿。LOST 采用下侧连续连接并实际到达 `[48,70]`，固定人物保持原位，未建立优先权或让行承诺，也没有整层动态搜索。

**CLIN-37 的目标失效检查被局部动作门控挡住。** 导航侧仍持有旧停车目标，`_dispatch_ward_release` 遇到尚未到达临时角点的 `local_move` 就返回；即使实际步暂时畅通、角色持续绕行，也不会执行临床安全选点。正常与恢复分支都实走 2400 步仍未完成。另一名护士在 tick 4295 实际站到 `[45,72]`；此时现有 `_ward_release_target` 已能只读返回 `[45,71]`，但离位流程未使用它。

临床离位现在先用目标身体范围查询当前局部身体索引。旧停车点被静止身体占用时，即使正在局部绕行，也沿已有本病房安全选点规则重选，安全取消本人旧地面行走再发布新停车点。原床位、患者、离位责任、班表、已排培训和整备余量保持，不命令占位同事移动。只有真实到达并清出完整床边缓冲才完成离位。停车点是离位任务的派生落脚点，不是更换原临床任务或患者目的地。
