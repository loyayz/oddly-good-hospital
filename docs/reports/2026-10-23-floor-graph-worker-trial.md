# 楼层冷图Worker分组试验

四个Worker实际完成独立楼层图构建，组经过时间10.769～12.870ms，串行同工作控制为19.290～20.877ms。全部图被原路线查询消费，完整GP业务、事件、随机流和最终状态一致；完整窗口没有建立稳定收益，P99仍有退化结果，方案不采纳。生产源码与测试保持`5712c6f7fbc7e222e2a483bc376201352fd5ffc2`，正式性能验收未通过。

本轮工程基线为dev `936a7f1`。报告及证据只做本地提交，不push。

## 实际边界与原规则

[入口路线诊断](2026-10-23-entry-route-costs.md)记录GP851的4张冷图构建43.943ms，其中包含主线程静态几何、Godot图装配和容量登记。普通867没有这项工作，因此本试验主要针对集中选区尾步，不能据图构建改善宣称普通步改善。

沿用同一合法160人GP输入，80步完整执行：120患者、32员工、8访客，4层、64房间、1336设施，0.1秒步长。Godot 4.7.2 Windows headless debug、原DLL、四任务部门环境采样、12次真实查询预热、128MiB导航总额度及查询部分1/4规则保持。没有缩短输入、恢复服务缓存或提前暖机。

生效版本在首次真实公共选座扫描已开启的只读边界枚举本轮实际合资格人物，按其起点楼层和原完整身体图键去重。主线程采集当前楼层来源、检查原容量额度并创建不可变`RouteClearance`；每个job独占一份`FloorNavigation/AStar2D`，只做点、边和掩码装配。`WorkerThreadPool.add_group_task()`分配至4个工作线程，主线程等待完整屏障后按原人物扫描顺序登记缓存。后续原图获取仍验证当前来源，任务、使用权、实际移动、队序、门及预约许可沿原路径提交。

预算准入先以完整9216点容量保守检查；实际登记继续使用原点数、来源序列化和固定容器计费，不增加每线程额度。四张图共39687424字节、查询部分0，目标134217728字节。这个值是驱逐容量记账，不是Release实际分配量或峰值内存证明。

Godot文档支持按元素分派[WorkerThreadPool组任务](https://docs.godotengine.org/en/stable/classes/class_workerthreadpool.html)，并要求等待任务完成。不同线程不能同时使用同一AStar对象；本试验按job独占、屏障后交接，未访问活动场景树。依据见[线程安全说明](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html)。

每图都是9216点。Worker减少了组经过时间，但单job比主线程串行时更慢；本轮没有证明其底层原因，不归因于GDScript全局锁、分配器或混合核心调度。主线程几何准备仍占约20～27ms，不能把整张冷图原有43.943ms视作全部可并行工作，也不能将嵌套job时间与组时间相加。

提前形成实际扫描所需图后，后续入口检查直接借用驻留几何，顺带消除原一次入口重复投影。B2/B3/C1/C2各减少16次门候选和16次预约候选查询；其余原查询次数、完整业务、事件、随机流、最终二进制与非计时sample完全一致。串行控制也包含这项改动，因此Worker与串行的对比不会将重复投影省略全部归给并行。

## 运行环境核对

测量完成后的主机只读快照确认Intel Core Ultra 5 125H、14核18逻辑处理器，没有残留Godot进程。约2.151秒的进程CPU增量采样记录到ChatGPT、Codex和Docker后台活动；这是累计CPU时间，不能与单核经过时间直接相加。采样不与七次测量同步，不足以证明其解释了本轮时间波动。处理器频率字段也只是异步快照，不能据此还原每个模拟步的运行核心或频率。

普通沙箱中的`Get-Process`只看到了采集器自己的进程，不能用它单独证明主机无其他Godot实例。本批先等待每个实际会话退出，再核对七份引擎进程起止凭据，区间均不重叠；另行主机只读核对未改变电源、亲和性、优先级或任何后台进程。

## 验证、保留与未完成

七个完整引擎窗口、560步全部保持160人资格，原业务、事件、随机流、最终状态和非计时sample通过隔离核对。五份准备工程均保留身份及变化源码，其中旧两端点串行工程未运行。基线485份来源、145份测试与当前工作区逐项一致；两个有效Worker窗口均有真实4线程执行及完整屏障，两个串行控制执行相同四份图工作。

B2的引擎与完整语义核对通过，初版计数驱动未允许省掉的16次门/预约查询而退出1。失败检查与修正后的独立检查同时保留，没有重新测量来替换该结果。B1未触发分组的结果同样保留并单列，不能作为Worker成功执行证据。

原选SPACE-46、SPACE-51、SPACE-55、STAFF-57、STAFF-61，覆盖组权限、来源/预算/恢复、成本报价、第三人实际离开唤醒及全部入口预算。因GP完整收益未建立且方案未采纳，没有追加这些独立功能回归，也没有公共或运营性能窗口；不宣称这些用例本轮通过。未变生产继续引用[既有第三人退出与负缓存证据](2026-10-23-occupied-seat-dependencies.md)。
