# 区域派生、导航主体与环境查询成本修复

基线为 `dev` 的 `87af6a6ad04a8e1eb2b84e8d237af0a9d89d5703`。修复覆盖区域派生生命周期、相同主体的候选查询准备、单位身体冷图墙检测，以及环境来源求交。合法候选、业务规则、160人负载与固定0.1秒阶段保持。正式性能验收继续暂停。

## 问题、处理及根因约束

| 问题 | 实际成本与根因 | 采用的修复及边界 |
| --- | --- | --- |
| 不同目标重复准备同一人物起点 | 完整候选查询各自读取起点、计算整数落点前缀、检查分数起点到落点的通行，并序列化同一身体包络；这些前提属于相同封闭只读批次 | 起点和前缀证明归原有 `point_journeys` 只读批次内的单人主体。不同目标仍分别查询完整路线，返回值仍独立复制。独立调用、新批次、不同世界不共享；同行组和非空阵型保留原完整键及原检查 |
| 无关几何修订重建全部公共区域 | 全局版本仅能说明某处变化，原 `_ensure` 却重复执行每层格点遍历、连通分组、排序与区域哈希 | 当前世界每层只保存最新完整区域依据及派生结果。修订时比较真实楼板/阻挡、房间形状、设施实际占地/患者位与连接占地，只有改变层重建。未变区域对象、成员与顺序复用；换世界、删层和失去楼板释放对应结果 |
| 单位身体冷图重复通用墙矩形计算 | 整数1×1节点内部没有整数墙线，相邻四向边只跨一个方向的一条墙线，却仍走通用矩形构造和墙桶分派 | 在原净高、身体、楼板、设施、预约和成员检查之后，整数单位节点不再分派内部墙检测；四邻边直接选择原对应墙桶。真实门处理仍调用原谓词。大身体、分数扫掠、非相邻边及非索引查询保留完整回退 |
| 普通环境观察反复遍历大覆盖区 | 每人调用已经就绪的来源准备；墙/污渍计数在来源很少时仍遍历全部覆盖格点 | 就绪标志只在原只读环境批次内消费；布尔存在性、显式距离/键仲裁及纯计数使用较小字典求交。解释性污渍来源仍保留原覆盖顺序；实际采样频率、公式与来源不变 |

重复执行的共同原因是把上层已经证明的稳定前提留在逐候选消费者里，同时把全局变更身份当成所有派生结果都已改变。修复将结果放回原所有者及实际有效边界，避免增加跨提交的动态许可缓存。专项回归同时检查完整结果和执行次数，后续不能仅凭相同终态掩盖准备次数重新增加。

区域连通依据不拥有门、净高、操作/维修位、故障和当前权限。上述条件仍使等待与入口几何按原边界失效，区域命中不能授予通行许可。单人来源证明也不能跨实际移动、身体/朝向变化或事实提交保留；这些操作必须结束原只读批次。两份现行规格已同步记录边界。

没有新增路径搜索算法。路径仍由 Godot AStar2D/AStar3D 求解，原生装配和标准库排序保持。单位墙检测只消除既有整数网格上的空计算，不替代引擎寻路或改变通行规则。
