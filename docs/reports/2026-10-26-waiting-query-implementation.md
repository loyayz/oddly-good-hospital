# 等候点行程复用与等待结果定向失效

实现基线为dev `41ecbac`。等候点行程复用、等待结果反向依赖及对应规格已修改。脚本解析、静态检查、构建、功能回归和性能采集均未执行，尚无正确性或性能通过结论。正式性能验收保持未通过，没有新的前后指标。

## 等候点行程

`HospitalNavigation._waiting_cost_basis()`在原人物只读查询内持有真实起点分数段，或单电梯的完整到站报价。每个安全候选通过`waiting_travel_ticks()`计算剩余层内结构行程，调用原`_floor_route()`、Godot图和距离场。此路径不反复展开相同交通前缀，也不生成另一套通路算法。

快路径边界为同层最多一个连接，或跨层恰好一部电梯、已获得唯一目标层落点的完整报价。到站时间必须与同次原完整报价一致；未知估计、来源证明缺失或复杂连接继续完整报价。不同落点依据不能沿用旧前缀。已就绪结构距离场仍由原导航缓存借用，继续执行原12次查询预热、容量计费与驱逐。

完整入口集合、lower/y/x顺序、严格更优更新、预算、分数起点通行证明、各段取整和溢出处理保持。每个实际候选仍核验当前安全站位。只读查询关闭后释放前缀；具体使用权、实际路径及到场复核仍由原任务和移动所有者承担。

## 等待结果

`waiting_dependencies.gd`持有可重建的资源反向索引和空间观察索引，使用现有`BodyIndex/Boost.Geometry`，不增加业务队列。首次失败登记完整依赖；后续未变化等待者只检查请求与脏状态，省去逐人重新装配完整签名。完整签名接口保留用于计算依据与诊断对照。

设施依赖包括实际使用者、预约、适配、故障、整备及访客让座资格；区域依赖包含真实成员，可观察修复、新增或移除带来的机会。队列、本人和有序成员身体、关系、环境、连接及实际观察过的楼层结构来源分别持有共享证明。

实际移动和显式身体同步按旧、新楼层及身体矩形通知等待拥有者。预约更新与释放按旧、新完整regions通知；门预约的范围/跨度变化同时失效依赖该楼层的等待者。观察索引分别保存原矩形，不把矩形之间空隙扩为依赖。非排队第三人的进入、离开和换层参与同一失效过程。

尚未提供细粒度提交通知的字段，在患者候诊、访客及员工生活各自的同步调度观察内，按不同资源共享一次当前值核对，变化后只标记订阅者。这部分仍有观察成本，不表述为全部字段已纯事件化。显式变化重新开启观察；独立原始计算调用每次刷新当前来源，保留没有生产调度通知的计算入口。

多次变化合并为等待者的一个脏状态，仍在原调度阶段、原次序重查，不在通知回调中立即抢座。再次失败时替换订阅，意图结束时清理；换世界或替换完整事实时重建。运行时索引、订阅与观察均不进入`WorldState.freeze()`。叫号、取消、期限、真实移动及取位安全边界保持。
