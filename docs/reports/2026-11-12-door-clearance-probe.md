## Fixed real-corpus API microbenchmark

Before timing, the plan was fixed to eight captured calls, six pairs each, AB/BA/AB/BA/AB/BA order, one fresh-context cold call and 2000 warm calls per arm. There were 48 pairs and 192000 total warm calls; no extra pairs were added after looking at results. A is the production `HospitalSpace`, B a subclass overriding only `movement_doors` with one extra same-instance guard inside the member loop. Both arms execute the same whole API and the same per-return equality check. The production checkout remains unchanged.

The candidate skips a member only when `is_same(world.facts.actors[id], actor)`, because the initial reach already contains that dictionary instance's clearance. It does not match by actor ID, skip different instances or group members, change live door/reservation queries, or reorder results. The corpus retains the real world-actor alias, not a detached copy.

Warm batches total A 899721 us and B 804785 us. B is faster in 43/48 pairs; median paired reduction is 11.49%, aggregate reduction 10.55%, approximately 0.99 us per call. This is a local result on eight single-actor calls returning no candidate doors, not a full-step gain or a claim about all 9818 observed calls. Independent cold-cache calls total A 765138 us and B 645261 us, but include cache preparation and are not the principal benefit claim. The single process exited 0 after 16.879 s.

Every paired returned array, captured body cache, query counters, navigation source records (excluding weak world handle), retained floor door data/charge/use, navigation counters/keys, and reservation records (excluding runtime index object) compares equal. The complete World stays unchanged. Runtime index objects are not compared bytewise. These checks do not establish nonempty-door behavior, door ownership/lifecycle, multi-member convoy or same-ID/different-instance proxy boundaries; those are required before retaining a production edit.
