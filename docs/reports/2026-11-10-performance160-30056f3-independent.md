# Windows 160 人独立性能验证：30056f3

`30056f3b433939f315b5b590978ebc80453de0f9` 的最大实测瓶颈仍是移动与空间区间：三次为 **61.522、59.507、60.883ms/步，占完整模拟步的 69.06%、69.37%、69.40%**。这是区间经过时间，尚未把当前版本内部各函数拆开计时。本轮没有实施优化，不能据此宣称任何提速。

## 版本、输入与范围

游戏源码来自 GitHub `dot/next-stage-20261107` 同步后的 `30056f3`。独立 clone 中生产游戏、内容与项目配置没有修改；仅覆盖 `plain_v4.gd`、`campaign160.py` 两个测量工具，来源为 `6cba75203d014f64258e525e1aaa03a06b907fd4`。根阶段观测使用该游戏提交已有的 `step_profile.gd`，不开启嵌套服务替换。源码身份和工具原文均随证据保留。

固定输入 SHA256：`ce56591c43fe1704abf76348dd5e67b0eae2a599143c03e045a780439a1bc15c`。初始实际 120 患者、32 员工、8 访客，共 160 人；64 房间、1340 设施，其中 1200 个装饰物、24 张护理床、8 个导诊台，布局为四层。正常到院、离院、访客、维修和需求继续运行，不固定人口，不跳过业务。

每个新进程先准备观察层 1F 的静态缓存，再实际执行 1000 个前缀步与 2000 个采样步，步长 0.1 秒。三次串行执行，没有额外 plain 轮、函数诊断轮或并行基准。Windows 应用主线程选核，环境采样 4 个任务，`OMP_NUM_THREADS=1`。操作系统缓存与正常桌面应用保留，不宣称独占机器。

主机为 Intel Core Ultra 5 125H（14 核、18 逻辑处理器），Windows 11 build 26300，平衡电源计划。引擎为 Godot 4.7.2 官方 Windows 控制台版，SHA256 `c8f0a6bc45a19b33541501e57f6f7cd972ab18453743266339d495cbbe846643`；原生主 DLL SHA256 `9238c293354b2d19928007ce4c49f03c96c4a9b50056239aa0d8b4c1d48dd5b1`。从 `e7146a3` 到 `30056f3` 的原生源码、内容和项目配置未变，沿用同一运行时库与导入资源。

## 实际调用链与实现成本

1. **任务与临床交接。** [simulation.gd](../../game/sim/simulation.gd) 的 `step_nonblocking` 先执行楼层导诊、候诊和其他任务调度，再调用 [clinical_runtime.gd](../../game/clinic/clinical_runtime.gd) 的 `dispatch`，遍历当前就诊与票据，准备导诊、选择站点和员工、检查真实到场，再发布或继续移动。票据与资源会在本步内发生真实交接，跨步保留调度结论必须重新核对其事实依据。
2. **移动与回接。** [hospital_movement.gd](../../game/building/hospital_movement.gd) 的 `advance` 同步人物/队列、处理预约和层间交通、预算派路，然后遍历现有移动。单人经 `_local_resume/_local_collision → _local_try_return → 原路线候选 → _local_return_endpoint_clear/_local_return → _local_path_clear` 检查完整连接，最后由实际 `_move_step` 再检查当前扫掠。完整连接预检查是当前选点条件，真实迈步检查负责现场物理安全；本轮保持两者语义。
3. **可确认的重复计算机制，耗时占比尚未测量。** 终点已经在 `_local_return_endpoint_clear` 检查结构几何，紧接的 `_local_return` 再检查相同位置；L 形两段通过静态扫掠后，`_local_path_clear` 又检查同样的段。[hospital_space.gd](../../game/building/hospital_space.gd) 的 `_actor_rect` 每个角色仅保留最后一个朝向，终点多朝向与临时折角探测会交替覆盖这个槽位。代码能确认这些重复点，尚不能把它们各自换算成当前版本可节省的毫秒数。
4. **新床岗位检查需要单独计量。** `0b73f1c` 新增 `_bed_goal_regions/_bed_local_path_blocker`，在原目标和临时停点区分空床边通行与使用预约，构造末段/拐点身体包络，再查局部预约索引。它们为已确认的床岗位规则服务；即使不是去床上工作，当前移动也会经过相应入口。应先统计有效软床预约、空候选和几何构造次数，再判断空集快路径或调用范围能否减少成本，不能据本轮历史差值认定该提交造成了多少回退。
5. **候诊还存在整区域候选排序。** [public_areas.gd](../../game/life/public_areas.gd) 的 `select` 已在 `30056f3` 使用设施类型索引，不能再将旧全设施枚举当作当前问题。但 `_entry_order` 失去最近两种基准的缓存命中时，仍会通过 `_ordered_entry_cells` 为区域所有格生成并排序键；区域覆盖整层时便是运行时整区枚举。原生排序提高执行效率，不能消除这项算法工作。本轮根计时没有记录该分支调用数，不能把候诊的 6.4–6.7ms 全部归给它。静态距离场路径已改为只借用加载时准备的场，缓存未命中走点到点查询，不应将其误报为运行时新建全层距离场。

旧 `e7146a3` 的函数级局部回接耗时不适用于当前版本的函数分摊。本轮只有根阶段计时；历史运行也不是本轮的相邻对照，不能据两批耗时差宣称新提交加速或回退。此前同步 memo 候选的完整步三组结果方向不一致，已撤回；发现重复检查并不自动证明再加一层缓存会更快。

## 保持玩法的改进方向

- 先定位当前移动区间内部 `_local_try_return`、新增床岗位检查、实际 `_move_step` 和包络构造的占比，再选择改动。保持最近可达原路线点、完整连接条件、真实到达后推进游标与每步现场安全。
- 对同一同步调用刚证明过的终点和段，直接消费该证明，减少重复几何计算与临时数组/字典构造。身体、几何、预约或已接受扫掠发生变化后重新观察，不能保留未来通行许可。
- 将身体身份与假想朝向的几何复用分清，保留精确朝向和有界缓存，验证体型绑定、姿态变化、恢复及真实转向，避免临时探测反复挤掉可复用包络。收益尚待同条件对照。
- 床岗位入口优先验证可复用的当前楼层预约索引是否存在相关候选，减少没有相关预约时的投影构造；保留床体通行和床边使用权的区别。
- 对候诊整区排序，先取得命中率、枚举格数和实际消费候选数；改进应使用加载期静态索引与运行时局部候选，保留合法选择范围，不以最近 N 人/格或减少负载换取速度。

以上为实现候选，没有实施或验证其收益。没有修改回接玩法、通行优先级、让行承诺、人口、模拟步长或存档语义。
