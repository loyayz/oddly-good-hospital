# Windows 160 人移动耗时归因

游戏基线仍为 `e7146a3`，诊断副本从 `5d873df` 创建。相同初始 160 人输入、1000 前缀步、2000 采样步、应用主线程选核、4 个环境任务，串行三次。源码内同脚本包装选定函数，原函数体逐字逆变换核验一致；不替换服务脚本，不改变原生线程采样资格。计时只记录驱动主线程。

三次完整诊断步平均为 94.975、97.930、104.860ms。所有终态与未插桩基线完整二进制一致，调用数三次相同，计时栈错误为零。包装器有开销，下面用于同批次归因，不能与 plain 拼接计算加速。

| 函数 | 每 2000 步调用数 | 含子调用 ms/步，三次 | 选定函数之外的自身区间 ms/步，三次 |
| --- | ---: | --- | --- |
| movement.advance | 2000 | 66.125 / 67.709 / 72.363 | 3.050 / 3.118 / 3.551 |
| _local_try_return | 66615 | 38.939 / 39.790 / 41.024 | 4.333 / 4.428 / 4.632 |
| _local_return | 283802 | 22.954 / 23.434 / 24.122 | 9.816 / 10.006 / 10.148 |
| _local_path_clear | 260252 | 16.910 / 17.246 / 18.156 | 9.921 / 10.125 / 10.636 |
| _move_step | 209095 | 16.005 / 16.514 / 18.647 | 12.565 / 12.942 / 14.651 |
| _local_return_endpoint_clear | 499128 | 11.738 / 12.017 / 12.372 | 7.653 / 7.848 / 8.102 |
| _movement_contacts | 615039 | 7.565 / 7.750 / 8.329 | 同左 |

含子调用列相互嵌套，不能求和。“自身区间”仍包含未选中的后代、等待和观测开销，不是纯 CPU 指令采样。

实际调用链是 `HospitalSimulation.step → space.advance → movement.advance → _local_resume/_local_collision → _local_try_return → 原路线候选迭代 → 终点与固定正交连接检查 → _local_path_clear → 身体/已接受扫掠/预约`。当前大头是局部连接的重复证明，而不是每步预算派路。约 33 次重接尝试/步，平均每次检查 4.26 个连接、7.49 个终点；同一目标在终点函数、连接函数及段检查中重复查询静态几何。同一同步尝试内身体和预约未变，也重复查询邻域候选。身体矩形调用含假想朝向，不能直接用真实角色上一次矩形替换全部调用。

最小优化候选是一次同步尝试内复用精确坐标的静态证明及完整邻域候选，下一次实际移动或另一个角色必须使用新观察。窄相扫掠、真实运动、候选顺序、合法负载及现行局部连接集合保持原语义。这里尚未记录优化收益。

功能基线另有一项历史冲突：SPACE-10 的 `nearest_return_around_furniture_and_entrance` 在未修改代码及纯缓存候选上均无法到达，两份完整用例详情相同。旧阶段规格要求双轴外侧折线；当前 `docs/design/01-simulation.md` 只允许直连、两种直角与同轴侧向连接，旧用例依赖已撤去的链接。此项不能声称通过，也不能以增加旧链接作为性能优化。后续保留失败证据，按现行规则选择真实到达和业务交接回归。

本报告不包含实际显示帧、GPU 或并行加速结论。Windows 原生主线程选核三次均返回 applied=true、performance_cores、fc03、错误 0。完整原始数据、插桩身份和失败基线见 [证据清单](evidence/2026-11-10-performance160-movement/manifest.json)。
