# 160 人混合场景的身体、导航与尾延迟诊断

完整混合场景的 CPU 延迟仍未达标。组合优化后的 B03 三轮 plain P95 为 **90.625～98.014 ms**，项目目标为 10 ms；P99 为 109.410～120.599 ms、最大值为 288.649～300.453 ms，对应目标为 15 ms、30 ms。速度比均达到1×目标，业务覆盖仍为26/31项，三轮均`qualified=false`。指标来自 [balance.json](../data/balance.json)；完整窗口及业务结果见[临床流程性能报告](2026-11-12-clinical-flow-performance.md)。

下述函数诊断使用 `7b2a735` 的 B02 冻结生产源、`89d4e1db…` 原生桥和 mixed `75f5e1d9…` 完整输入。1000 个真实前缀步后，连续采样 6000 步，tick 633→7633；app 主线程策略、4 个环境任务、`OMP_NUM_THREADS=1`。原 v3 压力行继续保留，mixed 是独立负载行。完整诊断没有混入后续 `a4766fb` 门禁重排或 `9368fc6` 身体、导航优化；后者的 B03 plain 三轮另列于下文。

## 已实施的最小优化与局部证据

代码核对确认了两类无须改变玩法的重复工作，[`9368fc6`](https://github.com/loyayz/oddly-good-hospital/commit/9368fc6) 已修复：

- `HospitalSpace.walking_speed` 在一次速度查询中对同一身体调用 `content.actor_body` 两次。现在普通个体借用已有 `body` 缓存读取一次；同行复合身体仍从原内容入口读取一次。身体、速度公式和服务所有权不变。曾尝试的额外公共 helper 拖慢了独立 `body()` 查询，最终恢复了原 `body()` 方法。
- `NavigationCache._source_record` 对同一 world/floor 反复拼接查找文本并构造缺省字典。现在只复用最近一次查找文本，仍校验原 weak owner、几何 revision，并执行原使用计数、计费和淘汰。投影继承中，封存的设施容器未变时复用已验证的静态身份；实际 footprint 变化仍走原重算路径，动态占用继续捕获。

局部 probe 使用真实完整终态的所有角色和所有者，结果及 World/RNG 只读检查通过。每种操作分别计时三对，计数与计时分开，不减少查询数或合法候选。

| 局部操作 | 完整输入范围 | 三对合计耗时变化 |
| --- | --- | ---: |
| `walking_speed` | v3：179 个 Actor，每对 179000 次 | 减少 78.21% |
| `walking_speed` | mixed：184 个 Actor，每对 184000 次 | 减少 77.87% |
| `_source_record` | 同 world、同 floor，每对 10000 次 | 减少 32.29% |
| `_source_record` | 同 world、四个 floor，每对 40000 次 | 减少 3.14% |
| `_source_record` | 两个完整 world 交替、同 floor，每对 20000 次 | 增加 1.40% |
| `inherit_projection` | 20 个完整投影 world，每个 4 层 | 减少 57.20% |

普通个体速度的独立计数中，v3 每个完整查询遍历的内容身体读取由 358 次变为冷 8 次、暖 0 次；mixed 由 368 次变为冷 9 次、暖 0 次。独立 `body()` 方法恢复原文后，各对耗时有上下波动，按与原方法相当记录，不额外宣称收益。投影继承的静态身份 hash 调用在独立计数中由 80 次降为 0，完整静态/动态语义摘要、预算和驻留计费相同。

选定回归 `PERF-08`、`SPACE-53/57/60/61` 通过。局部收益不是整体 CPU 收益；双 owner 交替查询的轻微变慢也完整保留。`9368fc6` 的完整 mixed 窗口现已测量三次，原 v3 本批只验证0＋2入口，原压力行继续保留。进一步优化先核对高调用几何、索引和派工路径中可证明的同步重复准备，不改变身体扫掠、候选顺序、通行所有权、导航预算或合法负载。
