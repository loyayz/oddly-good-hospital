# 队列值快照共享试验：不采纳

同一决策观察内共享队列记录的试验不采纳。GP共享视图命中1016次、构建63次，原25943条逐观察装配减少为1410条共享新建记录，但连续plain对照平均86.587→86.483→85.958ms，没有稳定整步收益。公共平均111.417ms，高于两侧95.626和92.777ms，P99也退化。生产和测试源码已经恢复到dev `5712c6f7fbc7e222e2a483bc376201352fd5ffc2`，没有保留新缓存或失效责任。

## 试验机制与实际准备量

原等待签名仍按每个观察者装配同区排队者的身体、姿态、朝向与目标。试验仅在当前`_decision_view`中保留一份完整队列快照和涉及人物的事实快照，使用[Godot容器值比较](https://docs.godotengine.org/en/stable/classes/class_dictionary.html#class-dictionary-operator-eq-dictionary)确认当前事实未变后共享记录；不使用哈希代替值证明。

记录保持原次序，消费时排除本意图的全部同身份记录；未到场及不在等待阶段的记录仍排除。有序同行组与缺失成员的观察范围保留。缓存自有的行和成员数组分别使用[Array只读接口](https://docs.godotengine.org/en/stable/classes/class_array.html#class-array-method-make-read-only)保护，未冻结原世界事实；世界、tick或原决策观察失效后释放。实际移动、预约和使用没有在线程或缓存中提交。

## 为什么高命中仍没有收益

条件内联计时先计算返回表达式，再停止时钟。只在选定tick记录函数时间，root仍覆盖完整GP80。包含区间相互嵌套，不相加；签名统计跨患者、访客等调用者，不全部属于root候诊。

| 选步与函数 | A | B |
| --- | ---: | ---: |
| GP867完整等待签名 / 18次 | 12.286ms | 9.925ms |
| GP867队列段 / 18次 | 5.449ms | 4.212ms |
| GP867共享视图获取 / 18次 | 不适用 | 3.750ms |
| GP867访客dispatch / 1次 | 8.620ms | 7.849ms |
| GP851队列段 / 18次 | 0.724ms | 2.352ms |
| GP851共享视图获取 / 7次 | 不适用 | 2.123ms |

普通867的队列段只净少约1.237ms；共享视图获取包含当前人物收集、值比较、必要的快照重建及计数，仍支付3.750ms。不能把它全部称为原生比较CPU，也不能从父区间扣除它还原无观察耗时。851的构建成本反而超过原队列段。

准备量从反复创建记录转移到了快照和值证明。它没有消除实时事实检查，而且新增准备在少量消费者、刚发生变化或首次构建时不能摊薄。六项规则验证和很高的命中率都不足以证明整步收益，因此撤回；普通867局部改善也不用于覆盖公共整步退化。

诊断全窗均值96.895→90.029ms，与plain也有明显差异；该差值混有运行波动和观察开销，不据此宣称低扰动或精确节省。原始数据全部保留。
