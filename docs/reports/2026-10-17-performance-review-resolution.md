# 性能设计审查处理结果

审查来源：[性能设计静态审查](https://chatgpt.com/s/t_6ad33af277548191bc6f8860bc06e8a0)。审查基线为 `d74d795fcf5c8c85073741a8efff6a260a514957`，处理分支为 `dev`。本文按原审查顺序记录独立核对、改动、验证和剩余事项。

业务依据为 `docs/design/07-clinical-team.md`、`docs/design/11-growth-arrivals-recruitment.md` §1.1.1～§1.1.2、§4，以及 `docs/specs/26-10/2026-10-16-performance-validation.md`。原实现与旧求解结果不作为正确答案。精确容量 C、独立结构规模 K、合法候选集合、岗位互异、日计划抽签和当前步待结果规则继续适用。

容量输入容器冲突、冻结承诺扣减、必要检查遗漏、锁持时间与天赋公式问题已修复；护理原始模型复用、原生批量运算、临床和空间查询优化已实施。运输时钟仍可能使相关 C 参考需求重新生成，准备输入尚未完成全部三层拆分。功能与数学检查通过不代表性能指标通过，本文不提供优化后毫秒数或正式性能达标结论。

**有效，已修复。** `_reference_classes()` 的输出包含 `resource_ids`、`model_key` 和 `references`，不能再交给允许 `clear()` 的临床查询缓存。`HospitalArrivalService._existing_workload()` 使用独立 `reference_query` 补算旧病例，保留原模型身份和已有参考输出，不以缺省键掩盖错误。

`GROW-42` 从合法旧候诊状态开始，关闭其病种并保留另一开放病种，验证补算不改变模型输出、旧需求仍存在、容量完整返回，医院事实与随机流保持只读。

## 4. P0：连接设施触发粗粒度失效

**有效，已缩小失效范围，尚未全部完成。** `HospitalTransit.reference_conditions()` 只投影几何、故障／紧急状态、当前运输阶段和已知余量等报价输入，排除 `use_receipts`、历史票据、无关耐久记录。捕获与参考 basis 共用该投影。

K 增加独立结构输入缓存：保留资源身份、结构选择、接待条件、岗位和床位关系，不把 C 的时间系数与概率作为 K 的求解依据。同一结构不因纯数值变化重新求 K。

**剩余问题：** 当前连接设施的 `phase`、`remaining_ticks`、`floor_id` 等确实参与运输预计，仍保留在 C 的参考依据内；变化后仍可能重建整班临床参考病例及 C 原生模型。不能为保住缓存而删除这些真实依赖。下一步需要将连接几何、可行性、当前运输前缀与 PlanScore 的依赖拆开，并覆盖新增候选，而不只记录上次最优解使用的资源。

`GROW-47` 实际推进合法乘梯到登舱，验证收据和普通耐久变化不改参考条件，而实际推进产生的已知余量变化仍被保留。该用例没有证明运行中的 C 已实现局部系数更新，也没有测量三班重建频率。

## 5. P0：护理 SCIP 模型重建

**有效，原始模型与数值更新已分离。** `Model` 保留 `PackingProgram`、流变量、岗位变量、资源约束及其映射。相同模型的预算更新同时修改精确资源 RHS、流上界、派生 RHS 和互斥 Big-M 系数，避免只改预算而保留过小上界。预算恢复、零预算恢复及最优岗位切换仍重新证明最优，未冻结旧岗位选择。

SCIP 的变换状态属于旧问题数值，不能当作已验证的可复用搜索成果。每次精确取值并独立检查原约束后释放变换状态，保留原始变量与约束；异常路径也释放。此次实现不宣称保留搜索树、RECTLU 分解或 MIP 最优性证明。

### 5.1 回归暴露的原生生命周期问题

大型双术组用例曾在释放多个长期模型时发生原生访问异常。符号化堆栈定位到 SCIP 10.1 的 `RECTLUfreeFactorization()`／`QSnum_factor_clear()`，对应 RECTLU 源码为各变换分解初始化、释放进程全局 GMP 临时量。多个变换分解长期并存或重叠调用不满足这条生命周期限制。

修复包括：

- SCIP 相关原生入口及模型析构使用进程互斥，避免相关调用交叠；标量 GMP、批量汇总和 CPU 计时不使用这把锁。
- 原始模型持续存在，变换分解在每次求解调用返回前释放；成功和异常路径均清理。
- 精确模式继续在创建问题前启用，保留精确模式安全的默认插件，不通过更换浮点求解或忽略异常规避问题。

这会限制同进程 SCIP 调用的并行度。是否需要隔离进程或修复上游 RECTLU 生命周期，须结合后续并发收益测量，不能将当前模型复用表述成无限并行。

## 6. P1：准备请求与输入捕获

**有效，派发顺序与繁忙时的重复捕获已修复，三层输入拆分尚未完成。** `_select_request()` 先 `poll(false)` 只接收完成值，再选择最新或封闭输入；旧 latest 不会在封闭输入检查之前抢先派发。保留一项活动工作与一项可替换后继请求。

当活动任务与后继请求都存在时，`prepare_next_day()` 跳过本次大输入捕获；下一个空位或最终日界重新读取原所有者。最终日界截止点、未就绪续接、错误重试、保存及随机提交规则保持不变。捕获增加次数、耗时、复用、被替换请求等计数，worker 增加独立 CPU 时间。

**剩余问题：** 结构、参考需求、当前余量尚未完全成为可独立更新的三层只读投影；工作完成较快时仍可能每步捕获和比较。未统计捕获字节量、分类失效原因、过时任务 CPU 及最终差异量。未增加新的线程框架或未经测量的细粒度并行。

## 9. P1：导航查询前的成本与缓存

**有效，主要重复查询已消除。** 普通模拟步结束仍增长世界 revision，但不使楼层几何代次变化。几何事实替换、明确几何触碰、楼板完工及预约区域变更按原所有者使相关源失效；保守 `touch()` 默认仍失效，避免任意外部事实修改静默复用旧几何。

同一楼层源共享设施 `BodyIndex`，只读候选查询不再各自扫描全院设施建索引。动态 actor 查询和距离估计与静态图分开计费、优先回收；离院或已删除 actor 的查询随完整边界清理，取消按 actor 反复序列化 occupancy 的计费方式。后台仍独占自身可变 AStar 对象。

**剩余问题：** 尚非所有命令都具备细分到楼层、几何、适配、权限的独立版本；保守触碰仍可能多刷新。长时间换批和频繁适配的内存峰值、图冷建数尚未测量，计费额度只是回收估计，不能当作实际 Release 内存。

## 14. 后续分析入口

1. **C 的运输依赖与数值更新。** 先区分几何可行性、连接设施故障／紧急规则、当前运输前缀、路线竞争与 PlanScore；给实际依赖及新增候选建立证据，避免普通乘梯导致整班参考病例和原生 C 模型重建。K 的独立结构缓存不等于 C 已增量化。
2. **准备输入的三层拆分。** 结构／参考需求／原所有者余量分别拥有可重建身份与更新边界；封闭日界仍读取最后合法输入。优先度和繁忙合并已有基础，不以提前截止或旧值交付消除等待。
3. **剩余候选与数值成本。** 观察术台×术组×会诊展开、剩余标量桥接、SCIP 原始模型更新与精确搜索、LP 证书和 K 前缀组合各自成本，再选择共享、批量化或证明复用。SCIP 调用当前串行，线程数本身不能消除该限制。
4. **普通步与资源。** 观察仍在进行的 `equipment_use()` 扫描、保守几何触碰、多消费者缓存命中及长期演员换批，决定是否补原所有者反向索引与楼层细分代次。
5. **正式测量。** 在修复相关用例通过后，建立真实导出 Release 的活动会话入口和持续 160 人四层负载，保留访客、住院、手术、运输与装修活动；区分捕获／建模／原生转换／精确求解／提交／等待，记录实际帧、速度和资源。运行中重建与日界等待不改标预热，不用轻负载补样稀释超标。
