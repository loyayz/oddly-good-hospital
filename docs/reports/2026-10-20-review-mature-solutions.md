## 成熟方案替换与保留理由

| 责任 | 最终实现 | 处理依据 |
| --- | --- | --- |
| 空间宽阶段 | Boost.Geometry R-tree | 删除自写分桶；同一适配供人物、已接受扫掠、设施、门、预约使用；精确判断仍由各自规则拥有 |
| 跨层最短路 | Boost.Graph Dijkstra | 删除自写Dijkstra及松弛；按需回调生成边；完整int64和ID平局由薄适配保持，不改成浮点最短路 |
| 移动请求调度 | `std::priority_queue` | 删除自写堆及每步排序，不改变保存序号和公平性 |
| 个人床及接待匹配 | Boost.Graph maximum cardinality matching | 删除两套增广路。个人床仍先最大覆盖，再保员工优先覆盖集，再逐员工按耗时和床ID择优；不是最小总耗时 |
| 重复端点距离场 | Boost.Graph breadth_first_search | 删除两处脚本BFS，借用同一FloorNavigation的四位出边掩码；保留12次命中门槛、有向边、预约及UP/LEFT/RIGHT/DOWN顺序，失败回AStar2D；每图新增9216字节计入原缓存预算 |
| 建造连通及孔洞检查 | Boost.Graph connected_components | 删除网格BFS；四邻、96×96、外扩98×98、无孔洞及内接矩形规则不变 |
| 容量图纯可达性 | Boost.Graph depth_first_visit | 两处DFS借用原children迭代器，不复制邻接图；结构根全部完成后遍历，概率模型仅从正概率根收集资源 |
| JSON输入／输出 | Boost.JSON SAX／RapidJSON Writer | 删除手写词法和递归解析。RapidJSON Reader即使NumbersAsStrings也提前拒绝合法`0e999`；Boost的number_precision::none验证语法并保留数字片段，再复用标准整数解析及既有UCRT小数解码 |
| ZIP／CRC | minizip-ng 4.2.2／zlib 1.3.2 | 删除手写ZIP结构编解码、CRC表及解压包装；32KiB流、取消、预算、SHA、受限条目和严格布局策略保留 |
| 纹理页尺寸 | Godot nearest_po2 | 删除乘二循环；正数输入范围和输出尺寸保持 |

没有采用的具体实现选项：

1. **整套直接改成PhysicsServer2D／Box2D固定形状cast。** 当前精确边界同时包含两个人物在同一模拟边界内的移动、转向引起的包络变化、卧姿离位和严格“仅接触不相交”。`body_test_motion`及固定点云shape cast没有接收两个起止尺寸变化包络的同等接口；将其直接当成最终权威会改变通行结果。宽阶段已经换成熟空间树，剩余`BodySweep`只负责四个严格线性不等式的交集，成员权限继续独立判断。没有再写一套物理引擎。
2. **为避免所有数组而重写楼层A*。** Godot AStar2D公开接口返回原生ID路径；没有公开仅返回精确成本的查询。保留这份引擎原生ID数组，消除脚本逐格数组和字典路径。不能把计数器归零描述为A*不再创建任何数组。
3. **预先算全部同层锚点组合或每次改成全楼层多目标距离场。** 当前采用AStar2D点到点搜索，达到原12次端点命中门槛才由Boost BFS建立距离场，共用同一图的边。预先计算全部组合会计算未访问连接，每次全层搜索在少量目标时会扩大工作量；未采用取消摊销门槛的做法。跨层Dijkstra已经保留惰性访问，拓扑声明也缓存；本轮不以预计算扩大工作量或内存预算。
4. **把可让行员工资格永久缓存。** 资格依赖真实工作、安全交接、当前任务与预约，跨步缓存会再造需要逐写入点维护的事实。局部空间候选和单次决策职责集合已消除本次评审指出的重复全局遍历，后续真实状态仍即时读取。
5. **采用minizip默认宽松读取行为。** 备份协议要求连续布局、严格文件尾、ZIP64边界、CRC、压缩流终点、白名单及失败不发布。保留固定源码上的小型策略适配，通用ZIP和压缩仍由库实现。
6. **整个结构见证替换成普通图遍历。** AND／OR、资源互斥、护士归属及病床覆盖是医院证明规则；普通DFS无法代替它。纯可达性与匹配已分别交给Boost，完整精确优化仍为SCIP／SoPlex／GMP；证书失败回到完整求解，不删合法分支。
7. **仅因绑定或着色器是项目代码而全部重写。** GDExtension适配实际调用Godot的Variant、容器和析构；没有实现另一套内存或引用计数。独立骨架批绘制继续使用Skeleton3D、Skin、MultiMesh和ImageTexture；普通MultiMesh没有逐实例独立Skeleton输入。兼容输入绕行限定引擎哈希和OpenGL，不将内部packed布局换成未经验证的公开API重编码。上述理由说明必要适配，不证明其渲染性能已经通过。
