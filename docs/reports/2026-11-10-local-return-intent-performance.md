# 回接意图简化：160 人对照与验收边界

`30056f3` 上的回接意图简化已实现，最终测量提交为 `f8d8f8050a716be5e7427fb2c89e6296d1db8450`。相同初始 160 人、三次串行验证中，完整模拟步合并均值由 **87.532ms 降至 62.832ms（−28.2%）**，P99 由 **161.303ms 降至 94.551ms（−41.4%）**。但导诊业务同时明显减少：采样期工时由 1794 降至 709，终态保留的采样期完成回执由 28 降至 13，更多人物处于局部回接等待。**目前不能将该候选验收为业务表现保持的可靠优化，也不能把全部耗时差归为相同业务工作的计算节省。**

## 版本和改动

起始核对的 `dot/next-stage-20261107` 为 `30056f3b433939f315b5b590978ebc80453de0f9`。实现与验证位于独立工程、专属分支 `codex/performance-160-20261110`，主工作区保持原分支与内容。

- `815500b`：侧移后依次意图走向原路线 B、C、D；真实受阻后再换下一候选，从实际位置继续。选定意图不推进原路线游标，实际到达才推进。
- `700ff4a`：补齐新碰撞分支中原有的固定身体侧方出口检查，增加真实接触专项。
- `f8d8f80`：近共线历史只提供后退距离，保留当前实际横向坐标，避免一 ULP 的历史坐标差生成斜向后退目标；不改变角色位置、碰撞容差、目的地或历史。

候选连接继续检查静态结构和床岗位权限；未来整条连接上的动态身体不再逐段预演。当前实际迈步仍检查身体、已接受扫掠、门与预约。没有增加通行优先级、让行承诺或整层搜索，没有调整人口、模拟步长、到院规则、任务数或合法输入范围。既有候诊整区排序问题未在此改动中处理。

冻结测量期间，上游另增 `184a647b3144b6c85821e051ce3a223dc0e34fdc`，涉及连续局部转角和临床交接，与本候选直接重叠。本轮没有把该提交混入冻结源码或结果，**数据只适用于 30056f3 加上述三个改动，不代表最新 184a647，也未验证与其合并后的行为或性能**。

## 固定输入与测量范围

输入 SHA256 为 `ce56591c43fe1704abf76348dd5e67b0eae2a599143c03e045a780439a1bc15c`，与 [修改前独立验证](2026-11-10-performance160-30056f3-independent.md) 相同。初始实际为 120 患者、32 员工、8 访客；四层、64 房间、1340 设施，含 1200 个装饰物、24 张护理床和 8 个导诊台。正常到院、离院、需求、访客和维修继续运行，不固定人口。

每次新进程实际执行 1000 个前缀步和 2000 个采样步，每步 0.1 秒；每轮三次串行，采样范围和输入均未缩短。观察层 1F 在初始化准备静态缓存。使用相同的 `plain_v4.gd`、`campaign160.py`、根阶段计时和原生库，没有同时运行其他基准。系统缓存与正常桌面应用保留，因此不是独占机器实验。

表中时间为 `HospitalSimulation.step()` 墙钟经过时间，包含内部工作线程等待。初始化、步外观测与日志另记；不含 GameSession、显示帧、GPU 或持久化生命周期。画面没有验证，模拟步倒数不是实际游戏 FPS。原生库沿用相同运行时，没有另外进行发行构建验收。

实测减少主要落在移动与空间区间，最终仍约占完整步 57%。代码中的直接变化是 `_local_resume/_local_collision → _local_try_return → _local_return` 不再对每个候选执行完整动态连接预检查，也不在每个部分后退步重新选择未来整条连接。候选只是意图，真实 `_move_step` 才检查眼前扫掠；被阻挡后才尝试后续原路线点。该机制确实移除了原来的计算，但本轮没有对新旧每个内部函数作配对计数或自身耗时测量，无法把 24.782ms 全部归到某个被删除的辅助函数。

根区间互不重叠，但并非模块自身 CPU 分摊。`movement.space` 还包括预算派路、床岗位和层间交通；`clinic.dispatch` 包含导诊 `prepare/ordered_tickets`、临床忙碌视图和资源/到场检查，不能将独立的约 0.5ms 导诊调度区间解释为全部导诊成本。临床调度区间反而增加，说明路径演进改变后调度工作分布也改变了。不得把全部阶段差值理解为相同计算内容的单独提速。

## 业务结果与未通过的验收边界

以下均取相同的 2000 步采样窗口；各版本自身三次业务结果一致。

| 指标 | 30056f3 | f8d8f80 |
| --- | ---: | ---: |
| GP 工时观测下界 | 502 | 503 |
| 导诊工时观测 | 1794 | 709 |
| 终态保留且完成 tick 在采样期的导诊回执 | 28 | 13 |
| 服务开始 / 完成 | 4 / 4 | 4 / 4 |
| 真实到院 / 真实离院 | 2 / 1 | 2 / 0 |

| 耐心评估事件 | 491 | 539 |
| 采样开始 / 最终在场人数 | 163 / 166 | 163 / 167 |
| 全部 3000 步环境请求完成 / 消费 | 368326 / 368326 | 370066 / 370066 |

没有手动降低负载：初始人口与输入相同，最终人口、耐心评估和环境请求还略增。但导诊完成回执减少，已经超出“工作计数口径变化”的解释；当前数据不支持“吞吐保持或提高”的结论。GP 计数省略服务切换 tick，是下界；导诊工时也是观测计数。回执统计来自保留的终态，不把已清理记录推定为零，也不把终态计数当成全程所有导诊完成总量。

只读解码两版第 1 次终态、没有推进任何模拟步，得到进一步线索：仍有移动订单的导诊人物为 102→99，其中带局部移动状态的为 55→71，移动订单上标记“等待原路线局部连接空出”的为 **7→29**。例如最终版 `bench_patient_0002` 在 3F 的 `[29,53.1999969482422]`，当前临时目标已经到达，仍意图回接 `[29,58]`，原路线游标尚未推进；`bench_patient_0006` 也在导诊台附近处于相同等待。这是实际保留事实，不是模拟中伪造的到达或等待。

等待分支对应 `_local_resume → _local_try_return` 未能构造可接受的当前静态连接。新逻辑减少了未来动态预检查，但当前仍只尝试两种直角连接；侧移后的实际位置与静态障碍可能使这组连接不足。该静态连接覆盖是明确的代码限制，终态等待增加是实测；**尚未逐个重放这些人物，不能宣称 29 人全部永久死锁，也未证明所有导诊下降都由这一条分支造成**。历史轨迹在新旧两版都能看到往复运动，不能把基线当作到达正确性的判据。

下一项应先从这些真实等待状态选择最小到达回归，检验局部静态转角的覆盖和侧移后连续推进；保留 B/C/D 作为意图、实际受阻才换目标的简化，不恢复未来人物整段预演，不扩大到运行时整层搜索。与上游 `184a647` 的连续局部转角改动合并后，需要重新做受影响功能回归及相同三次测量。此项尚未实施或验证。
