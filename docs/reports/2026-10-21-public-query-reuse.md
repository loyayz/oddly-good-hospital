# 公共任务重复查询与冷启动成本

基线为 dev `b9bb59d59ec5db1d75f80e6db25f27f335f7fa41`。修复四类已复现成本：同批自动选区反复重建人物索引、冷建路网重复检查双向静态边、不同人物占住终点时仍反复派发局部绕行，以及等待依据中环境点与候选点的全量交叉扫描。公共360步平均耗时下降21.03%，GP80步下降12.94%；仍存在秒级冷步和百毫秒级普通步，正式性能验收继续暂停。

原始输入、前后完整步、细分函数、移动观察、相关回归及失败见[证据目录](evidence/2026-10-21-public-query-reuse/README.md)。所有快速运行保持120名患者、32名员工、8名访客，4层、64房间、1336设施及原0.1秒模拟步；没有削减候选、负载、排队或业务工作。

## 定位与处理

| 已确认问题 | 修复 | 保留边界 |
| --- | --- | --- |
| 自动选区每个主体强制刷新全部人物，已有动态父查询也重新刷新 | 同一世界的封闭动态查询复用当前人物索引；候诊批次首次实际扫描强制刷新，后续复用，所有查询在提交任务前关闭 | 独立调用仍刷新；显式强刷参数仍生效；其他世界及私有投影保持隔离；实际身体变化继续由原所有者同步，不引入永久身体版本或世界事实 |
| 冷建路网对相邻格的对称静态边检查两次 | 每对静态相邻格只检查一次，使用 Godot `connect_points(..., true)` 建双向边，并同步两端掩码 | 原邻接顺序和完整静态通行谓词保持；人物、预约与局部修补仍按原方向处理；不是删除必要路网 |
| 中途A阻挡，终点由另一人B占用，仍每步重派去该终点 | 实际碰撞后，用已有当前身体索引检查终点不可避开的身体核心；任何当前身体必占时保留原路径等待 | 不用历史扫掠、未来预约、组间空隙或可换朝向避开的角落证明必占；B实际离开后最迟下一边界允许绕过A；无冷却或负缓存 |
| 每次判断是否重试都把全部环境样本与全部候选点交叉比较，并序列化完整依赖 | 环境位置使用已有 `BodyIndex` / Boost R-tree 宽筛，再执行原曼哈顿距离精筛；按原样本序输出。保存一次深拷贝的结构快照，以引擎值比较代替每次 JSON 编码 | 全部依赖保留，不用摘要哈希替代事实；精确8格边界不改；同tick几何变化使视图失效；运行时缓存不入存档 |

没有增加自定义寻路、排序或空间树算法。环境索引使用单位矩形代理样本原点，宽筛留有余量，是否纳入仍由原 `abs(dx)+abs(dy)<=8.0` 决定。重复候选点去重，多个候选命中的样本只保留一次，最终按原源序排序。独立原全量枚举覆盖空点集、重复点、恰8格、8格外微小差值和小数坐标。

等待快照的嵌套位置、预约、同行成员、环境记录及附加事实在记住等待时深拷贝，之后采集只读值。嵌套附加值1→3→1、字典键顺序变化和同tick几何失效均有专项断言。环境位置索引遵循现有派发边界：设施移动和环境新增通过所有者失效，原位状态仍参与结构比较；推进阶段删除或替换的环境集合在下一tick重建。不把该视图解释为支持任意同tick直接替换源集合且不通知所有者。

## 时间具体花在哪里

原报告的秒级剩余成本包含首次构建的真实 `FloorNavigation` 实例。补齐全实例观察后，公共冷步和GP高成本步各为4次 `_build`，运营冷步8次；这些位置没有 `_repair`。没有证据支持直接删除其中四张图，实际修复是每张图内部的重复边工作。

普通公共步的另一主要成本是等待依据：tick2764、2863、2963各有24、20、20次签名采集，自身耗时40.51、43.59、40.63毫秒。对原输入前160步另作诊断，3107次采集中环境筛选累计3.232秒，其他依赖采集1.950秒，JSON编码0.493秒。主要问题是环境交叉扫描，不能把全部成本归给JSON。这个160步前缀只定位函数，不冒充完成16次公共服务的360步窗口。
