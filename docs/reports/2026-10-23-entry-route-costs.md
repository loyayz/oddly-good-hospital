# 普通步、入口路线与冷图成本

普通步的主要成本分散在候诊/访客等待、临床调度、真实移动与部门体验采样。GP尾步主要是集中选区和随后选位；公共尾步还存在临床调度与等待依赖同时变重的形态。静态投影重复构建每个完整窗口仅一次，弱引用借用试验没有建立整步收益，不采纳。正式性能验收仍未通过。

基线工程为dev `c122dcc75856592c68be4698b416ab9aad9f5b58`，生产源码及测试与`5712c6f7fbc7e222e2a483bc376201352fd5ffc2`相同。本轮只提交诊断报告和证据；弱引用、插桩和探针均保存在证据中，没有合入游戏。交付保留本地，不push。

## 负载与测量边界

沿用原合法160人输入：120患者、32员工、8访客，4层、64房间、1336设施，固定0.1秒步长。GP80步和公共360步均完整执行。Godot 4.7.2 Windows headless debug、原原生DLL、四任务部门环境采样、结构反向场、12次真实查询预热、128MiB导航总预算及查询部分1/4规则保持。每个进程重建服务，没有恢复运行时缓存、提前预热或截短输入。

函数探针记录实际经过时间和调用次数，返回表达式执行后停止计时，排除内层lambda的返回。按所选实际tick记录根阶段和原查询计数增量；计数快照及输出在模拟步计时之外。不同探针运行的绝对时间差很大，不能跨运行相减估算自耗，也不能将嵌套函数时间相加。固定tick只是复查位置，其排序身份由本次完整窗口决定。

## 普通步在做什么

同一份`probe03-gp80`诊断中的867步为52.579ms，拆分如下。该步没有选区、路线搜索或新静态投影，18次等待负结果均命中；缓存命中仍需核验相关事实。

| 根阶段 | 时间 | 实际功能与必要性 |
| --- | ---: | --- |
| 候诊调度 | 13.641ms | 处理已有选座/生活意图、目标有效性、等待资格及安全站位。负结果须观察相关设施、队序、身体、预约、环境和让位预览依赖，才能在条件恢复时醒来 |
| 临床调度 | 12.013ms | 为原临床票检查实际设施、合格当班人员、资源竞争和安全交接；该根阶段也包含访客派发，不能全部解释为患者候选排序 |
| 真实移动 | 11.559ms | 逐单位处理原路线、身体扫掠、门准入、实际预约、邻近身体及已接受扫掠，再提交真实位置与索引 |
| 部门采样 | 6.141ms | 累计患者真实位置的环境体验、原因时钟与到期怒气，以及员工每日能量/休息记录；环境计算已使用四任务Worker批次 |
| 其他根阶段、观察和残差 | 9.225ms | 包含到院需求、结算、发展、各模块边界及观察开销，不能再整体归入移动或寻路 |

这份诊断的`_decision_signature()`为18次、8.049ms，属于候诊和访客的实际依赖装配调用，不能与根阶段再相加。`_dispatch_public_seat()`112次、12.144ms，多数已有移动只核对目标、区域和明确失败后返回。`_ensure()`246次仅0.138ms，`_wait_constraints()`36次仅0.012ms。高调用次数不等于大块耗时。

当前需求不允许删除动态通行许可、降低安全核验频率或延长轮询。[公共设施规格§3.4～3.5](../specs/26-10/2026-10-18-public-facility-area-use.md#34-阶段检查与计算复用)允许复用未变的静态依据、当前同步观察和完整负结果；实际拥有者、附近身体、已接受扫掠及原业务交接仍实时核验。[移动规格](../specs/26-10/2026-10-19-task-navigation-movement.md)要求稳定移动目标、真实到位与当前许可。

## 公共窗口的区别

`probe02-public360`中，2651步415.937ms、候诊371.725ms；103次等待点搜索189.200ms，88次入口落点45.385ms，978次安全等待检查55.414ms。该步302次层内查询、127次静态路径构建及65次反向场命中，符合集中选区形态。

同一窗口的P99是2760步260.722ms：临床110.478ms、候诊96.148ms、移动20.225ms、部门采样14.058ms。它只有6次路线请求和6次层内查询，没有等待点搜索；等待依赖批次38次、矩形646个，负结果重查19次、命中5次。2843步同样只有9次路线请求，却有临床51.752ms、候诊86.992ms、44批692个等待依赖矩形。不能用冷图或A*解释这些尾步。

另一份`cache01-public360`诊断确认：冷2624步4张图构建50.635ms、路径缓存处理56.442ms；2651步没有新图，图获取302次仅6.644ms，距离查询464次12.961ms、路径缓存127次14.300ms。2760的图获取6次仅0.135ms。不同诊断只比较实际调用组成，不把跨运行时间下降当作优化收益。

## 弱引用借用试验与整窗结果

原入口静态检查没有驻留图时会创建投影，随后首次建图再次创建相同投影。原路径诊断确认完整图键与去除查询占用后的来源完全相同：GP851重复一次3.783～4.781ms，公共冷2624重复一次3.809ms。普通867没有新投影。GP冷824另有16次独立创建，但同一个已封闭查询内没有重复，不能据此假设一次查询内共享能消除它们。

试验在现有每世界/楼层来源记录中只保留最近一份几何的Godot弱引用及完整原图键；来源静态版本未变且原对象仍存活时，借用不可变数组创建绑定当前来源、身体的包装。没有增加强引用缓存、跨身份权限结果、图历史或预算。原驻留图接口、组与偏移回退、实际预约及身体检查保持。

每个完整GP和公共窗口均只借用一次。受试入口/建图构造中，GP实际构建20次，公共4次，各省16次门候选和16次预约候选查询；这不是全部权限查询包装的构造次数。其余原查询次数、完整业务、事件、随机流、最终二进制和非计时sample一致。

## 必须保留与可以减少的步骤

必须保留用途/资格/身体兼容、完整结构路线、当前安全站位、原队序和实际取位原子性。第三人、当前预约及已接受扫掠是实际阻挡；区域连通、静态路线和预约许可各解决不同问题，不能互相代替。部门真实体验累计、临床安全交接及人物真实移动也不是诊断日志。

不要求每次调用重新派生相同区域、复制未消费的完整布局、重复装配同源图、重排同一完整入口序列，或在未变的失败条件下重选全院。现有代码已对其中部分工作复用。未测得足够重复量的步骤不能因看起来冗余就扩大缓存；本次弱引用只省一次即属于该边界。完整布局复制的必要性、普通等待签名装配和公共临床调度仍可继续按具体消费者核验。
