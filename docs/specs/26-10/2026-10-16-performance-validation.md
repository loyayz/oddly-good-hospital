# 阶段28完整性能验证与优化

## 目标与依据

当前已实现的阶段1至28在本机固定负载上完成性能验证；不达标项持续定位、优化并按相同负载复测，直到满足既定目标。旧阶段的三轮优化停止限制不适用于本轮。尚未实现的阶段29以后玩法与最终正式资产不构成本轮已验证范围。

验证按选定场景逐轮推进。本次重新开始的完整测量只记录超标数据、判定和瓶颈线索，暂不因超标优化实现；完成其他可执行场景并汇总缺失证据。后续恢复优化时按同负载复测，公共优化只补验实际受影响部分；无关证据继续复用。

业务规则以现行设计与设计数据为依据。性能数值、负载和统计定义分别沿用 `balance.performance_targets`、`balance.performance_reference` 与技术设计第9节，本规格不建立第二套阈值。历史构建、已有快照和旧内核结果不定义正确性，也不证明当前版本通过。

## 完整范围

- 覆盖默认160人四层经营与640人密集现场的1×/3×，320人补充增长成本校准。两种窗口尺寸（2560×1440、2880×1920）、100%/75%/约67%三维比例及100%/200%界面比例均取得实际边界证据，不与全部人数和速度相乘。最高像素下200%界面、约67%拾取与文字/列表布局保留；实际独立成本或参数交互需要追加相关组合。
- 基础160人负载包含四个实际活动层、120名患者、32名医院职工、8名普通访客、64间房、128个服务位、1200件道具与24张病床。320/640档保持相同业务机制并记录实际角色构成、工作量及密度，不以静止或不可参与业务的假角色充数。
- 宽层负载在九地块96×96同层提供64间房、128服务位、1200道具及160/640实际角色。高层负载为640角色、10000层稀疏结构及1/10/1000/10000活动层，保留合法布局、身体适配与跨层业务。
- 经营、平移、近远景、反复缩放、切层、局部改建、冷缓存、热缓存、主动回收、反复切院、原生文字与列表、自动保存均按其真实工作计入相应工况。密集区间达到目标密度90%并满足对应指标的最低样本，独立统计，不以空院片段稀释。
- 保存恢复覆盖160人基线、临床中途、真实64MiB/128MiB世界、保存副本与切院候选/旧世界重叠。大世界记录实际资源与时长，不套用基线限制拒绝合法世界。
- 当前阶段的临床、护理、排班、生活、耗材、装修、设备维护、研究、到访及交通进入负载与成本覆盖。后续未实现机制保持明确缺失。

## 容量计算的准备与提交

容量采用提前准备、按依赖增量更新、日界校验并一次提交。精确容量C、独立结构规模K、病例概率、PlanScore、共享资源工时、护士岗位配置、旧工作扣减及ArrivalPlan的全部数值与随机规则继续以[随机来客规格§1.1.1～§1.2](../../design/11-growth-arrivals-recruitment.md)为唯一依据；§1.1.2拥有生命周期和待结果分支，不设置早于原日界的新输入截止点。

经营期间准备可重建的结构、参考需求和求解候选。相关资格、能力、方案经验、研究、设备、科室、排班、通路或病例输入变化时更新实际受影响部分，并传播概率归一化等必要影响；当前承诺和队列余量由原所有者在日界最终读取。普通tick、镜头和正常短时忙碌不触发全量重建。求解基和已验证成果可以复用，变化后的可行性与最优性仍须完整校验。

护理覆盖按各床承诺区间与班次求交后相加，一名护士覆盖多床的槽位时间可以超过单班长度；主动护理工时仍单独扣减并保持互斥。当前承诺在同一事实边界只读取一次，再分别形成三个班次余量，不把并行床承诺先拼成串行工时。

后台输入保留原业务版本及各层实际依赖。新病例名义模型去除临时预约，已有承诺读取真实展开适配、支撑设施和安全释放余量；同层再次转床期间，源床扣至实际安全释放，目标床保留新承诺，历史治疗台不重新承担旧床占用。预约授权变化在原空间所有者提交时立即使对应查询失效，冷热缓存不改变合法路线和安全交接。

实际承诺运输保留活动叫梯票、分配顺序、通行组身体及出口占用；新病例名义模型独立去除排队竞争。运输后段未知不抹掉已知的源释放量，也不重新占用已释放设施。封闭请求持有对应输入的完整结果直至消费或显式释放，其他准备任务完成不能覆盖它；失败重试仍针对原封闭输入。

名义运输的缓存身份包含连接条件、在途组成员与相对偏移、乘客身体及姿态朝向。病例参考与旅程复用共同遵守这些依赖；相同连接字段不代表在途组出口包络相同。连接新增、范围和故障变化仍重新检查全部合法替代路线，不只监听上次选中的连接。

参考模型与实际会诊在完整合法方案集上执行同一医院策略与同分仲裁，选定方案后保留全部合法资源选择。候选复用包含实际读取的专业、科室与服务池依赖；适配和路线使用同一候选布局。参考科室沿原合法路由选取，不以最快科室替代路由或复制共享资源预算；正式登记继续使用医院公共接待。已足够的诊断证据不再要求后续检查资源。

评价读取和回收共同保护当前已结算窗口及下一医院日所需候选，不以今日新病例挤掉今日仍应可查询的历史。经营采样仍在原每步边界执行，怒气结算间隔不作为环境采样间隔。原生求解只按完整可达模型中实际引用的资源判断护理约束；等式和不等式均按原始精确边界验证，耗尽资源的展示不等同于扩建收益证明。

结构资格的存在性查询找到合法方案即可结束，详细方案解释仍保留完整集合。容量模型直接组装全部终端阶段和独立前缀选择；完整队列代表只在实际需要时物化。几何参考仅拥有参与语义判定的字段，不保留无关完整源记录。护理预算变化后，旧整数岗位和缩放后的连续流只有在全部当前原始约束下精确可行、并达到由完整合法定价得到的当前全局上界时才免搜索；证明不成立时继续完整求解，不沿用旧问题的最优界。

主线程拥有固定顺序的医院事实、命令和随机提交；独立工作任务只处理一致只读输入。日界在原命令及前置边界生效后、到访前封闭最终输入，对候选补齐差异；完整结果就绪才生成并提交当天计划。未就绪时按§1.1.2保持当前步待续接并继续响应窗口，新经营命令排在该步之后；不重复已有阶段、不先推进新日、不用旧值或伪0代替完整结果。

等待、失败重试、暂停、保存及退出均沿§1.1.2的明确边界处理。最近完整显示和已提交日计划不被半步事实替换；存档不包含准备任务、求解状态或第二套预算世界。保持模式的名义基础能力冻结、有效当日计划的恢复及已有保存协议不变。

通用任务调度使用Godot已有Thread或WorkerThreadPool。容量连续优化采用SoPlex精确有理数模式，整数与分数运算统一采用GMP；医院模型、隐式资源选择的完整定价、护士岗位配置、独立结构规模K与业务提交仍由原所有者负责。求解与完整最优性检查按批次进入原生计算，避免逐标量跨语言调用；浮点容差解不得作为精确结果。分数继续使用规范十进制分子/分母，保存格式、取整方向和既有随机源不变。依赖或求解失败返回明确错误，不提交伪零容量。

通用离散搜索在LP与数值核心之后采用SCIP精确模式；流式JSON与受限ZIP的通用编解码分别采用RapidJSON和minizip-ng/zlib，保持原有类型、范围、完整性与归档安全策略。已有AStar2D、SQLite、Godot随机与哈希能力继续复用。依赖按实际替换责任逐项接入，记录固定来源、构建身份、许可证与随包文件，支持离线发行；尚未接入或未验证部分如实保留为未完成，不因选型或后台并发能力本身宣称性能通过。

## 测量与完成条件

评审完整性修复独立完成设计、实现和受影响回归，先提交处理结果，再执行一次限定范围的简单性能验证并单独提交报告，最后推送 dev；本轮不运行完整性能验证。简单验证中的超标项只记录，不继续优化。五轮评审及第五轮补充内容按原建议逐项给出最终采用或不采用结论；实现缺口、正确性证据和性能收益分别记录，不以缺少收益测量代替采用判断。

准备输入按布局、参考需求和当前承诺分层持有完整隔离值。布局由原几何所有者的变更身份驱动重建；动态记录未归口的写入保留内容比较。分层共享、记录版本与集合成员身份只属于可重建观察，不进入存档或成为第二份业务事实。日界仍封闭原截止点的全部输入，后继替换不依赖未应用的差分。变化回原值、删除恢复、恢复医院与切院均不得污染既有输入。

病例复用允许使用可证明的运输独立性：全部相关路线已经达到原几何时间下界时，连接变化不能产生更优运输；进入竖向或替代路线搜索的病例继续按完整连接候选重新判断。新增候选和原不可行分支均属于依赖范围。共享依据只在相同封闭只读输入内有效，实际承诺保留真实票序和出口，名义需求仍去除短时排队。

临床资源组件可整批执行精确规范化、重试权重和汇总，业务所有者仍决定资格、方案及全部候选。驻留身份按有序资源名及规范分数精确区分；没有有限哈希碰撞或近似相等。护理配置变化可更新原模型的可恢复限制；连续流、原始约束和当前全局上界共同验证后才发布。固定岗位连续模型与稀疏预算证明可复用其稳定数据，不与 SCIP 变换分解重叠持有。

活动病例索引由原到院与完成边界维护，病例离院后的临床、评价和居民结算全部完成才移除；恢复时从完整事实重建。历史病例、收费与收据继续保留。稳定 ID 顺序和同输入选择不变，查询返回的容器不允许修改原索引。只读占用与环境视图只在没有相关事实写入的观察区段共享，前一项真实预约或资源释放必须立即对后一项查询可见。

诊断分别记录布局复用、动态扫描／比较、输入替换、过时任务、病例重算、运输候选／缓存、组件装配、原生转换、定价、搜索、固定岗位重建、最终精确验证与锁等待。载荷估计、容器计数和实际内存分别命名；相关回归及有限固定操作观察不构成正式性能验收。

正式采集固定种子、命令、负载和版本，预热完成、样本量与操作覆盖统一遵守当前技术设计第9节和performance_targets.capture，不逐组固定等待60秒及采样600秒。同一工况同时覆盖多项责任时只采集一次；每项结论必须有对应证据，不声称未测组合独立通过。诊断短跑只用于定位。一次正式结论中的全部工况使用同一最终Release运行单元，记录实际源文件、引擎、原生库、发行文件和采集工具身份；相关实现未变化的通过证据可复用。

帧与模拟步分位数分别满足对应最低样本，操作场景完成其被测工作；只验证显示边界时仍记录全部步、速度和资源，但不因样本不足宣称模拟分位数通过。结果接近阈值或不稳定时追加独立窗口，保留先前结果与延长依据；超标不得靠增加轻负载样本稀释。首次加载与缓存准备完成后结束预热，运行中的资源重建和切换不改标成预热。

保存、施工、换班/日界、切层、切院、冷暖与驱逐及输入/预览按相关操作覆盖安排，不要求在每个显示组合等待。允许从合法业务边界开始，被测工作真实执行。发行前两现实小时稳定性场景单独保留，不乘到每个参数组合；阶段28验证不冒充最终正式内容的发行稳定性通过。

完整模拟步的P95≤10ms、P99≤15ms、普通最大≤30ms，真实推进速度≥所选速度的99%。实际呈现帧的P95≤16.7ms、P99≤25ms、普通最大≤50ms。输入至预览P95≤100ms，最大房间完整预览P95≤200ms。160人基线的主线程副本P95≤25ms、保存总时长≤2秒、载入≤5秒，工作集目标≤2GiB、共享图形资源目标≤512MiB。标准视图按原≤400绘制调用、≤1.5M可见三角形预算核验。

提前准备分别记录总现实时间、后台CPU、主线程输入提取/增量更新、校验提交及资源峰值；此前已完成的计算不重复记入日界步。当前步开始到最终完成的单调现实耗时包含跨帧待结果间隔，另列主线程执行时间；等待仍计入经营采样与原速度分母，不因窗口流畅、收到暂停/保存请求或转到后台而删除。未完成步记录未完成，不按切片数冒充完整步样本。技术规格第9节拥有统一测量口径。

分位数采用单调现实时间与最近秩算法。呈现帧取目标进程实际显示的相邻不同帧；引擎回调、平均FPS和CPU/GPU耗时不代替它。保留采样窗口末端已开始间隔的完整尾部，不剔除正常经营、保存、切层或资源退场长帧。模拟速度仅统计原采样窗口完成的真实tick，不借尾帧延长采样时间。

资源记录工作集、私有提交、实际图形分配及OS/引擎佐证；payload、分配、估计与驻留分栏，共享分配只计一次，重叠计数不相加。记录轮询频率、观察峰值和进程生命周期峰值；不可用的Release监视器或零值不构成零成本证据。

每组保留原始数据、退出码、脚本错误、起止与样本数量、实际人数及可见量、尺寸与渲染器、刷新和同步、电源与后台状态、采集开销、操作覆盖、预热完成及停止/延长依据以及各项判定。缺失、丢帧、未完成或实际模式不可用均为证据不足，不代填通过。完整通过要求全部适用责任、场景及指标有有效通过证据且没有未关闭的相关业务问题。

## 受保护行为

医院事实、随机流、固定0.1模拟秒、阶段先后、命令原子性与幂等、临床服务承诺、费用与耗材、实际移动和安全交接、暂停恢复及保存提交保持现行设计。不得减少合法人数、跳步、削减业务负载、重抽结果、改概率/工时/金额或跳过安全检查来获得性能通过。

镜头、界面比例、渲染比例、缓存冷热和回收不改变同种子同命令同tick的医院事实、预约与医疗结算。只在需求明确规定的顺序和确定性结果上要求严格一致，不以旧内核逐帧输出作为一般性能优化约束。

## 变更面契约

允许调整设计与采样配置、同步内容类型定义和生成资料，新增本地固定负载、独立Release采集与离线统计，修正测量缺陷，并优化当前所有者内的查询、索引、数据访问、重复扫描、投影、资源共享与释放。容量可增加一致只读准备、按依赖增量更新、后台求解和当前步续接控制；事实提交仍由原所有者按原阶段完成。缓存必须可由事实重建且不进入医院快照；续接控制只属于当前会话，存档仍只取完整步，不保存待续接状态。测量时间和缓冲不成为模拟状态。

业务责任、数值与合法容量边界不变，不添加运行时镜像账本、测试专用生产入口或通用框架。新增成本限于可重建缓存、必要表现资源及独立验收产物，纳入对应资源测量。

本机实际呈现追踪、Arc图形分配证据与全部窗口模式的可采集性在执行时核验。若必需证据无法取得，保留实际已完成结果和具体阻塞，不宣称完整达标。功能回归、静态检查、构建、性能和实机画面检查分别判定；功能回归按优化实际改变的事实、资源所有权和交接选择。
