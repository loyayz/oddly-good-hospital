# 房间、区域与导诊实施记录

## 合同与实施顺序

完整合同为 `2026-11-10-rooms-areas-guidance.md`，关联设计按该规格第11节读取。旧实现和历史性能快照不定义业务答案。墙价为每格边20币，每格边1.5米；新增墙长、报价和账目统一读取 `balance.wall_cost_edge`。4×4内格的独立四边共16格墙边，墙价320币，门另计，不收面积基础费，也不自动铺地。

实施与验证分为以下边界：

1. 独立墙和定向门形成合法空房，九种用途及家具约束接入建造、整备、蓝图、路径和视图；验证结构、计价、失败原子性、重复确认及撤销。
2. 临床和研究使用真实整房班表；医生个人桌不再作为上班凭据，护士工作交接保留；验证设备资格、同室并行、单人岗位互斥及研究培训桌位竞争。
3. 个人床属于员工宿舍，长期归属与休息室沙发回退分离；验证真实睡眠、完整工时、起身返岗、无位结束和冷恢复。
4. 逐设施三格区域使用局部几何索引，墙门均为边界；自动与手动任务保存原行程目标，在实际到达或移动确认失败后处理变化。
5. 删除运营科室，保留患者体验、怒气、全院和员工评分、小票与账目；导诊使用真实固定护士、同层随机房间、整台暂停及安排票序。
6. 功能、静态导入、内容一致性、画面检查和性能分别取证。功能验收后提交并推送 `dot/next-stage-20261107`；固定内容快照执行独立评审，修复与验证后再次提交推送。
7. 实现前基线及既有阶段性能证据保留；评审前不再新增性能验证。评审修复并推送后执行三次测量，以固定合法输入分析瓶颈、实施优化，再执行三次同负载测量。

业务交接沿房间结构→用途/班表→真实设施及人员→安全服务→结算/退出展开。公共几何查询在只读结果含义未变处停止扩大回归；公共身份重写和保存变更追加对应CORE用例。

## 生活需求与探望参数

员工自动需求采用首次180模拟秒、完成后冷却180秒、安全离岗后寻找45秒、实际使用8秒。先如厕，成功后与饮水交替；失败也冷却，但不虚构使用或改变下一用途。已到期时钟保留一个待办，原临床集合、术前准备、护士交接、当前服务和护理覆盖按安全责任交接，睡眠与已到期休假优先。

医生探望每60模拟秒检查空闲且无临床排班的在岗医生。有仍在恢复中的原住院患者时，每名医生每游戏日最多一次25%判定，关系读取已完成全科或手术主刀记录。探望使用床边三格内的真实安全站位，持续6秒；不预留床位或护理人员，不推进护理、治疗、出院与收费，新增临床排班或患者住院结束时按实际移动边界结束。判定日、原行程及完成记录保存在员工事实中。

数值来源为`balance.amenity_flow`和`balance.doctor_visits`。实现与专项功能验证后先提交推送，再执行独立评审与修复推送，最后执行性能测量与优化循环。
