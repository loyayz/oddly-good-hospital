# 局部绕行与已完成玩法修复：阶段验证

## 本阶段变更

- 移动受阻时不按人数、狭窄区域、时间或角色 ID 分通行优先级，也不重搜整条剩余路线。优先实际左右侧移，按原路线从近到远检查可达返回格，接回后继续原后缀，保持原目标和请求序号。
- 左右不通时沿已经走过的路线逐段后退；新起步没有历史时只检查直接后方一段。后退沿弯道时按当前段判断左右。侧移与重接都验证真实扫掠；队列仅验证队长代理，成员从尾迹发布位置。
- 局部重接只检查固定正交链接，不调用全程寻路。先检查两条 L 形和四条单轴外侧折线，再检查八条双轴外侧折线，覆盖家具旁凹位到门侧的局部返回。每个原路线格检查完这些固定链接后才考虑更远的格。队列外侧距离覆盖自身转弯尾迹。已完成局部前缀而受阻的角色没有永久占路权。
- 保存局部绕行阶段、原路径及后退历史；读档拒绝旧优先级让行状态和损坏的绕行状态。
- 移动 API 使用可重建的成员归属索引；相同目标请求不再扫描全部医院移动。正式取消/完成主动清理，世界或移动字典替换时重建。
- 自动候诊失去最后座位区域后沿原 5 秒边界重试，保留起时和临床票号。
- 员工自愿短休复用本步已完成派工的空闲结果，去掉替手预测和每池一人限制。
- 环境采样只有一个任务时直接执行同一任务函数，多任务保留线程池及结果验证/回退。

## 临时缺员恢复后的双拐角返回回归

自然入院专项的缺医生恢复场景暴露一个局部链接遗漏：医生侧移到 `[42,92]` 后，接待员仍占据原路线 `[44,91]`，接待台与房间门侧需要同时绕过两个轴上的拐角。旧六种固定链接不能表示已经可安全通行的四段路径，医生因此停等。增加八种固定双轴外侧链接，沿用原扫掠、身体、预约与队列尾迹检查，不新增寻路请求、通行优先级或保存状态。

SPACE-10 的 `nearest_return_around_furniture_and_entrance` 从合法家具、房门和角色输入开始，实际移动到原目标，验证最近可返回格 `[44,90]`、静止阻挡者保持不动、原目标与请求序号不变、仅一次全局派路、逐步身体与扫掠安全，以及重接阶段 JSON 恢复。自然入院 `NAT-04-staff` 同时保留真实前置、原方案与票号、缺员等待和恢复治疗的完整业务断言。此补充的执行结果单独记录，不修改上述阶段的历史通过数量。固定链接仍是有界局部策略，不声称覆盖任意迷宫或高密度交通。
