# 界面、操作与完整用户流程

## 1. 界面的任务

游戏现场占据主要画面。玩家最常做的动作是看一位病人、放一件设施、移动一间房和发现一个笑点。经营信息用于解释现场，而不是把医院缩成报表背景。视觉继承场景概念图的温暖玩具医院；界面以清楚的标签、实体图标和有限层次衬托场景。

主界面模式是“体验现场”，建造与管理面板是“执行任务”，图鉴与院史是“阅读”。同一时刻只有一个主要侧面板；高优先级对话框最多一层，不能叠三层确认。

## 2. 屏幕结构

以 1920×1080、100% UI 为布局基准，最小窗口 1280×720。顶栏高56，底部主工具栏高72，侧面板宽360、距边16。普通游玩时中央现场至少占屏幕面积65%；打开侧栏后至少55%。场景信息条不能盖住选中角色的头部和治疗核心动作。

```text
┌ 医院名 ▾  现金  今日收支             第12日   暂停 1× 2× 3×  菜单 ┐
│                                                                │
│        医院场景：角色、治疗、公共候诊、院区扩建                  │
│                                         ┌ 选中对象 ─────────┐  │
│                                         │ 当前阶段与原因     │  │
│                                         │ 下一步 / 预计等待  │  │
│                                         │ 最相关的两项操作   │  │
│                                         └────────────────────┘  │
│  事件短提示（最多3条）                      镜头 / 地图 / 叠层    │
└ 建造  员工  接诊  研究  任务  居民与图鉴   当前模式快捷键提示 ────┘
```

建造目录从底部升起，高248；对象检查侧栏同时收起。屏幕顶部显示草案总价与“确认建造 / 取消”，底部显示分类、缩略图、筛选和搜索。物品详情在悬停或键盘聚焦后0.4秒显示，可按F1固定；不要求精准悬停读小字。

1280宽或UI≥125%时侧栏改为最大宽320的覆盖面板，选中对象自动保持在未遮挡区域；底栏次要入口收入“更多”。低分辨率下放置目录按2行滚动，不能挤压确认/取消按钮。所有滚动区域显示当前位置，不让关闭按钮随内容滚走。

菜单中的存档、新建或设置使用稳定名称，不把“存档槽”用作医院名称。需要从医院切换到另一座时先保存当前状态，再显示目标校验与加载进度；原医院和草稿保留到目标完整就绪后一起切换。目标损坏、缺少内容、资源不足或切换取消时留在暂停的原医院，可继续编辑，不返回空白主菜单；“原医院已保存”与“已进入目标医院”分别表示真实完成的阶段。医院载入后先暂停，显示保存时的现场状态，由玩家按Space开始；此前速度作为界面偏好记住，不在载入期间先推进几步。

选中候诊患者时，座位一栏只说明当前真实状态，如“这里比较安静”“朋友正在旁边等候”或“附近没有可用候诊位”，最多两项；没有实际条件就显示普通候诊。当前原因不是已保存的历史动机，朋友离位后不继续称他在旁。可从“换个座位”进入原空间预览，指定真实合法目标；被叫号时入口随临床阶段收起，预览过期仍须复核实际占位。默认不显示性格分数、候选排名或八项权重，不让日常候诊变成手动优化题。

缺货卡里的补足建议复用原采购动作，显示当前数量、价格、付款后现金和真实目标说明；空间/资金不够直接说明原因，不悄悄缩单。就绪病例的说明可定位姓名与原票号，复工说明只引用本次缺货事件。普通购买与原每日一次援助并列，创作模式显示医院实付/基金代付；自动解决后同一原因卡收起。按下时捕获本次固定数量，队列随后变化只更新说明，不能把已经提交的2包替换成另一个病例的7包。

环境热图一次只显示当前层的一种覆盖，图例标明实际居民或参考身体。只为当前视野分块更新；区域尚未得到当前结果时显示“正在更新”纹理，固定几何放不下身体和本层未购/未完工区域使用不同纹理，不把未知或不可站立写成0分。图例结合颜色、明度和纹理，数值断点沿原0/60/70/80/100，不在每格写数字。选中或按原0.4秒悬停规则查看单格时，由原当前查询展示数值与来源；等待中的旧纹理不能替代当前查询。原患者卡仍显示本人的真实环境值。刷新是现实时间的显示工作，不暂停建造、接诊或候诊，不生成居民头顶文字。

### 医院时间一眼能读懂

顶栏显示第几医院日、24小时HH:mm钟面与当前速度，读取模拟规格§1.1的唯一时钟；正常经营面板的治疗、排班、招聘、研究、施工、等候和假期默认显示医院分钟/小时/日。剩余值按显示单位向上取，实际完成才换完成状态；短于一分钟显示“不足1分钟”。展开详情才显示原模拟秒，不让玩家在同一面板猜两种“分钟”。日界与临近换班来自真实sim_tick，不按系统日期或画面动画推进。

本机性能、自动保存、输入响应和导出/载入进度明确标现实时间；自动保存设置写“每3现实分钟”，不能显示为每3医院分钟。1×/2×/3×的速度说明分别写“一医院日约30/15/10现实分钟，不含暂停”；未来预估只说明当前条件，不承诺故障与等待后的实际完成日期。界面显示不改临床工作、预算、期限或随机流。

新日计划尚未就绪时，顶栏显示“正在准备新一天”及实际已等待的现实时间，保留最近完整现场，不显示伪造百分比或完成倒计时。窗口、镜头与菜单继续响应；已有面板显示最近完整结果，新查询尚无完整结果时标“准备完成后更新”。经营操作显示“已接收，准备完成后处理”，不显示已付款或已应用。暂停请求显示“当前步结束后暂停”，保存请求显示“等待当前步完成后保存”；完成后按原真实回执更新。发生计算错误时说明具体原因，提供重试及原不保存退出流程；保存后退出或切院仍等待真实保存成功。处理顺序与不重抽日计划的规则归[随机来客规格§1.1.2](11-growth-arrivals-recruitment.md)，界面不显示线程、求解基或内部输入版本。

选择“保持当前客流”而名义能力尚未就绪时，显示“正在计算接诊能力，完成后生效”；不把开关画成已生效或将临时旧负荷当作冻结上限。保存需等待原设置命令完成，暂停状态不因此推进医院时间。

“全层”按当前场景安全矩形适配范围，排除顶/底栏、当前目录与侧栏的固定遮挡，给真实楼板和身体/症状显示范围留总尺寸10%余量。大面积可以缩得比90米更远；仍只显示当前层。窗口变窄、界面缩放或打开侧栏时不反复自动拉动镜头，下一次主动概览/缩放使用新边界；当前构图可保留，必要时按钮提示重新概览。正在施工且本层尚无合法楼板时给出原施工定位，不拿未完成楼板当可建医院；场景安全矩形没有面积时保留镜头，待窗口恢复再处理当前有效操作。

## 5. 具体工作流

建房：选择已解锁房型 → 显示类型和最小尺寸 → 拖出连续轮廓并安排门 → 选择“只建空房”或配置设备 → 分列基础墙地、门、设备和可选美化费用 → 核对“可放置”与“可使用”后确认。只建空房成功即出现真实墙地与门，卡片显示房型、面积和“未就绪：缺设备”等当前原因；不需要先招员工或放机器，不赠送预设设备。缺件的完整预设继续保留草案，只有主动选择只建空房才按壳体清单成交。后续放入设备或安排人员时，沿原开放意愿与实际就绪条件决定可用性，不因空房已存在就提前接诊。

建造预览跟随当前草案的实际格子、方向、对象绑定与所选身体/选项；同格鼠标微移不反复重启检查。连续拖动或快速旋转只保留最新需求，轮廓即时反映当前草案，完整检查未就绪时在原草案栏显示“正在检查”，不沿用旧位置的可建绿色、路径通过标记或旧清单。可放置与可开诊仍分开说明。未就绪时原确认按钮不能应用，不积累稍后自动确认，也不新增弹窗；完成后按原确认流程操作。切层保留原层草案，旧结果不在另一层画成可建对象。计算和失效规则由preview_computation与技术规格§3拥有。

搬房：选一个或多个完整房间 → 移动/切层选目标 → 预览新路径、表面替换与原位置 → 点“停止新预约并准备改建” → 当前服务安全结束、人员走出 → 提示“可以应用” → 点“应用改建”按当前报价一次提交。空房无阻碍时可直接应用；等待时可收起面板、保存或调整安排，显示具体阻碍与可预测部分工时，不给无法保证的总倒计时。取消不会撤销已完成的转床或重新开放玩家已关闭的科室。

复制布局：完整框选单层房间/公共家具 → 保存空间蓝图 → 在已建空地预览 → 展开库存复用与新购清单 → 切换身体检查路径 → 选择是否追加美化施工 → 确认总价并放置。未配齐时保留缺件草案，主动选择只建空房才建立未开放建筑。无库存匹配、新购未解锁、故障库存、施工岗位缺口分别列出原因；“可放置”与“可开诊”分别显示。

查看事故：点击现场图标 → 侧栏显示“谁、为什么、现在影响什么、多久恢复” → 可选“优先处理”或“定位处理员工”。例如：“法师阿洛治疗没有成功，把医生冻住了。护士正在赶来；无人处理时冰块也会在45秒内融化。”实际界面显示剩余秒数，不能永远显示45秒。倒计时从实际作用阶段而非前兆开始计算；解冻后改为医生剩余休整时间，不继续显示冰冻或马上标成可接诊。有人正在赶来只说明派工状态，预计帮助工时不代替真实到场和工作；同一事件优先显示当前仍有效的恢复路径。事件产生的地面污物另显示清洁任务，临时状态结束不代表已打扫。

扩大接诊：研究完成短提示 → 点新病症 → 列出检查、会诊医生、至少一种方案、团队/床位与完整路线 → 逐条定位建设或招聘 → 点击“开放接诊”。新增病症沿用现有总到访档位，提示引用本院当天冻结的真实机会计划和明日区间，不固定写成起始规模的每日6—10次；实际患者数仍受开门、容量与路线影响。

恢复旧保存点：查看医院名称/时间/模式/内容兼容 → 点击恢复 → 保存当前状态为恢复检查点 → 校验目标 → 原子切换世界 → 显示“已回到第N日”。任一步失败都停留原世界，可打开错误详情但不自动覆盖其他保存点。

买地：点产权轮廓或建造“土地” → 选择1F共边可购地块 → 核对1,024格、顺序地价、付款后余额与“仅空地” → 确认后取得自然草地。真实房间边界墙保留，不送墙门；后续地面价序可直接展开。

买新层：先建或选择一部实际电梯 → 定位其所属地块和正下层房间 → 预览该块下一层的合并价、工人/工具与下层工作点 → 确认购买施工。缺房可定位下层并建空房，缺条件不误显示已付款；已有单显示原进度而非第二份订单。模块完工后，仅本块显示空楼板，界面分别提供“本层购买其他地块”“建房”和“安装电梯站”。旁块仍需下方已有房间且另付模块价；跨地块井道标出未取得部分，补齐前不能出梯。单站梯显示“目前只有1F站”，第二站安装明确显示0新增费与实际空间缺口，不画成付款后自动连通整层。

改门：选门 → 选外观/移动 → 预览收起与按当前身体展开的轮廓 → 显示价差、墙段和通路阻挡 → 确认。玩家不用手动输入尺寸；空间不足时用“展开会碰到长椅”“床尾挡住通路”等说明定位红格。可切换身体示例，显示完整路线，不承诺有自动伸缩就一定能通过。

修设备：现场扳手图标 → 查看故障、停用影响、修理员和剩余时间 → 优先处理或招聘。预防保养与随机故障分别显示，正常设备也展示低/中/高风险等级；概率公式只在帮助中。门和日用家具免维护，不显示故障或保养入口。

办活动：居民页“社区活动”或确有story_activity_links关联且满足开放条件的故事目标“安排” → 选独立休闲角落和互助主题（候诊区、通道不可选）、查看自愿报名来源 → 预览人数范围、故事必需角色、可用座位/站位和缺少条件 → 点“安排活动”后显示已定名单 → 现场看集合、演出、散场。预览合影可显示“场地可接待4—12位，安排时确定人数”；确认后显示“本次报名11位”，不把期望或上限写成保证到齐。若只够4位则直接显示当前场地4位。名单冻结后因场地占用尚未出发时显示“已报名11位，休闲区还有3处待位被占用”并可定位；不会提示全院160人或普通访客8人已满。普通合影展示本次可核验的康复纪念对象与协助报名缘由；没有合格对象时提示“暂无可报名的康复纪念对象”，不让玩家勾选病史。ST12目标入口明确显示对应邀请及四家族要求，不把未接取目标默认为已选，也不要求先完成故事。CA04仅在ST02完成后按SAL01提供庆祝安排，居民页入口也保留这一资格与关联；未达成时说明故事条件，不转为普通花展。ST09等没有活动关联的故事只显示原病例目标、完成结尾与领取入口，不生成默认庆祝报名。

故事中的固定成员与随机增加的邻居在同一名单显示。必需人物仍在就诊时显示其当前阶段并可定位；缺少亡灵家族、培养皿泊位或高门分别给出相应建设或接诊条件入口。集合页显示“已到7/11、2位乘梯、2位等待入院”，可展开延迟原因；高层预计时间依据真实路线，不固定倒数30秒。取消计划立即结束，取消集合/演出则显示“正在散场”，最后一人真实离院后恢复举办入口。取消无需追加确认弹窗；扩建需要结束当前活动时在同一个建造预览中说明影响，不自动重复举办。

做任务：打开任务簿 → 选择最多三项委托 → 预览目标与奖励 → 接取后目标出现小条 → 达标通知只提示一次 → 领取现金；已领取按钮变完成记录。任务可取消追踪但不会因此清空进度。未领成果长期保留。目标行显示中文动作、实际筛选条件和数量单位；例如“动物家族 · 治愈就诊 1/3次”，诊断完成不能被“康复”任务误认为已计数。只有实际有期限或预约的内容才显示对应时间，这些社区委托没有截止日。

### 放下之前，试试看

建造、搬移和蓝图草案共用“试试看”。默认带入当前选中居民；没有选择时用普通人类示例，旁边可切换普通人类、长颈鹿、石巨人三个体型，标签明确写出示例名字，不暗示覆盖全部种族。也可从当前在院角色选择患者或职员，直接使用其身体、附件和真实岗位。示例是虚影，不生成角色、疾病、资格、库存或临床预约。

画面只展开当前房间或所选设施：实线是基座，半透明实体是展开占地，虚线是患者与同时在场职员的身体/岗位，箭头是进出路线。门诊、手术、护理分别按真实站姿/躺姿和团队人数检查；已有排班职员按当前可用组合预览，缺岗时可显示普通人类职员虚影，但必须并列标“仅检查空间，尚缺合格职员”。不能用一个小护士的虚影代表实际巨型护士。

结果分别为“此组合空间够用”“可用，经过这里的人需要绕行”“放不下”，最后一种只突出第一个真实阻挡，并可展开其他原因。设施展开后留一格过道时，一格居民可通过、三格居民不可通过，切换旁观体型会直接改变路线箭头。若截断任一在院角色全部出口或已承诺路线，沿适配规则拒绝；有合法绕路时不误报为全面停诊。

试摆不自动挪家具、扩房或购地。拖开红格上的物件即可重新预览，所有变化仍留在同一草案，确认页合计实际费用。“可放置”“此组合空间够用”“可开诊”分别描述建造、适配与完整接诊条件；缺人、缺研究或缺治疗包仍会显示各自原因。提交时重查当前世界修订；预览关闭即释放显示资源，不保存虚影、不预留现实空间。

阻挡说明取实际对象类型：墙或家具给出改建定位；地面垃圾写“先清理这几格，设施才能展开”，打开原清洁页并定位已有污渍，沿用唯一置顶操作，不新建重复任务。纸屑可走过，因此普通行走预览不把同一格画成墙；设施展开预览仍保持受阻。并存原因可展开查看，清洁完成后当前卡和预览自动刷新，不要求玩家再次点“启用伸缩”或默认购买更大机器。

建造目录将医生办公室、员工休息室和护士工作台放在“员工设施”中；预览显示当前科室能共享的实际办公位、睡眠位和同层护理工作台，新增职员时给一句支持设施提示，不要求逐人绑定。

员工卡使用rest_cues区分“清醒短休”“正在找床”“等合身床位”“正在睡觉”“院外休整”，只显示当前一项。睡眠提示从原sleep_phase、睡眠余量、床位预约和真实离院状态派生；正在走向院门时不能写成已在院外睡觉。只有强制睡眠的原45秒等床阶段显示候床；提前睡眠没有空床时继续原班表，不显示虚假的等待。需要处理时按休息区合并提示，不弹逐人睡眠确认。床位预览显示完整卧姿、上下床区域及实际可通行空间。

接诊卡保留四档节奏，默认随医院成长，主行显示所选档位、明日随机范围及主要瓶颈，详情区分参考平均、实际到院和三班覆盖。例如规模S=2且选择正常档时显示“正常接诊 · 明日预计75—125次机会”，仅适用于两套独立且同等的D09基础常规参考资源、无额外路线与旧队列负荷；参考平均100来自原32.4秒终点占用及90%负荷，不由S直接推导全医院人数。真实医院按全部开放病例和资源时钟求值，整数范围中点不是参考期望。保持当前客流冻结完整名义基础能力上限，扩建提高余量，下降仍下调；结构额度仍按原偏好。当前在院含住院分项，不把120等样本当非法人数，建设与招聘不设32员工/24床/160人封顶。

## 6. 引导与可发现性

十项onboarding_steps依次介绍创建医院、定位患者、人类治疗、僵尸治疗、座位体型试摆或调整、有结尾的互动、取得研究资料、工资与补助、成长奖励、保存与医院列表。顺序只决定默认推荐，不锁建造/研究/诊疗等任何功能，也不要求在首15分钟内做完。每项只有一个当前主动作；已经在本院完成的真实行为可以提前满足对应项，不要求为了教程再移动一次椅子、再研究一次或再领一笔奖励。

座位教学OB05接受两种真实学习行为：对一件座位完成“试试看”并实际显示当前目标体型的空间结果，或由玩家确认一次座位移动/添置。够用、需绕行、放不下都能帮助理解空间，预览结果已显示便可记为完成，不强制修改满意的布局；只有打开按钮、仍在计算、过期结果或其他医院的预览不算。已看完结果后取消草案仍保留教学完成，预设开院自动摆放不冒充玩家操作。完成只在本院引导标记中记录一次，不产生建造费用、任务成果或空间预约。

开院提示和情境帮助使用面向院长的短句，默认只指向一个当前对象或下一步动作；证据键、随机流、凭据与处理器留在规格和调试信息中。研究、治疗、工资、奖励与保存仍各自按原事实完成，改写提示不会提前结算。

每项状态为未完成、完成或已跳过，另有本医院的引导开关；医院之间独立保存。未完成条件分为已有对象可操作、等待真实条件、需要建设三类，只展示具体差项。缺患者时显示下个原到访机会，缺设备时打开原建设预览，缺现金沿用真实账本与恢复经营；教程不自动建房、招人或借一笔教学现金。完成不发额外钱、经验或装修物件，也不改真实评分。

### 6.1 两次教学来院与自由操作

开院引导开启时，首个未跳过的教学请求为普通人类S49/D37，随后是僵尸S13/D09。每请求至多绑定一次真实Visit，按顺序使用原到访计划中的合法机会，仍检查开放权重、容量、人员和完整路线；目标不合法时该机会正常消耗，请求等下一次，不额外补人。页面明确显示等待原因与“跳过本项”；跳过未入院的这一项后处理下一请求，两项都结束则恢复普通抽样。空地开局同样先实际建设，教学不会在院内生成堵路患者。

请求在入院时消耗，并把一次成功保护交给该Visit；对应第一项实际TreatmentAttempt建立时把成功结果冻结，消耗Visit上的保护。保护不跳过准备、耗材、操作时间、住院和原收费，不赠第三位患者保护。若患者在第一次尝试前友好离院，保护随Visit结束，不退回请求；这一项保持可跳过，也可由此后真实的同种族同病治愈完成。已经冻结的结果、已入院Visit的保护与已消耗请求分别归各自事实所有者，结束引导不改写正在进行的病例。

“跳过本项”只结束对应提示与尚未发出的教学请求；“结束开院指引”关闭整个当前医院引导并取消未发请求，取消标记随医院保存。重新开启仅恢复尚未结束的说明，不恢复已经取消的教学来院请求。已入院患者正常就诊，已开始互动安全收尾。帮助中的“再看说明”只重播插画、文字和当前对象定位，不重置引导状态、赠品凭据、患者保护或随机流。按原保存点恢复医院时，整座医院与引导一起回到该点，不能把另一条进度分支的完成状态混入。

互动教学观察实际患者、陪诊或探视者之间发生的一次完整日常互动，或一次主事件安全收尾；性格、关系和真实情境照常决定表现。没有互动时可看说明或跳过，不生成配戏访客，不延长康复患者停留，也不把患者转为闲逛身份。此前镜头外已发生的完整互动同样可认领。五类有明确用途的活动采用自愿报名和各自随机人数区间，不是教学补人入口。

### 6.2 错过现场，也能接着学

治疗与互动项的完成取真实结算/收尾事实，不取摄像机是否看见动画；不在视野内发生时卡片写“已完成，可查看记录”，定位现存患者、小票或院史摘要，不伪装成正在现场演出。研究资料由实际诊断或简报到达满足，打开资料页或点击索取并不等于收到。成长奖励须有原领取凭据，自由模式以实际领取完成/外观奖励为准，不把未发的现金写成已到账。

工资与补助项要求实际打开能显示全岗位成本和下次补助的财务页；自由模式显示不发补助及创作基金，仍能完成阅读。保存项先记录实际手动保存成功回执，再介绍医院列表；只有一座医院时打开列表即可学习入口，不要求创建第二家来回切换。取消文件对话框或保存失败不算成功。读入当前有效的手动保存点本身也能证明保存动作已成功，避免该快照恰好早于成功回执导致引导反复要求保存；未来保存点或其他医院的文件不能作为证明。每项涉及的最多两个事实标记由该项拥有，不复制交易、病例或文件内容。

### 6.3 九种情境帮助

context_lessons覆盖宽高不通、首次买地预览、设备故障、排班缺口、手术/住院准备、安全改建、生活兜底、直接资助与员工冰冻。提示取当前真实阻碍或已经发生的账目，不提前断言诊断、疗效或未来破产。每项有短说明、一个最相关入口及“稍后/不再主动提示”，没有必须执行的指令；财务紧张也不要求立刻领取任务或卖家具。

全屏同时最多一条教学气泡，服从原三条通知总预算；两条教学气泡之间至少60模拟秒。存档错误和真实命令失败优先，建造确认与拖拽期间不浮出遮挡按钮，关闭面板后再从仍然存在的情境挑选。候选按内容优先级、原因出现tick和稳定ID排列，不按事件数量堆队。问题已经解除则撤掉当前建议，不再追着玩家弹旧问题；帮助目录仍可手动查阅。

每医院每项最多完成一次主动教学，“稍后”延至下一医院日仍有对应情境时再尝试，已读/停用标记仅在选择阅读或不再提示时终结；关闭本医院主动帮助后仍可手动打开原因卡。状态按有限定义保存看过/停用/延后日与全局下一可提示tick，不保存无限待弹队列。提示和插画不会独立推动业务时间；打开普通原因卡维持当前游戏速度，只有原明确会暂停的模式继续暂停。字幕、键盘焦点、125%…200%缩放和低动态均能完成全部引导。

引导状态归原HospitalMeta.tutorial_flags，并按步骤/情境定义键存完成和跳过事实；ArrivalPlan只消费原来客机会，Visit拥有入院后尚未使用的保护，TreatmentAttempt拥有冻结结果，提示没有自己的患者池或余额。新增内容仅是十步定义、九种情境帮助和原教学状态闭合；全部游戏系统从开院起按各自研究/资源条件可用，不缩成教学专用版本。保存回执、空地恢复、跳过及可访问性仍须在真实游戏验证。

冰冻的主动说明同样由context_lessons及共享提示预算拥有，不另发第二条教学气泡。规则解释从原因卡片展开，主界面不显示概率公式。

## 7. 提示、语气与重要程度

普通康复不弹窗，只在角色动作与轻音效中表达。研究完成、第一种新居民、故事进展为低频短提示。存档失败、命令无法提交为持续可操作提示。只有退出未保存、删除医院、覆盖手动槽和切换自由建造使用明确确认；暂停、正常建造和游戏事件不频繁确认。

屏幕同时最多3条短提示；同原因10秒内合并，例如“3件设备等待维修”。严重程度用图标、标题与颜色共同说明，声音可以关闭。事件不强制移动镜头，只提供“去看看”。

10秒合并窗口不是每10秒重新提醒一次的计时器。相同根因持续存在时，人数、剩余工时、受影响房间和处理进度只更新原原因卡，不重新弹出或播放音效。首次出现可给一次短提示；同一问题首次从普通等候升级为实际服务受阻或缺货罢工时，最多再给一次，其后仍在原卡更新。新增受影响患者和切换当前选中对象不算新问题；不同根因仍按原优先级合并和三条显示预算筛选，超出的普通短提示不排成长队延后轰炸。

原因真正解除后原卡安静收起，下一次由新的真实故障/缺货事件或新状态转换产生的问题才可重新提示。手动收起短提示不关闭原因卡、暂停计时或取消工单；仍可从对应页面查看。载入、切换医院或恢复旧保存点时直接用当前事实建立卡片和原继续经营便签，不将现存问题当作新发生一遍。建造拖拽、付款确认和文本组合期间不浮出遮挡操作的普通短提示；操作结束只展示仍有效的最高优先项，已解除的略过。

提示去重使用原原因卡的稳定根因引用与本次视图会话中的已提示等级，不逐患者另记一份问题；没有独立根因实体的缺岗等状态按原查询从不存在变为存在区分。视图只保留当前仍有效的根因记录，解除即释放；加载时将已有原因初始化为已展示当前等级。视图信息可丢弃，不写入医疗、工资或任务状态。保存失败、内容不兼容和真实命令被拒绝继续显示对应可行动错误，不受普通短提示次数隐藏；错误恢复后依据原成功回执解除，不能靠提示超时宣称已修复。

固定文案：缺员工“需要一位治疗能力达到1级的医生”；不可达“这扇门通不到公共走道”；资金不足“还差320欢乐币，可先缩小房间或打包现有家具”；保存失败“这次保存没有完成，你仍在当前医院。重试／导出到其他位置”；内容缺失“此保存点需要以下内容包，原文件已保留”。

### 医患文字只在当前病例里显示

医患对话为文字，没有语音、TTS或拟语声。只有当前对象详情明确绑定的一个病例可显示，原病例详情内最多一张卡、两行正文，不在角色头顶、每台机器或整个候诊区铺对话气泡；房间或活动名单未唯一指向病例时不自动挑一个人来说话。文字来自该病例真正开始的沟通与已登记短句，未选中的医患仍完成原交流与工时。看微观近景不会再复制一张文字卡。

诊断台的医生性格由原道具小动作辨认，不加性格对白、额外气泡或常驻解释标签。观看时谨慎核对、果断指向、好奇观察、温和平稳、效率对齐与团队协作准备分别有自己的姿态；病例状态与证据仍读原详情。医患文字关闭时工作小动作继续，次要表现名额不足时仍保留主采集姿态和必要进度。

大面积医院的远景保留当前真实轮廓和医疗/安全状态，当前选中且可见对象有完整细节。平移与切层时先响应镜头、对象选择和必要信息，细节在原预算内分帧补齐；尚未就绪的轮廓仍引用真实实体，不将已拆墙或已离院者当成有效对象。显示准备不暂停医院，叫号继续用原号签/头像/站点。加载说明只在当前对象详情显示，现场轮廓使用图符，不给每位角色铺加载文字、对白或全屏解释。

当前文字通常保留至少4现实秒，不要求读完、关闭或确认才能继续诊疗。服务已经结束时使用原状态注明本段已结束，不让保留的短句冒充角色还在讲话；阅读窗到期后只查询此刻仍实际存在的沟通，无新内容就收起，漏过的句子不排队补播。主动切换对象、关文字、退出或重要提示占位可提前收起，不阻挡输入。原名字与必要状态继续在对象详情显示，短句不携带尚未揭晓的疗效。

日常互动、回访、活动与病症道具使用动作、表情、插画和图符，不显示对白句子。道具上的招呼、道谢、客服、合影提醒改成图符；数字票号、楼号、房间标识、物品数量、进度和可执行原因继续按真实信息显示。叫号只用既有号签、头像与站点指示，不添加播报、叫号句或确认步骤。普通提示仍遵循原最多3条与合并规则，必要信息不依赖医患文字开关。

## 8. 字体、色彩与辅助选项

画面设置显示“标准／低画质”和独立“三维清晰度100%／75%／约67%”，默认标准+75%。说明直接写“只调整三维场景，文字与按钮保持清晰”；UI缩放仍由原100…200%设置拥有。选择改变当前显示，不改变医院状态、不收费、不暂停任务或重新生成角色。选中轮廓、放置格和拾取在各比例下指向同一真实对象；静音、低动态和画质可以独立组合。当前设置只保存为本地偏好，不给本机硬件预先盖“60fps已通过”章。

UI采用 Noto Sans CJK SC Regular/Medium；正文18逻辑像素、次级16、标题24，最小辅助文字14。图标旁的操作名称默认可见。按钮点击区域至少40×40，主要确认至少96×40；面板内连续操作间距8，段落间距16。设计色板：背景暖白 #F5F0E6，面板 #FFFDF7，正文 #243932，主操作深绿 #286F5A，信息青 #397F91，提醒棕橙 #8B4D17，异常深红 #A23D43。提醒和异常都保留文字，实际渲染需测对比度而不是仅依赖色值。

UI缩放支持100%、125%、150%、175%、200%，布局随可用逻辑面积重排。医院名字最长24个用户可见字符，角色名字最长16，物品名最长24；超出面板宽度换行或省略并提供焦点全文，不能截断金额和操作按钮。

文字处理复用当前控件和共享字体资源，具体成本合同见技术规格“原生界面的文字与字体资源”。普通数值刷新频率不延迟中文输入法、光标、焦点或命令反馈；两个相同名字的列表对象仍分别绑定真实身份。缩放、改字体或收窄面板后重新排版，必要全文保持可访问。随包字体回退仍缺字时显示缺字符号并保留可查看、复制和编辑的原文，不要求为性能改名，也不联网下载字体。

选项包含：独立音乐/机器/角色音效/UI音量；医患对话文字默认开；减弱闪烁；减少镜头与界面动画；事件慢镜头默认关；跟随镜头平滑程度；背景暂停；高对比选中轮廓；关闭自动旋转；启用键盘格网操作。不提供语音、拟语声或全院对白字幕模式。微观观察窗有独立放大按钮，不要求把整个医院放到极近。同时只打开一个近景面板，再点另一扇窗切换原面板目标，不叠窗口、不改变原运行速度；仍可主动使用既有1×观看。近景显示当前真实到场者，空窗显示暂无可观察对象；关窗或切层后院内互动照常继续。医患文字只在当前病例详情占一个位置，近景不复制第二份；关闭文字仍能看见叫号图示、患者状态和故障定位，设置中没有广播入口。

减弱动态时取消镜头晃动、急闪和快速旋转，机器用分段姿态和进度条表达；业务结果和工时完全不变。光效不得使用快速明暗交替制造笑点。“以1×看这段”只由玩家主动开启，其速度与镜头边界见本节，不自动抢控制权。

### 安心看完一段小喜剧

选中正在发生的检查、门诊治疗、手术操作或床边护理时，可点“以1×看这段”；当前没有执行段就显示原等待原因，不为观看提前叫号或开工。操作绑定当前执行会话及阶段，只持续到这一段结束或中断，手术结束不会继续锁定整段住院，护理结束也不等到整次出院。1×下只进入观察，2×/3×下暂时改为1×；暂停中可选择观看，时间仍暂停，待恢复速度设为1×；随后手动继续视为新的速度意图，结束后保持1×。

临时速度只在观看仍拥有控制权时恢复到进入前的运行速度。玩家手动点任意速度或按Space后，立即撤销临时恢复意图，阶段结束不能擅自从暂停跳回3×；即使手动又点1×也视为新意图。设置、拍照或失焦引发的原自动暂停只冻结观察，关闭后沿原自动暂停规则恢复。一次只观察一段，切换目标先结束旧观察，不叠加多层恢复栈；退出医院、读档和切换医院清除临时意图，旧会话不能改新医院速度。

自动暂停原因可同时存在：拍照内打开文件窗口只增加一个临时原因，关闭它不会退出拍照或启动医院；恢复焦点也只解除失焦原因。顶部沿用一个暂停标记，展开才看具体来源，不叠加多条警报。观看的1×仅是仍有效的临时覆盖；普通自动暂停不把它写成玩家永久速度，也不因反复开关窗口把原3×遗忘为1×。玩家主动改速立即撤销观看覆盖，此后关闭窗口使用新意图。

F跟随沿原规则绑定实际角色，手动平移、手动切楼层或取消选择即结束跟随。允许自动跟随切层时，楼梯按实际跨层点切换，乘梯中留在原观察层并显示真实目的层，到站后再切；关闭该选项时只显示去所在楼层入口。没有中间楼层就不渲染假场景，不为镜头生成第二个角色。镜头取身体真实高度与包络留边，床和门展开时不裁掉身体，也不自动放大到看不见四周；低动态用稳定构图替代追随晃动。

目标离院后沿原规则停在院门并显示病例摘要，取消观看不撤销治疗、采购、员工工作或场景占地。观看会话只属于本地视图，不写入医疗会话或快照；永久偏好保存玩家选择的速度和镜头选项，临时1×不覆盖它们。读取当前治疗状态可以欣赏现场，不能翻看尚未揭晓的结果或借回放再次获得收入与实践。

扩建与接诊页用“多了一个治疗位”“已补齐第二组接诊能力”等具体说明解释变化，主卡显示明天的随机来客范围。保持当前客流是可选的经营节奏，楼层、病床与真实服务能力仍照常增长；详细班次匹配按需展开。移动原有诊室和购买无人设备各有明确原因说明，不把付款成功当作已经增加吞吐。

诊断详情显示已完成的证据来源和真正需要的下一项检查；达到门槛后标明“证据已足够，无需共振”等实际结论。比较升级或医护培训时使用实际两段执行者与设备，没有完整可执行团队则标注条件示例。预测只说明在这些条件下可省哪项检查，不能提前确诊、安排不存在的护士或多收未做项目。

管理列表在滚动和更新时保持选中者与阅读位置；排序值相同按稳定对象顺序排列。输入名称、选词或确认一行操作时，列表不从指针下换人。对象已离院或离职时保留明确的离开说明，再按原导航返回；不能悄悄把下一位当作原目标。搜索与筛选等待更新时显示进度状态，不把尚未返回的结果显示为“没有患者”。头像使用轻量静态图，查看具体动作仍定位实际医院现场。

## 9. 存档、导入与删除的界面约定

重复打开游戏且同一医院资料目录正被占用时，启动页显示“医院资料正在被占用，请回到已打开的游戏或稍后重试”，提供重试和退出，不进入医院列表。退出游戏尚有写盘任务时仍保持占用；崩溃后重开沿原保存恢复流程，玩家无需查找或删除锁文件。其他启动错误显示真实原因，不把权限不足写成医院损坏。

导出默认文件名包含医院名和日期，但路径组件过滤Windows非法字符，显示名称不改。系统文件对话框可取消；取消不是失败，不显示红色错误。导入先只读取清单，显示版本、医院名、日期、容量和兼容结果，点击“作为新医院导入”后生成新的医院ID。

手动槽已满时让玩家选择替换一个，默认不选最旧；自动保存只轮换自动槽。删除医院先确认名称，移动到30天可恢复垃圾箱；列表显示剩余天数，清空垃圾箱需要第二次明确操作。卸载默认保留用户数据，不与游戏内垃圾箱联动。

医院切换和退出等待保存时最多显示一个进度遮罩。超过5现实秒显示“仍在保存”，超过15秒提供取消退出/导出；只有原写入明确失败后才启用重试，进行中不启动第二个写入器，不把卡住当成功。只有收到持久化成功回执才显示“已保存”。

保存提示注明实际保存的医院日时刻，期间又有进展则显示“此后还有进展”，不让较旧回执覆盖较新的编辑。退出等待中不再接收经营命令；取消退出保留当前医院暂停，迟到成功不会再次关闭。未提交草稿在原退出确认里列出摘要，提供“保存已确认进展并舍弃草稿／返回编辑”，不增加第二层弹窗；Ctrl+S旁提示“草稿尚未建造”，保存本身不施工、不收费。草稿和已确认的待改建安排使用不同标记，后者随医院正常保存。

### 重回医院的继续经营便签

医院成功载入、切换或恢复旧保存点后保持原默认暂停，现场角落显示“还是第N日，你离开时的医院在这里”。便签只读取本次实际载入的世界，最多共用既有三张经营提示的位置，不与常驻问题卡各复制一份。玩家可直接按Space或点击原继续按钮，不必阅读、勾选或关闭三条提醒。

先合并当前阻碍既有照护的真实原因，再使用原原因卡优先序显示缺货、故障、缺岗或路线问题；剩余位置可显示当前已关注目标，以及最早开始且未完成的研究、培训、装修或升级工作。没有对应事实就省略，没有问题时只说“医院停在原来的时刻”，不制造待办。目标使用原任务/培养目标顺序，工作按开始tick与ID稳定选择；显示的是当前状态和下一步入口，不替玩家选择研究、支付材料、领取奖励或召回员工。

每条都可定位实际对象或原详情页，已离职人员、已移除物件和旧记录只显示历史文字，不能落到另一座医院的同名对象。打开旧保存点显示那个时间点的库存、队列、能力和工作余量；不与较新保存点混算，也不把现实离开多久写成患者等待了多久。近期院史可从原入口展开，便签自身不写“回来一次”的经营事件。

开始经营后便签收起，尚未解决的问题继续由原卡片更新；再次打开只重查原事实，不重发提示、采购或奖励。它是可丢弃的视图投影，没有另存一份任务列表、完成状态或离线计时器。临时观看与跟随不恢复，保存的镜头偏好和原选项照常生效；快速切换医院时只接受当前医院与当前加载会话的结果。

正在治疗的患者卡和选中机器显示本次真实“常规操作中”或“舒缓操作中”，读取已开工Attempt，而方案比较继续显示下一次可选项。舒缓的当前提示解释“动作更轻，工作量已包含准备”，不显示“已获得护士安抚”或承诺治愈；暂停时改为“本次舒缓，已暂停：故障”等实际原因，不继续称操作中；同样不以舒缓文字掩盖缺员。C档转入病床后改用实际恢复/照护状态。文字与原方案图标共用进度区域，低动态和静音同样可辨，不在全院每台机器额外悬挂新倒计时。

## 10. 验收画面

必须提供同一医院的1920×1080@100%、1280×720@100%、1920×1080@200%三组画面；每组覆盖普通游玩、建房/换门预览、土地付款、长病名/身高详情、设备故障、补助和工资账目、任务领取、冰冻、研究锁定原因、存档失败。使用最大名称、两台同时治疗、近景大体型与微观居民，验证真实内容范围。以上是实施阶段的必交画面，不以当前概念图代替。

## 医生、手术与住院的操作细节

医护详情固定为“能力、排班、性格与履历”，医生另显示职称与工资。能力区每人只显示三条有名字的星级进度：医生诊断/治疗/手术，护士诊断/护理/手术；每条只有“继续工作会进步”和“安排培训”两种成长入口。主刀/麻醉显示为手术岗位分工，不拆出额外技能；晋级只列病例、现有能力与评估费。研究桌、占班与待办原因在报名预览中解释，不把公式或内部资格ID放进日常操作。

排班网格以医生为行、早中晚为列。单格修改弹出任务与科室池选择，底部显示“初诊1、体态1、麻醉0、查房0”等覆盖事实；连续手术班以相连底色表示。指出具体冲突，例如“晚→早→中连续工作3班，请留出一班休息”“这台手术需要215秒连续窗口，当前剩余178秒”。预览结果从模拟投影取得，不在界面另算资格。

选方案时展示预计成功率，不伪装成保证治愈。已展示的方案卡给出等待、操作、观察时间以及本次治疗包数量、现存可用量、设施使用费和成功后另收的治愈费。自动理由直接引用分项评分，例如“舒缓方案把握更高，预计多用29秒”；手动选择也须符合能力和75%底线。效果低于75%底线、较已确定报价下降超过5个百分点或方案必要条件失效时，自动方案显示“医生正在重新核对”，由原流程接续；院长指定才显示“按新效果继续/另选方案/交给医生”。效果提高不打断，单纯资源等候不反复会诊，同一张卡更新原因而不弹连续确认窗口。真正治疗已开始时不再要求重选。

手术室和病房从建造目录直接找到。预设提供紧凑和宽敞布局，预览门、床与设备真实展开范围、医护操作区、购置费与工资。床会自动伸长，空间不足直接显示“床尾差一格”等阻挡原因，不要求另买巨型床或指定门型。床位板按房间分组标空闲、即将入住、恢复中、等查房、故障暂停，不依赖单独颜色区分。

手术和恢复失败显示下一步而不制造危急倒计时：“机器完成本次后需要维修”“护理床需要维修，护士将转至2号床”“查房医生下一班到岗，预计还等46秒”。病例恢复和排班信息默认在选中时展开；现场保留清楚的患者演出，不让排班表常驻覆盖医院。

## 诊室互动与员工休假操作

患者卡可见“表达较模糊，医生正在用图卡询问”“急性子，等厕所使怒气增长较快”，不显示贬低患者的性格标签。敲门前兆说明具体等待原因与可用处理人员；暂停可调班、指派导诊、规划新座位，不提供远程强制清零怒气按钮。

员工头像优先显示当前主要需要：工作、休息、交接、缺货抗议。详情展开即时能量、医生长期劳累和压力及最近原因。休假仍可预览1…3日覆盖，已有手术与护理先交接；游乐自动在合法休息点使用，不要求操作小游戏。缺货页共用全院一张卡，采购后显示自动复工进度，无逐人劝返按钮。

诊室台词可自动播放、跳过或关闭字幕演出；规则工时仍按开始时承诺推进。患者性格、医生回应和当前局面用一句解释串起，不让玩家在每位病人的对话树中连续做选择。


## 熟客与经营建议的呈现

角色卡显示最多3条有来源日期的熟客记忆；只写实际前情与已经发生的回访，不给未发生的剧情打勾。公共区出现回访时只显示短气泡，不抢镜头。建造帮助提供四种生活角落搭配卡和AE01…AE03真实操作区预览；巨型软垫不以视觉缩放掩盖占地。

经营原因卡、3张并发上限及可预览排班建议使用[熟客记忆与喜剧节奏](10-community-comedy.md)的规则。建议应用前显示所有班次差异与残留缺口；相关班次、人员或安全覆盖发生实质变化才重新生成，世界照常运转不使按钮不断过期。需要更新时在原面板标明变化并保留草稿，不层叠确认框；安全与保存错误不被普通建议限额隐藏。


## 随机到访、离院与招聘反馈

接诊面板显示今天冻结档位、随机范围、参考平均量、已实际到院及次日设置，不写成每天必来。档位说明轻松/正常/忙碌/盛大开放的压力倾向，人数来自本院资源工时。展开才看班次覆盖、瓶颈与未计的未知变化，不向主界面铺求解器参数。患者卡显示真实等候、当前离院倾向和原因，不提前揭示随机疗效；反馈区分弃候、主动转诊和两次未愈。

招聘详情列出角色全部设定和录用后的现金/工资变化；不可达的楼层给出具体楼梯、电梯或门，不把外观介绍当作能力值。简历过期只汇总提示。楼层切换、跨层定位、未提交草案和镜头偏好按新增经营规格处理。

建造帮助里的生活角落页展示四张搭配卡，使用内容目录的家具和互动引用。可查看现有物件、打开原价建造预览，或在已有相关会话时使用现场观看；默认不显示种族收集进度、待完成感叹号或新的角落评分。

## 11. 轻松选择设备与职员

医疗建造目录只呈现六张卡：诊断台、整复台、调理舱、奇想台、手术台、护理床。卡片先讲“能帮谁、需要哪种能力、多少钱”；84套演出放在病例图鉴中欣赏，不铺成商店和升级清单。选设备时只显示当前三档之一、实际可服务范围、当班医护是否合格和一个升级按钮。病例效果预览用“治疗成功率91%”“操作约32秒”等实际结果，详细展开才显示能力发挥率，默认不要求计算。设备卡的人员分工和升级用途引用操作档案短句；诊断台明确初诊由医生承担，手术台明确两名医生与一名手术护士共同工作。

职员种族页展示一句具体天赋，例如“章鱼：登记更利落”，并显示当前岗位是否适用；不推荐按种族拼出唯一最优阵容。招聘可指定种族，身体是否能到岗有实景预览。每名医护三条能力可并排读完，获得实操升级时给一句轻巧提示，忙时归入履历，不弹确认、不给玩家再分配一颗经验点。

所有面向玩家的缺岗与操作条件使用“岗位＋本人能力及所需等级”，再按实际情况补充研究或医生职称；不显示q_tXX、q_or等内部标记，不把科室名当作另一张证书。例如“需要治疗2级的医生”“需要手术1级的护士”；已经合格但未到岗时写“护士正在前往这里”，不能仍提示重新培训。能力进度按实际完成事实更新，任务卡只展示当前达标人数和下一步可查看的培养入口。Q13的两项能力必须来自同一名在职医生，不能把两人各一项凑成一人；护士能力、机器升级、科室主题与职称不替代该条件。

医院备份大小随真实楼层、员工与病例状态增长。保存/导入页可显示“正在校验”“正在保存”与已处理字节，资源不足时显示所需和可用空间、可选择其他目录；原医院与上次有效保存保持可用。取消结束未提交作业，不把未保存显示成成功，不因大医院自动丢弃远处楼层或早期活动事实。

### 一次没奏效之后

患者卡沿[临床结果与下一步](07-clinical-team.md#15-治疗结果与下一步)显示“这次没奏效，仍可再试一次”“治疗完成，恢复中”或“两次已完成，安排友好转诊”，并列当前实际原因。首次失败默认自动由原临床流程接续，关闭面板也照常进行；院长可查看方案、指定另一合法方案或主动转诊，没有逐人确认重试的弹窗。原院长指定方案和显著条件变化仍使用既有重评规则，结果提示不能覆盖它。

上一尝试的结果与下一方案的报价分成两行：已经发生的结果不随换人或升级变动，下一行只表示当前预测。手术及需要住院观察的门诊只显示已完成操作与后续照护，不用绿色康复章泄露开工时承诺的结果；查房尚未完成时也不写“只等付款”。普通康复与失败不自动抢镜头，旧结果可从本次小票查看。

方案比较使用原患者侧栏，有当前推荐时默认展示它及至多一个实际合法备选；没有备选时只显示推荐，不补造手术或第三种方案。没有可执行方案时显示真实待齐原因，并可展开病例实际存在的方案及各自缺项；缺资源方案仍不进入自动评分。其余方案沿原展开列表查看。卡片先展示成功率、操作/必要恢复、待齐条件、设施费与治疗包。已经完成的初诊和检查单列实收，成功治愈费标明“成功后”；小数概率保留足以分辨本次差异的精度，98%上限直接显示98%。不把诊断、机器完成、第一次失败和整个就诊结局合成同一个图标。低动态和静音下同样能读懂下一步，结果卡不要求玩家读完才能离位或开工。
