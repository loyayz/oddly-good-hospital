# 第二阶段：基准工具与成本接入

本报告保留阶段2的历史基准方案。原基准、采集与回放工具已撤下，当前功能专项见[测试入口](../../tests/README.md)；后续性能测量按实际阶段28代码另行设计，本报告不构成当前性能通过结论。

第二阶段交付Release基准准备、专用负载、原始采集和报告工具。第二阶段性能检测全部跳过，当时72组显示组合均保持`not_measured`，没有本阶段的性能通过结论；该历史计划不再作为当前测量门禁。后续采集采用[技术规格第9节](04-technical.md)的代表场景、样本量和操作覆盖。第三阶段使用同一工具独立实测正式内核，结果见[第三阶段报告](15-stage03-kernel-performance.md)。实施合同见[第二、第三阶段规格](../specs/26-10/2026-10-14-stage02-stage03-simulation-kernel.md)。

## 1. 已交付入口

| 入口 | 责任与输出 |
| --- | --- |
| `tools/prepare-performance-plan.ps1` | 从`balance.performance_targets`生成72组显示参数、空间样本及资源目标；输出`.cache/validation/stage02/baseline-plan.json`，测量数为0 |
| `tools/prepare-kernel-benchmark.ps1` | 独立复制基准工程，导出固定Godot版本的Release exe/pck及原生库，记录源文件与发行单元哈希；准备过程不启动测量 |
| `tools/benchmarks/kernel_fixture.gd` | 使用真实身体、合法布局、持续路径请求和D23手术病例；160/320/640目标人数及实际在院人数分别记录，保留10000层稀疏结构 |
| `tools/benchmarks/timed_simulation.gd` | 对实际完整`step`及命令边界采样；记录真实tick、路径与病例计数，区分实际行走身体和待寻路请求，夹具准备与人数观察单独计时 |
| `tools/measure-kernel.ps1` | 分组执行Release；保留参数、stdout/stderr、退出码、原始NDJSON和每秒OS工作集/私有提交；拒绝含脚本错误的记录 |
| `tools/benchmarks/display_projection.gd` | 接入现有场景投影、平移/变焦/切层及UI尺寸；正值引擎观察量单列，缺少的实际呈现/GPU字段保持空值 |
| `tools/report-kernel.py` | 从原始记录核对tick连续性、完整步分位和真实命令样本；分组判定目标，校准均值模型并保留缺失成本 |
| `tools/benchmarks/cost-coverage.json` | 四类成本的已实现组件、缺失项与后续接入阶段 |

采集、profiler和显示控制均位于工具目录；医院快照不保存采样时间、性能字段或新的测试随机流。诊断profile、短时排查和正式采集各用独立目录，短时数据不能替代每组60秒预热、600秒采样的正式结果。

## 2. 负载与模型边界

模拟夹具使用第一阶段的实际临床流程及身体通行实现。额外居民在四个96×96合法楼层持续移动，命令沿正式边界提交；真实患者离院后在下一边界补入一名移动居民。逻辑记录数、实际在院数、医护和病例数均独立记录。该夹具提供当前机制的真实工作量，多站点经营及其他未接入系统的成本保留缺失。

`kernel-mobile-and-surgery-v2`在步前只提出居民目标，正式固定步中的全院FIFO队列执行真实搜索，缓存命中也占用额度。分散负载使用32格往返，单层密集诊断使用8格往返；移动记录数包含等待，实际行走人数另按本步地面位置变化统计。旧版1格往返负载不用于直接计算新版的同负载优化比例。导航缓存容量记账与128MiB目标单列，Release原生图的精确分配量保持未测。

| 成本模型 | 当前工具可采集的内容 | 后续接入 |
| --- | --- | --- |
| 模拟/查询 | 完整固定步、命令、路径、身体移动、临床就绪、手术及账目 | 多临床站点：10；环境脏区：19；来客容量与候诊离院：24；互动候选：29 |
| 绘制/姿态 | 第一阶段Compatibility资源和现有投影的引擎观察量 | 正式投影、LOD、透明和姿态上传：7；全部资源：35；实际呈现与完整显示矩阵：38 |
| 内存/资源 | OS工作集、私有提交及进程峰值 | 图形分配、资源重叠：7；完整世界和切换峰值：38 |
| 保存/恢复 | 第一阶段事务快照实现可复用 | 正式64MiB/128MiB世界：5；多院候选与退场重叠：6；完整存储峰值：38 |

均值模型以160/320当前实际负载校准，640独立检验。模型限于相同夹具和已测人数范围，不把模块P95相加，不预测未接入系统或完整游戏。真实Release采集及模型参数在第三阶段形成。

## 3. 检测状态与复现

默认12组、完整72组、密集显示区间、图形资源、冷热/驱逐、切院峰值和64MiB/128MiB存储检测均未执行。显示工具没有实际呈现间隔或GPU取证能力，这些字段保持缺失；无窗口模拟结果不能判断显示帧率。

```powershell
pwsh -NoProfile -File tools/prepare-performance-plan.ps1
pwsh -NoProfile -File tools/prepare-kernel-benchmark.ps1
```

静态计划生成结果为72组、0次测量。正式测量单独使用`tools/measure-kernel.ps1`，本阶段不执行该入口。

后期热点诊断可使用`-Profile -DiagnosticStartTick 8100 -WarmupSeconds 5 -SampleSeconds 20`。工具先逐个执行真实固定步到指定tick，再开始现实预热和采样；预运行不跳过寻路、临床或结算。这种模式始终标为诊断，不能生成正式通过证据。常规正式采集不使用该参数，仍独立执行60秒现实预热与600秒采样。

已交付当前负载的工程准备及明确成本接入表。完整阶段二显示、资源和存储验收保持未执行；第三阶段报告只判定实际测量的正式内核。
