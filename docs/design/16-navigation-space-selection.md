# 完整游戏的导航与空间技术选型

## 1. 选型结论

导航采用二维逻辑空间、确定性的层内显式图、按基准通行成本的跨层搜索及独立的行人协调。Godot 4.7.2的`AStar2D`负责层内通用搜索；它不承担全院交通、设施预约或最终移动许可。该选择来自完整玩法的空间和时间约束，不以既有实现或单次搜索速度为依据。

| 范围 | 技术方案 | 事实与许可的拥有者 |
| --- | --- | --- |
| 真实空间及适配 | 从当前身体、格边墙、门、设施、楼板和预约生成可丢弃查询投影 | 建筑、原内容身体与FacilityReservation |
| 层内路线 | Godot `AStar2D`四邻显式图，加确定性的图适配层 | NavigationService只持图、依赖和结果缓存 |
| 跨层路线 | 稀疏连接拓扑上的稳定基准成本搜索；不推演队列 | 原连接设施、LiftTransportState和TransitSession |
| 实际行走 | 原固定阶段内的完整身体/分段扫掠检查及单方局部绕行 | Movement与原位置、组和预约事实 |
| 邻域查询 | 按楼层R-tree空间索引，完整候选粗筛后执行精确检查 | 索引只持可重建引用及本阶段历史扫掠 |
| 三维画面 | 当前逻辑事实的平滑投影 | 表现层不提交通行、治疗或交通结果 |

层内搜索复用引擎；跨层连接求解和项目通行规则由项目实现。当前不新增第三方寻路包，也不为未测得的热点预先引入新的原生计算模块。未来原生化只替换已量化的计算实现，不另建一套世界、预约或移动规则。

导航、空间许可和表现层各自承担上述职责，搜索结果不替代实际移动与资源使用时的安全检查。

## 2. 完整玩法对选型的约束

| 设计事实 | 技术要求 | 规格来源 |
| --- | --- | --- |
| 单层96×96格，四邻移动；墙位于格边而不占格 | 需要显式判断相邻格之间的边，不能只判断格子是否为空 | [模拟与建造§2、§3](01-simulation.md) |
| 医院楼层和人数不设游戏上限；空结构层可能很多 | 按真实查询和实体分配，跨层身份使用CellRef，不能按最高层号建立满数组或全院巨图 | [多层与规模§9](11-growth-arrivals-recruitment.md) |
| 普通、巨型、微观载具和症状身体共存 | 按实际有效宽深高及原姿态/组投影核验；同为2格不保证门、净高或预约例外相同 | [内容适配§3](02-content.md)、[自动伸缩§2.1](01-simulation.md) |
| 只有门和护理病床扩大主体；其他设施固定，身体和岗位占用仍真实 | 公共几何、当前动态占用与自有预约例外分开；每次真实使用前原子复核 | [自动伸缩§2.1](01-simulation.md)、[手术住院§8](07-clinical-team.md) |
| 候诊、休息、睡眠、清洁、探视和活动均需真实到场 | 所有系统调用同一空间和路线查询；预览不生成移动角色或预约 | [医院日常](08-hospital-life.md)、[员工休闲](09-consultation-wellbeing.md)、[社区活动§10](10-community-comedy.md) |
| 公共设施自动先到区域、手动始终指定设施，使用权在真实到场后取得 | 区域入口行程和到场后局部路线分开；用途意图不产生远程物件占用，实际入用继续完整身体及真实使用空间校验 | [公共设施区域寻址规格](../specs/26-10/2026-10-18-public-facility-area-use.md) |
| 清洁和演出区域提高成本，不能硬封唯一出口 | 保留原非负软代价；搜索结果优选、实际步行距离和行走时间分别表达 | [移动§3](01-simulation.md) |
| 电梯有真实空车位置、已到站队列、模式及登离舱时间 | 寻路使用固定通行时间；队列与轿厢状态由移动实际执行，独立估时可以未知 | [交通§4、§4.1](11-growth-arrivals-recruitment.md) |
| 会车须容纳整个身体，陪同转床不能拆组 | 寻路只给候选路线；实际扫掠、局部绕行和预约许可仍由原Movement执行 | [移动§3](01-simulation.md)、[技术§6](04-technical.md) |
| 固定0.1秒步长，稳定实体顺序、保存恢复和独立回放 | 图冷热、局部修补、视图及运行速度不能改变相同查询的结果和业务顺序 | [模拟时间§1](01-simulation.md)、[技术§6](04-technical.md) |
| 建造和临床查询必须基于当前完整世界 | 同步读取一致查询边界；后台烘焙或异步结果不能直接成为当前安全许可 | [技术§3、§6](04-technical.md) |

三维表现不产生可任意上下移动的三维玩法：楼层之间只能沿真实连接通行，身体高度是准入条件。因此导航的逻辑维度仍为二维楼面加离散交通连接。

## 3. 候选比较

以下是能力与维护成本判断，不是同负载性能排名。

| 候选 | 适用处 | 完整设计下的取舍 |
| --- | --- | --- |
| `AStar2D`显式图 | 点、单向/双向边、自定义成本与邻接过滤 | 选为层内搜索。格边墙、门的逐边准入和局部修补能直接表达；需要管理图构建、查询覆盖与稳定邻接顺序。[官方API](https://docs.godotengine.org/en/4.7/classes/class_astar2d.html) |
| `AStarGrid2D` | 自动连接规则网格，格子阻挡和权重 | 普通格子地图更省代码，但本项目还要表达格边墙、门扫掠及查询者例外。可用细分网格/中间节点编码这些边，却增加表示和映射成本，不能仅因院区是网格便视为更简单的完整方案。跳跃模式还会忽略权重缩放，不能直接替代原软绕行。[官方API](https://docs.godotengine.org/en/4.7/classes/class_astargrid2d.html) |
| `NavigationServer2D/3D`及导航网格 | 连续区域路径和引擎导航服务 | 开放连续场景有价值；本项目必须额外约束四邻、格边墙、多包络门适配与同步改建。更换为导航网格不会消除这些规则，并增加烘焙、同步和多尺寸地图的维护面，因此不作为业务路线权威。[导航性能](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_optimizing_performance.html)、[Agent半径](https://docs.godotengine.org/en/4.7/classes/class_navigationagent2d.html#class-navigationagent2d-property-radius) |
| `NavigationAgent`避让及Physics查询 | 连续局部避让、形状相交与移动碰撞 | 可作辅助或以后单独对比，不能直接承担本项目的单方局部绕行、前后同行队列和原子预约。避让半径与寻路半径分离，避让障碍的更新也不能当作当前通路已经改变。[导航障碍](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationobstacles.html) |
| 流场、HPA*、D* Lite等额外搜索结构 | 大量同目标查询、分层粗化或反复修路的特定负载 | 医院有多身体、多目标和实际交通。它们可能服务于测得的热点，但当前没有证据证明维护额外结构优于单层最多9216位置的现成搜索；不将其列为基础依赖或默认实现 |
| 全部自写BFS/A*及碰撞库 | 完全控制内部行为 | 无权重BFS不能完成正式软绕行；重写层内通用搜索增加维护面。只保留引擎API未覆盖的跨层连接求解及业务空间规则 |

`AStar2D`因此继续适合一个明确子问题：给定当前合法四邻图求层内路径。它不构成“一个类解决全院导航”的方案，也没有获得“原生必然比当前实现快”的结论。

## 4. 确定性的图适配

Godot 4.7.2源码中的A*堆比较使用f、g值，等值时没有项目定义的节点ID最终排序；邻接来自`AHashMap`。该容器删除元素时会用末项填补空位，因此删除再恢复相同边不必恢复原遍历顺序。只在冷建图时按ID添加边不足以保证冷热一致。[A*源码](https://github.com/godotengine/godot/blob/4.7.2-stable/core/math/a_star.h)、[邻接容器源码](https://github.com/godotengine/godot/blob/4.7.2-stable/core/templates/a_hash_map.h)

本机`4.7.2.stable.official.ed1daf0bf`的专项探针使用一张5×5无障碍四邻图，对80种有向边删除/恢复和25种节点删除/恢复分别查询全部625对起终点。相同最终图共65,625组对照中，原生边恢复出现946条路径差异、节点恢复出现854条；将受影响源节点的出边清空并按目标ID排序恢复后，两类差异均为0。

上述记录是固定引擎与小图上的历史实验，仅证明邻接顺序风险及修正效果。原探针脚本已移除，不作为当前完整医院、预约、通行或性能的验证依据；当前需求专项入口见`tests/README.md`。

正式适配层遵循以下规则：

1. 层内节点ID固定为`y*96+x`；坐标先完成原整数范围核验，不能先截成Vector2i。冷建按稳定节点及出边顺序生成。
2. 图变更先完整收集旧、新几何影响的源节点；每个受影响源节点重建全部合法出边，按目标ID排序，以有向边操作独立恢复。删除节点时，其所有入边的源节点也属于受影响集合，不能只整理被删节点。
3. 不改变原成本、不添加微小ID权重、不消费随机数来打破平局。固定引擎版本、邻接表示及查询选项共同形成路径选择协议。
4. 同一查询期间图、成本及覆盖上下文保持固定；查询后解除上下文。同一个AStar实例不并发使用，主线程业务查询不与后台工作共享可变图。
5. 局部修补、完整重建、驱逐再建、不同命令历史收敛到相同世界，以及引擎升级均验证逐节点路径一致。部分路径还核对终点选择，不能只比较总距离。

## 5. 层内图和查询覆盖

游戏激活新医院或恢复医院时，完整加载当前观察层的静态基础几何和索引；玩家实际切层成功时加载对应整层。静态基础包括该层所有已取得地块、阻挡格、房间墙边、原始门形、阻挡设施真实占地和竖向结构占地，以及墙线、门和设施空间索引。没有角色的整层也完整加载，不再按当前角色体型或软时间限额选择部分图。纯视觉模型仍沿既有分帧资源和视锥策略处理，不强制同步加载整层模型文件。

该整层基础不依赖身体，不是所有潜在身体、姿态和楼层的通行图笛卡尔积。实际身体的门宽/净高适配、预约权限和移动占用仍按既有规则独立计算。未显示楼层经同一入口按需加载，跨层路径、费用报价、人员工作和模拟时钟均不受观察层限制。切层保留当前会话、速度和所有世界事实，不追加模拟步或随机调用；已开始的模拟边界完成前仍延后切层。

静态层及其持有的完整源数据共同计入导航缓存预算，允许一并回收；精确内容身份可从当前事实重建，驱逐本身不改变有效路线。静态层按完整源身份复用；预约权限单独变化不重建，墙门、家具实际占地或楼板等事实变化使相关层在下一次访问前重建，派生通行图仍按原脏区域修补。支撑设备离开和竖向结构出口的显式临时排除源使用隔离投影，不可覆盖或改写公共索引。静态层的保守持有量限制为原缓存目标的四分之一，剩余持有量仍与图、查询共享同一总目标；超出可持有量时本次仍完成整层计算并使用结果，后续可按需重建，不返回半层数据。此持有量是驱逐计量，不宣称等于进程实测内存。

公共图按`(floor_id, TraversalEnvelope签名)`懒加载，签名只合并已证明通行判断完全等价的身体/姿态或整组几何，不能只用1/2/3格归类。实际宽深高、症状、门净高及原组偏移必须参与相应判断，角色和预约身份留在查询上下文，不为每位居民复制一张公共图。

节点核验实际身体足迹；相邻边核验原四邻扫掠、格边墙、门可展开墙段、两侧空间及净高。合法节点不代表它们之间必然有合法边。建筑系统提供当前几何，设施系统提供展开及预约，不由搜索回调扫描全院重新生成这些事实。

共同几何和原软代价预计算为可索引的点边数据；`_compute_cost`只读取已验证成本。启发式使用已证明不高估的下界，缺少证明时取0。保持原成本定义，不把演出软代价换成真实走路时长或改变速度。实际步行距离从最终路线取得，再按原身体速度计算交通报价中的步行时间。

普通点到点寻路忽略可移动人物与短时操作预约；当前真实病床主体等结构几何仍进入公共图。临时身体、预约权限、门和电梯的实际使用许可归Movement，在实际遇到处检查；局部绕行可以使用当前完整占用查询，不能据远端短时占用否定出发。

EQ05护理床的完整预约区域用于使用权、建造及服务占用判断；通行投影只包含实际床主体，空患者/医护/维修岗位不进入硬障碍。默认占用查询仍严格，实际路过明确使用通行语义，不能给陌生任务床边使用权限。真正的身体和阶段扫掠保持原碰撞。移动最终停点及局部临时停点通过同一局部预约索引检查；单人使用已发行路径的最终来向，同行组只读取自身物理尾长范围内的路径后缀，跨连接复用正式离舱计划，不拼接不同楼层坐标。不能用末步才拒绝的方式让行人半身进入岗位后长期停住。

普通护理床预约且实体占地未变时，不再执行逐人出口证明。真正改变床主体的伸长仍使用既有安全证明，这是尚待改造的显式分支，不是普通预约的整层兜底，也不代表真实伸长已经完成局部化。

局部脏桶、nav_revision、occupancy_revision、查询结果键与旧结果回收沿[技术§6](04-technical.md)。图、点边数据、依赖、合并脏记录及结果共用128MiB目标，不为各类另分预算；原生图内部存储和临时查询成本一并测量，不能只按GDScript数组大小记账。缓存驱逐不改变路径、请求额度或预约；缺少完整依赖时从当前世界重建本次所需投影。完整、部分、几何不可达、动态争用及估时未知分别保留结果；临床准备和入口完整路线核验不能把部分路径当作已到达。

## 6. 跨层基准路线与独立估时

任务确定具体终点，HospitalNavigation按完整身体、楼板、墙门、固定主体和连接停层搜索点到点路线。层内使用确定性四邻图；跨层在实际连接、所需站点及换乘点上稳定搜索，不按最高层数建立满数组，不截取最近N部电梯。

路线成本包含真实步行距离按原速度取整的时间，以及连接固定的登舱、载客和离舱时间。结果的travel_ticks是基准通行成本，不是预计到达时刻，不含未知排队。当前故障仅允许原规则规定的安全下降方向；身体、净高和完整组容量仍须满足。

路线查询不调用整队交通报价，不创建票、叫梯或预先验证未来出口会在某时刻腾空。HospitalMovement在实际到达连接口后取得当前段票，处理真实队序、空车接人、登乘离舱、拥堵与途中故障。已启动安全段完成前不能因目标改变而传送或撤销载客。

单段交通预计仍由HospitalTransit.quote独立只读计算，沿[交通§4.1](11-growth-arrivals-recruitment.md)的同刻max(A,P)+E+G公式。不能有限估计时返回estimate_unknown及原因；此状态不等于无路，不参与普通路线可达性判定。时间与层号累加溢出明确失败，不截断或环绕。完整业务合同见[任务、寻路与移动规格](../specs/26-10/2026-10-19-task-navigation-movement.md)。

## 7. 行人、碰撞与空间索引

Movement在固定阶段⑤按稳定更新顺序执行真实移动，但更新顺序不授予角色长期通行优先权。相遇只让一方局部绕开，左右优先，必要时沿真实已走轨迹或身后邻格逐步后退；真正后退被人挡住时由实际可移动阻挡者绕开，再按原路线（含压缩段中间格）由近到远安全回接；保留原目的地。另一方现场通行安全即可继续，不等待绕行完成。前后同行队列只验证队长的新前端，成员沿真实尾迹跟随。通路不存在与暂时人物占用分别返回。每步Actor请求额度为max(8,ceil(A/20))，缓存命中也占额度；只读Readiness、预览和活动预算不进入这份业务队列。

身体索引由Boost.Geometry R-tree按实际楼层及完整小数位置包络登记，覆盖静止者、等候者、访客、职员和完整移动组。粗筛取得全部局部候选并按身份去重排序，随后核验真实身体、分段扫掠、同行时序和预约。实际移动结果同时返回位移与精确阻挡身份；局部绕行复用这些命中并归并同行主角，不再次从粗矩形候选猜测阻挡者。受短时争用触发的备用路线按每条候选四邻边核验移动单位完整身体的起终扫掠，不能只筛查到达格；正式移动仍按同一身体与当前阻挡重新许可。静止且没有安全或业务职责的职员阻塞唯一通路时，可在原受阻阈值后按正常Movement请求移至最近的完整身体可达空位；目标不得占窄道、行人剩余路线或设施预约。患者、访客及有工作、照护、培训、生活或操作预约责任的职员不会因此被推动。必须保留本次阶段内已接受提交的扫掠依据，不能用粗矩形相交直接拒绝原本能并行的宽路。

身体、阶段内已提交扫掠、设施、门和预约复用同一原生空间索引适配。历史4格／8格桶的测量只说明对应旧构建；当前R-tree没有每桶人数或候选截断上限。候选全集和严格接触边界由专项断言验证，算法替换本身不构成性能通过证据。

精确几何继续复用Godot的向量、矩形及适用的几何运算，不重写整套物理库。引擎Physics查询若作为额外候选来源，须单独证明状态同步、完整候选、稳定排序和当前预约语义；有限`max_results`不能截掉应参与的身体。Godot的物理系统没有确定性保证，但这不等于每个矩形查询都不确定，也不能只凭该警告否定全部原生查询。当前选择项目逻辑索引作为业务查询来源，表现碰撞体和避让速度不成为最终通行许可。[物理说明](https://docs.godotengine.org/en/4.7/tutorials/physics/physics_introduction.html)、[形状查询](https://docs.godotengine.org/en/4.7/classes/class_physicsdirectspacestate2d.html)

## 8. 正确性与成本约束

层内查询覆盖普通、微观与巨型身体、症状、净高、墙门、软代价、组扫掠及自有预约权限。带权、无路与部分路径在冷建、局部修补、驱逐和恢复后保持相同结果；失败回调与查询结束不污染后续查询。跨层结构路线、固定通行成本与实际排队分别判断。

邻域索引必须在窄路、宽路并行、静止身体、相交组、同XY异层、登离舱、治愈缩回、预约延迟释放及恢复中提供完整候选与稳定结果。

图冷建、局部修补、层内搜索、查询回调、跨层报价、邻域粗筛、精确碰撞、索引更新和内存分别计量；完整模拟步、完整呈现帧及实际模拟速度独立满足目标。真实路径请求与其他玩法查询计入其实际执行的生产边界。

导航图、几何投影及依赖容器共同计入128MiB缓存目标。缓存驱逐计量与实际进程工作集、私有提交量分别记录，不互相冒充。当前版本保存活动路线与真实任务按恢复合同保留，不引入假设的旧版本产品迁移。
