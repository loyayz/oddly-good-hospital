# 实施路线与阶段交付

## 1. 目标、基线与执行尺度

目标：将现有完整产品设计实现为可独立安装、单人离线运行的Windows医院建造经营游戏，保留同院持续成长、独立保存多院、完整临床与生活系统，以及由性格、关系和实际情境共同产生的喜剧。

架构：WorldState保存唯一模拟事实，固定步系统执行业务，命令边界完成原子修改；场景与Control界面只投影事实。内容以稳定ID、类型注册表和版本化处理器扩展，医院资料采用追加式完整提交与恢复协议。

技术栈：Godot 4.7.2标准版、带类型GDScript、Compatibility/OpenGL 3.3、Blender 4.5.14 LTS/GLB、UTF-8 JSON与CSV、每医院独立SQLite事务快照、Windows x86_64资料库占用桥接、NSIS 3.13。工程选型及公共签名沿用[技术规格](04-technical.md)，产品行为沿用[模拟规格](01-simulation.md)、[内容规格](02-content.md)及各系统章节。

本计划基于设计1.97.0、内容与数值schema100、起始布局schema9、临床布局schema5、产品快照schema1。规划起点为设计、数据、校验工具和离线阅读页。第一阶段已建立代表工程、源资产、Windows技术包及实机验证；第二阶段交付基准准备与成本接入清单，性能检测跳过；第三阶段交付正式内核及独立Release实测。范围与验证状态分别见[第一阶段报告](13-stage01-feasibility.md)、[第二阶段基准交付](14-stage02-benchmark.md)和[第三阶段实测](15-stage03-kernel-performance.md)。各阶段的文件和验证入口按对应成果逐项接入。

### 全局约束

- 最终交付完整设计；第一阶段的代表内容用于证明技术路径，后续阶段补齐系统与全部内容。
- 0.1模拟秒固定步、1800模拟秒一日、医院时钟hospital-time-v1、十阶段推进顺序和整数资金/概率保持原合同。
- 快进增加执行步数，暂停停止模拟；观察层、LOD、姿态采样、缓存和图形设置不改变业务结果。
- 160/320/640人、10000空结构楼层以及2GiB/512MiB资源目标用于验收与调校，医院规模继续按原经营和真实资源规则增长。
- 功能有真实占地、工作、付费、预约、人员和安全退出；成功、失败、暂停、取消与恢复都属于交付范围。
- 界面随对应系统交付可操作版本，日常默认自动运行，详细规则在详情中解释；每阶段保留保存与继续经营能力。
- 每个独立交付项先完成需求理解、决策收敛、方案设计、方案复核，再实施和验证；已确定规则直接执行，有实际冲突时修订对应规格。
- 文档和数据变更继续用PowerShell 7执行`docs/tools/export-design.ps1`；静态设计校验、游戏规则测试、Release性能、资产、安装和试玩分别记录。

### 2.2 共同接入规则

每个新系统同时完成自己的事实、命令/查询、正常流程、暂停/取消/失败/恢复、只读界面和代表表现；进行中状态在同阶段进入原快照，不建立临时第二套存档。未来模块尚未产生的事实列为待接入，不能据此提前将全部效果或验收标为通过。

数值随业务接入核对：临床核对概率/工时/费用/包耗，生活核对恢复/覆盖，运营核对维护/采购/工资，成长核对建设/研究/奖励，喜剧核对冷却/作用/恢复。每阶段补充真实计数和成本；阶段37关闭完整数值，阶段38关闭完整性能，阶段39关闭独立玩家体验。

完整医院的临床、经济、成长和自动恢复有实际数值结论。 账目/库存/占位/奖励守恒，无读档套利或永久无进展；开局缓冲、成熟持续经营、方案/升级/培养价值有实际数据支持。

**数值/性能接入：** 完整经营行为替换预测中的来客/覆盖/故障/恢复频度，下一阶段用同版本测完整帧与速度。

**前置条件：** 阶段35至37的完整正式资源、界面与数值版本冻结到同一候选构建。

**阶段目标：** 基于当前电脑和完整游戏的性能验收报告。

- [ ] **38.2 重跑全部显示与规模组合。** 阶段2的72显示组、320/640、活动160替换、宽高联合、密集区间、1000实际稀疏层/10000空结构、冷热/驱逐及大世界保存分别取证。

### 成果与通过条件

基于当前电脑和完整游戏的性能验收报告。 正式版本满足原帧/步/速度/响应/存储和资源合同，无P0/P1持续性能问题；普通经营卡顿及切层资源长帧全部计入。

**数值/性能接入：** 交付原始帧/业务/资源/条件记录、预测与正式实测差异、优化等价性；算法改变回到所属阶段补规则证据。

## 42. 第39阶段：独立玩家试玩与体验修正

**前置条件：** 阶段36至38完整可操作候选和测量已有，准备各成熟系统对应医院。

**阶段目标：** 经两轮独立玩家验证的轻松、有趣、可理解的发行候选。

### 工作步骤

- [ ] **39.1 完成首轮新玩家试玩。** 五名未接触实现者各30分钟，记录行为/原话；15分钟治疗/调整/保存、静音病例识别及无口头帮助作为原目标。
- [ ] **39.2 完成成熟系统专项。** 忙碌改建、活动人数/变体、放手观察、首次失败接续、手术/查房/结算区别在相应医院补测，记录真实误解与操作负担。
- [ ] **39.3 修正体验并完成次轮。** 改动作/信息层级/提示/自动恢复或对应数值后，五名玩家各60分钟按原4/5通过线验证记忆点、目标和轻松程度。
- [ ] **39.4 关闭回归和发行候选缺陷。** 体验改动若涉及数值回阶段37，涉及资源/逻辑/输入成本回阶段38的受影响组；P0/P1清零，P2有具体影响与复现。

### 成果与通过条件

经两轮独立玩家验证的轻松、有趣、可理解的发行候选。 原试玩目标均有行为证据，失败和下一步能理解、布局有实际意义、喜剧有具体记忆点，修正后规则与性能仍通过。

**数值/性能接入：** 统计手动救场/警报/互动重复/操作时间与实际问题；体验修改后的新增成本重新接入，不使用主观满意代替性能。

## 43. 第40阶段：Windows安装、升级与中断恢复

**前置条件：** 阶段39发行候选完整，阶段1安装/原生桥接样机与阶段5/6资料库协议可复用。

**阶段目标：** 离线可安装、升级、卸载和修复的Windows发行包。

### 工作步骤

- [ ] **40.1 完成发行单元与NSIS。** exe/独立pck/GDExtension声明/x86_64库及内容清单同版本，按用户安装到既定目录，快捷方式/卸载和体积目标可检查。
- [ ] **40.2 完成暂存与替换协议。** 新版完整核验才替换，旧版保留到程序/入口/卸载信息均成功，正常失败恢复完整旧版，首次安装失败有修复入口。
- [ ] **40.3 完成故障矩阵。** 解包/资源复制/原生库/入口阶段注入普通失败和强制中断，重跑同一离线包恢复完整旧版或新版，修复副本与玩家资料保留。

### 成果与通过条件

离线可安装、升级、卸载和修复的Windows发行包。 没有半套程序被报安装成功或启动；中断可恢复，医院/设置/蓝图/照片不被替换回滚，卸载后重装可继续医院。

**数值/性能接入：** 记录安装体积、暂存磁盘/时长、启动和修复成本；原生库和导出单元变化复核阶段38有关启动/运行条件。

## 46. 工作量、阶段边界与收尾

### 46.1 工作量估计

42阶段按独立成果计量，每阶段工作包再按规则/状态复杂度、资产适配和真实验收成本估计。阶段01/02记录实际工程速度、样板制作/返修时间及测量成本后形成排期；团队产能未确定时不写固定交付日期。

工程关键路径为内核/内容/保存→空间/临床→日常/能力→成长/交通/社交→全资源/界面→数值/性能/试玩→安装/兼容/发行。正式资产、中文和声音沿已验证管线持续制作；生产只依赖相应已通过合同，不等待所有业务完成。

72组基础显示组合的净预热/采样仍为13.2小时。诊断、设备/状态准备、冷热资源、大世界保存、长程经营/稳定、独立试玩、安装中断与失败复测分别计量；这些时间不与开发或资产制作工时混为一项。

### 46.2 每阶段的标准交付包

| 项目 | 内容 |
| --- | --- |
| 可运行成果 | 固定版本构建、该阶段操作/运行入口及实际可用范围 |
| 对应规格 | 当前有效规则、输入/输出、事实所有权和受保护旧行为 |
| 数据与资源 | 内容版本/指纹、代表或正式资产清单及尚未关闭项 |
| 可复现夹具 | 合法小世界/实际负载、固定seed、命令/镜头或故障步骤 |
| 验收证据 | 对应AC/V、规则与恢复、人工表现/输入、实际缺失项 |
| 数值和性能 | 工作次数/账目、受影响基准、原始记录与阶段2模型更新 |
| 收尾状态 | 通过/失败/尚未实施/缺少证据，下一阶段前置与阻断项 |

阶段05建立的保存服务持续接收新系统状态：本阶段能进行的任务、预留、工作余量、选择与一次性凭据必须在本阶段恢复；无效目标和资源不足沿同一原错误协议保留世界。阶段06的切院、取消退出和迟到回执复核相关新事实。

新增模拟/空间/查询组件复测原主要1×/3×和相关密集负载，新增资产/界面复测对应视图/缩放/资源条件；全矩阵由阶段38完整重跑。诊断短跑仅用于定位，不标成600秒正式采样通过。文档修改只运行设计校验；规则、性能、资产、安装和试玩的证据分别记录，已有无关通过项不重复制造工作。

阶段未通过时先修本阶段问题，复测受影响条件；规则或技术合同需要改变时先更新对应规格。上游回归失败暂停依赖该成果的后续交付，已验证的无关成果保留。

每个独立工作包完成feature-spec四步后实施，收尾检查实际责任/事实归属、重复状态、多余转发及达到的结果。P0为存档/恢复/重复结算/安装不可用，P1包括流程死锁、扩展破坏、必要内容缺失和持续性能超标，P2记录实际局部影响。依赖阻断和实际未测项不能以“阶段完成”隐藏。

## 47. 技术依据与来源

主要产品依据为本目录所有系统章节，以及[内容数据](../data/content-catalog.json)、[数值数据](../data/balance.json)、[起始布局](../data/starter-layout.json)、[临床布局](../data/clinical-layouts.json)和[生产规格](05-production.md)。这些文件继续拥有产品规则与数值，本计划拥有实施顺序、阶段交付和证据接入责任。
