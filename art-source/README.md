# 第一阶段源资产

五类居民和四类医疗主体由 `build_stage01.py` 以 Blender 4.5.14 LTS 生成。源单位为米、Z 向上，成品通过 GLB 转换为引擎 Y 向上，局部格深沿引擎 +Z。角色以脚底中心为根；设备以登记基座左上角地面为根。原始网格、真实骨架、顶点色和动作均保存在对应 `.blend` 中。

从仓库根目录导出并检查成品：

```powershell
pwsh -NoProfile -File tools/export-stage01-assets.ps1 -PrepareBlender -RenderSourcePreviews
```

准备脚本只将固定版本 Blender 放入 `.cache/tools`，归档以官方 SHA256 校验；也可通过 `-BlenderPath` 使用现有同版本程序。玩家运行 GLB 成品不需要 Blender。`.gdignore` 排除源文件的引擎导入。

`assets/models/stage01-production.json` 记录实际 GLB 身份、Surface、网格流、骨顺序、逆绑定、插槽、根变换、动作和测量包络。内容目录继续拥有身体尺寸、设施占地和临床业务；metadata 记录导出事实，不提供第二套业务定义。所有居民是一份视觉网格和骨架，培养皿内的小点是网格部件。S49 可复用同一网格、材质和骨架资源，以不同骨矩阵表示独立姿态；S14 的透明主体与不透明脸部保留原管线。

语义插槽是导入骨架中的同名骨骼。设备的 `patient_support` 表示实际软垫顶面，M37/M17 的软椅部件位于真实相邻患者预约区，不能把模型整体 AABB 当作机器基座。台床卧姿与站立姿态由当前真实预约决定，包装节点对同一骨架定向和定位；动画根没有位移或旋转变化。设备动作的阶段名称只供表现映射，阶段和进度仍由实际临床事实提供。

两张联系图从成品 GLB 重新导入后以 Cycles CPU 渲染，保留真实尺寸。居民图从左到右为 S49、S21、S59、S55、S14，设备图为 M37、M17、EQ01、EQ05。它们用于源资产美术检查；Compatibility 实机、独立姿态 GPU 等价性、主阴影、透明覆盖和游戏性能由第一阶段运行验收记录。当前只提供常用网格，其他六类骨架、近远 LOD 与完整病例资源继续按生产规格交付。
